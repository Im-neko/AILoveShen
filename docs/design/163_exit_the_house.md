# 163. 家から出られないとき: 壁を壊す手が先に外へ出ようとして失敗する循環

2026-10-11 01:30〜、user: 「家の中になんか石置いちゃって詰んでます」「コメントでどれだけ言ってもどうにもならない」「LLM が道具モードで起動しているのに、なぜ効かなかった？」

## 1. 何が起きていたか
玄関 (158, 79, -455) の床に草ブロックが残り、1 つ上 (158, 81, -455) にまぐさの板材があって、通れる高さが 1 マス (y=80) しかなかった。`inspect` は閉じた所（15 マス）と言い、家の登録（玄関・家の中が y=79）は実際に立つ高さ (y=80) の 1 つ下だった。

家のまわりは 10-10 14:42 の `level`（where=160,80,-461、半径 8、「埋めた 124」）で、家の床の高さ (79) より 1 高い 80 にそろえられていた。家の床より高い所へそろえると、玄関の外の地面が盛り上がって玄関が埋まる。

## 2. 道具モードでも効かなかった理由
LLM は正しい手を何度も選んでいた（壁を掘る、石を積む、出口を作る）。効かなかったのは、手を実行する側の 3 つの仕組み。
1. **壊す手が、先に家から出ることを求める**: `dig` と `level` の対象は壁などで、家の中のマスではないので `needsOutside` が真になり、実行前に `leaveHouse` が走る。`doorRouteOk` は玄関の下に地面があるかしか見ないので「玄関から出られる」と答え、`walkInto(玄関)` が草ブロックに 3 秒阻まれて `could not walk to` で失敗する。出るために壁を壊したいのに、壊す前に出ろと求められる循環。
2. **脱出の手が家の中では出ない**: `inspect` と `goto` の断りは「`climb out of the closed space` を使え」と案内するが、候補は家の中を閉じていないものとして除いていた（`candidates.mjs`）。毎回 `is not a current suggestion` で断られた。脱出は道具ではなく候補（`do_suggestion`）なので、候補に出なければ LLM に打つ手がない。
3. **失敗の理由が玄関の状態を言わない**: `could not walk to (158,79,-455)` からは、何がふさいでいるのか分からない。相談用の `ask_advisor` は 1 ステップに 1 回の調べものの枠で断られた。

コメントの返事は説明と同意で、行動は変わらなかった。決める側が正しくても、実行側が必ず失敗する状況だった。

## 3. 直したこと
- `exit-route.mjs`（新規）: `doorBlocker`（玄関と外のセルの、足と頭が通れるか。ドアは通れる）と `leaveRoute`（door / wall / walk / stuck）。玄関を通れないとき、壁の出口があれば wall、歩いて出られれば walk（行動の経路探しに任せる）、閉じていれば stuck と、ふさいでいるもの
- `planLeave` はこれに置き換え。`leaveHouse` は stuck なら、ふさいでいるもの（例: `the door cell 158,79,-455 holds grass_block`）と、中から手が届くので `dig` を `demolish: true` で直接呼べることを、理由に書く
- `needsOutside(c, home, bot)`: 中にいて、手が届く (4.5) ブロックを掘る・置く手は、外へ出ない（runner が渡す）
- 候補: 家の中で `leaveRoute` が stuck なら、閉じた所から出る手（積む・壁を掘る。家の壁を壊す手を含む）を出す
- `level` の道具: 家のまわり（家から 3 マス）を含む整地を、家の床と違う高さにそろえるのは断る（`where: home` か同じ高さを案内）

## 4. 直していないこと
- 今回の家の現在の形（草ブロックとまぐさ）そのもの。道具が通るようになったので、LLM が `dig(158,81,-455, demolish: true)` で出られる。急ぐなら `setblock 158 81 -455 air`
- `ask_advisor` が 1 ステップに 1 回の枠で断られること
