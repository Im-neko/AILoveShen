# 122. 失敗と断りに、邪魔なものの名前と次の手を添える

2026-10-08、user: 「こういうのもLLMがぱっと壊せば良いって判断出来るのが理想なんですが難しいですか？」「点検してひつようであれば修正していってください」

## 1. 考え方
草花が乗った苗木のマスで、LLM は約 2 時間「no free ground for a sapling … any more」を受け続けた。この文は何が邪魔かを言わず、同じ型の `till` は名指ししていた。LLM に「壊せばいい」と判断させるには、(1) 失敗が邪魔なものを名指しし、(2) 断りに出口があり、(3) 手の側で片付けられるものは片付ける、が要る。モデルの賢さに頼る前に、この 3 つを点検した。

## 2. 点検のやり方
直近 6 日分のステップログ（`logs/steps`）から、失敗・断り 379 件を理由の文ごとに数え、多い順に「原因を言っているか」「次の手を言っているか」を見た（98 種類）。すでに直した物（座標のマイナス落とし、チェストの記録）と、文が十分な物は除いた。

## 3.1 追記: 設計のマスが地面になっていた（同日、再起動後の実機）
白樺の植林場の最後の1マス (50,67,-194) が約3時間半植えられなかった。草花ではなく、そのマス自体が草ブロックの地面になっていた（66は土、67は草ブロック、68は空気）。3つの規則がそれぞれ正しいのに、組み合わせると出口がなかった:
- `plant`: マスが固いので「no free ground」。
- `dig`: 家の整地の保護（中心 44,-200、半径 8 の外側の余白）が床の高さ 67 以下を守るので「being leveled」。
- `level`（LLM が 50,67,-194 で頼んだ）: 床より上の出っ張りは対象外なので「already level」。
地面がいつ誰に上げられたかは分からない（設計時は空きのマスだったはず）。直し: 植林場のマスが固い苗木用の地面（`SAPLING_GROUND`）になっていて、その上が空気か除ける草花なら、マスを1つ上に直して保存する（`facilities.mjs` `ensureTreeCells`。`layoutStatus` の頭で呼ぶので、状態を読むどの経路でも合い、植える手と道具 `plant` のマスの照合（`layoutAt`）も同じ座標になる）。上が空いていない地面、植わった苗木、木、読み込まれていないマスは動かさない。実際の `state.json` の植林場で、このマスが 68 に直ることを確かめた。テスト: `test/tree-cell-anchor.test.mjs`（3 件、変異 5 つが落ちる）。

### 3.2 追記: 直しの抜け（同日）
上の直しは「上が空気か草花」のときだけマスをずらした。再起動後も同じマスで詰まったのは、そのマスにすでに木が育っていたため（66・67 が土、68・69 が白樺の原木。06:41Z に誰かが 50,68,-194 に植えた苗木が育った）。設計のマスは y=67 のままで、判定は土を見て「未植え」とし、木は 1 つ上にあるので見つからなかった。テストも草花の場合しか見ておらず、「上が丸太なら動かさない」と書いたのが誤りだった。直し: 上が苗木・原木でも 1 つ上に直す（そのマスに植わった木なので、既存の判定で済みと数えられる）。実際の `state.json` に、この列の実際のブロックを当てて、8/8 が済みになることを確かめた。

## 4. 直さなかったもの
- 「整地中なので掘れない」（`will not dig … being leveled`）: 断りには土や石を街の外から取る指示はあるが、そのマス自体の出口はない。出口の中身（整地に任せる、整地の対象から外す）は設計が要る。
- `withdraw: no chest is known to hold X`: 開けたことのないチェストは中身が分からない。記録の合わせ（設計書 121）で数が増えるので、様子を見る。
- `pickup: reached the item but picked nothing up`: 原因は持ち物の空きか、既に拾われたか、拾えない物か、文から区別できない。
- 点検の対象はログに出た 98 種類。`primitives.mjs` の `throw new Error` 135、`tools.mjs` の `refuse` 103 すべてを読んだわけではない。今回のログに出ない文は未点検。
