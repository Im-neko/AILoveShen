# 64. 採掘場: 掘る場所と階段を毎回同じ所にする

2026-09-30。状態: 実装済み、実機では未確認（ブリッジの再起動が要る）。

## 1. 何が起きていたか

user（2026-09-30）: 「採掘に行くとき毎回ちがうところから掘ってるから家の周りがあなぼこだらけ」。

- 階段掘り（`dig_down`）は、鉱石へ下りるたびに立っている所から新しい階段を掘り、前に掘った階段は
  覚えていなかった。
- 地表の石・土・砂利の自動採集（`digTargets`）、ツールの `find_blocks`、`observation.around` は、
  どれもボットにいちばん近いものを先に出す。手持ちに丸石 117、花崗岩 14、閃緑岩 11 があり、家のまわりを

- 設計書 47 §16 の採掘場（`facility(mine_1)`）は同じ場所から掘り続ける仕組みだが、設計が LLM 任せで、
  ソルバーの理由文に「作るとよい」と出るだけで、実際には作られていなかった。

## 2. 決めたこと（`minecraft-bridge/src/quarry.mjs`、`state.quarry = { spot, shafts }`、`state.json` に保存）

**採掘の場所（`spot`）**: 最後に意図して掘った自然の地形（`TERRAIN`: 石、土、砂利、砂、鉱石など。木と作物は
入れない）の位置。掘る手（`primitives.mjs` の `dig`）が `noteDig` で更新する。歩きながら経路が掘ったものは
数えない。

- 場所から `QUARRY_RADIUS`（12）の内は、近い順ではなく場所に近い順に掘る（掘った跡が広がって続く）
- 場所が今いる所から `QUARRY_REACH`（48）より遠ければ使わない（遠出した先でわざわざ戻らない）。場所から
  離れた所を掘れば、そこが新しい場所になる
- 使う所: `digTargets`（`world.mjs`。候補とソルバー）、`find_blocks`（`quarry: true` の印。場所の中を先に）、
  `observation.around`（`nearest` を場所の中のものから選び、`quarry: true`）。ツールモード（既定）は LLM が
  `around` の座標を `dig` に渡すので、候補だけでなくここも変えた

**階段（`shafts`）**: `dig_down` が下りた階段の入口（`top`）と底（`bottom`）。次に鉱石へ下りるとき、鉱石が
底以下にあれば（階段は下へしか掘らない）、その底まで歩いて続きから掘る。底まで歩けなければ、いつもどおり
その場から掘る（歩けなかったのは鉱石のせいではないので、鉱石を届かない印にしない）。入口が近い（3 以内）
なら同じ階段の続きとして底だけ深くする。4 本まで。`buriedTargets` は、階段の底から続けて届く鉱石を先に選ぶ。

**整地（`leveled`）**: 階段の入口の列は埋めない（穴として埋めると続きから下りられない）。

**見せ方**: `observation.quarry`（場所、距離、方角、階段）→ 状態の「採掘の場所」の行と、ツールの規則の 1 文、
`abilities.yaml` の `mine_ores`。

## 3. 採らなかったこと

- 採掘の場所を家のそばに決めて設計する: 石が家のそばにあるとは限らない。掘った所を場所にするだけにした
- 穴を埋める後始末: すでにできた穴は `leveled(home, r)` の仕事のまま。場所の内は埋めない設計にはしていない

## 4. 実機で見ること

- 丸石を掘るたびに、同じ場所の近くが掘り広げられる（`observation.quarry` の座標が動かない）
- `dig stairs down toward …` が 2 回目以降、`walked down the stairs dug before, then …` になる
- 場所が石の地面でなく土の上のとき、石は場所から離れた所を掘り、場所がそこへ移る（穴が 2 か所になる）
