# 154. 壊して整地する（leveled の demolish）

2026-10-10、user: 「既存の物を壊して整地することも手として用意しておきたいです」「保護してるのも必要があれば壊すことを選択肢に入れてほしいです」
（設計書 153 の続き: 「壊して作り直したらいいんじゃない」を行動にできなかった。工房の置き先が板・原木で塞がれ、`site blocked by` の置き直しが続けて失敗した）

## 1. 事実（調査）
- 建物の置き先が板・原木・丸石・チェストなどで塞がれたとき、壊して置き直す手はなかった（`build.mjs` `removable` は植物・仮設の作業台・水と、名前付き建物の自然地形だけ）
- 整地（`leveled`、設計書 41）は自然の地形の出っ張りと穴だけ。家・建物・木・畑・置いた物の列は触らない
- 一つずつ壊す `dig {demolish: true}` は保護（家・建物・建築中）も越えるが、座標を 1 つずつ指定する

## 2. 決めたこと（user の答え）
- 形: 既存の `level` を広げる。新しい述語は作らない（目標の語彙・solver・判定・候補は整地と同じ流れ）
- 範囲: 保護以外すべて → 保護された家・建物も含める（追加の指示）。ただし**明示したときだけ**。既定は今までどおり

## 3. 仕様
`leveled(where, distance, demolish)` / `level {where, radius, demolish: true}`:
- 壊して整地する: 置いた物（板・原木・チェスト・ベッドなど）、保護された家・建物（`inHouse`、植えた木のまわり）、木、畑（耕地）
- 残す列: 水・溶岩、採掘場（`mine`）と採掘階段の入口（`quarry stairs`）、壊せないブロック（`hardness < 0`）、DY（8）より深い穴
- 判定は同じ（全列の一番上の固いブロックが y-1）。壊したあとの穴は、今までどおり持っている土で埋める
- 普通の整地は、壊して残した列の数を `lines` に出し、`demolish` にすれば壊せると教える（選べる手として見せる）。道具の `level` が「もうそろっている」と断るときも同じ
- 候補の id は「…, taking down what stands there」。保護された部分を壊したら、結果に「記録は残るので、計画が建て直す（built(...)）」と添える（家や建物の記録は変えない）
- `site blocked by …` のエラーに、`dig {demolish: true}` か `level {demolish: true}` で壊してから置き直す、と添えた（`build.mjs` `siteBlocked`）

## 4. 直していないこと・危ないこと
- 壊した家や建物の記録（`state.home`、`state.builds`）は書き換えない。家を壊すと、家の修理（設計書 88）や `built(...)` が建て直すまで、家のない家の記録が残る。壊すと決めるのは配信者（LLM）
- チェストの中身は落ちる（拾う `collectNearbyDrops` は 8 個掘るごと）。中身を出してから壊すのは LLM の判断（`withdraw`）
- 設置先の板を壊しただけでは足りない場合（足場が塞ぐ）は、整地ではなく `dig {demolish}` を 1 つずつ使う
- 実機は未確認（配信で `demolish` が選ばれたときの動き）
