# つながった意思決定（言うこととやることを一致させる）

作成: 2026-09-25。`10_agent_lifecycle.md`・`11_primitive_actions.md` の上に、実況・コメントへの返答・目標の決定をつなぐ。M2（Twitch）の前に入れる。

## 1. 目的

ユーザーの方針（2026-09-25）: 「コメントの指摘を反映させることも必要だが、それよりも全ての意思決定がつながっていることが大切。コメントに応答した事と全く違う事をしていたら視聴者はびっくりする」。

今は判断する場所が3つあり、互いの結論を知らない。

| 判断 | 見ているもの | 見ていないもの |
|---|---|---|
| 目標の決定（Gemini、`AdvancePlayUseCase`） | ゲームの状態、過去の目標 | 実況で何を言ったか、コメントに何と答えたか |
| 実況・返答（Gemini、`GenerateCommentary/ResponseUseCase`） | 会話の履歴 | 今の目標とその理由、行動の結果（Phase 3 で「新しいお家を建てている」と作り話をした） |
| 行動の選択（Jev） | 目標の進み具合、体の欲求 | 言ったこと |

コメントに「ベッド作るね」と返しても、目標の側はそれを知らずに剣を作りに行く。

## 2. 原則

1. **目標の持ち主は `PlaySession` だけ**。今の目標、その理由、これまでの目標と終わった理由、視聴者からの頼みを持つ。別の「心」オブジェクトに目標の写しを作らない（写しは食い違う）
2. **「今何をしていて、なぜか」は1つの関数で書き出す**。`PlaySession` と最後の観測から `Activity`（値オブジェクト）を作り、目標の決定・実況・返答の3つのプロンプトが同じ書式で見る。目標の決定は、最近の会話（言ったこと・頼まれたこと）も見る
3. **行動に関わる返答は、返答と目標の変更を1回の生成で出す**。別々の呼び出しにしない（ずれようがない形にする）
4. **行動が変わったら口に出す**。目標の開始・終了（達成・停滞・断念）と、頼みを断ったことを実況の種にする
5. **Jev はこの外**。Jev は目標と欲求から作った候補からしか選ばないので、言ったことと食い違うのは Gemini の3つの判断の間だけ

## 3. 視聴者の頼みの流れ

```
コメント ─▶ GenerateResponse（Gemini 1回）
            └─ 出力: { reply, change_goal, predicate, item, count, distance, goal_reason }
                 ├─ change_goal=false: 返答だけ（雑談・「今なにしてるの？」・断る）
                 └─ change_goal=true: PlaySession.request_goal(頼み) ─▶ 返答を話す
                                                    │
AdvancePlay の次のステップの区切り ◀────────────────┘
  ├─ 今の目標を「視聴者 X さんの頼み: …」で終える（GoalEndedEvent、これまでの目標に記録）
  ├─ bridge.set_goal(頼みの目標)
  │    ├─ 受理: GoalSetEvent(requested_by=X)。実況は繰り返さない（返答で言った）
  │    └─ 拒否: ViewerRequestRejectedEvent。実況で「やっぱり無理だった、理由」を言う
  └─ 以後は普通の目標として追う。終わったら GoalEndedEvent(requested_by=X, met=...)
       └─ 実況で X さんに結果を言う（できた / できなかった理由）
```

- **目標を書き換えるのはステップのループだけ**。返答は `/act`（最大 45 秒）や目標の決定と並行して走るので、返答の側は `bridge.set_goal` を呼ばずに、`PlaySession` に頼みを置くだけにする。目標の決定の途中に頼みが来たら、決まった目標は次のステップの区切りで頼みに置き換わる
- **頼みの目標は、今出せる述語に限る**。返答のスキーマは、最後の観測から作った述語（`_predicates`）だけを許す。夜に `cleared` を頼まれても出せないので、返答で断る
- **頼みは1つだけ**。後から来た頼みは前の頼みを置き換える。置き換えたことは返答で言うよう指示し、確実に伝わるよう `ViewerRequestReplacedEvent` を実況でも言う。「朝になったら」のような後回しの頼みは v1 では受けない（返答で断る。キューは作らない）
- **約束は述語の目標だけ**。「あとで踊るね」のような、ブリッジが判定できない約束はしない（プロンプトで禁止する）。「朝になったら〜するね」「〜してから行こうかな」のような先の予定の言い方も禁止する（最初の実機確認で 2/8 件出た）
- **実況は出来事が起きた時点の `Activity` で話す**。生成中に目標が変わっても古い/新しい目標が混ざらない。家の完成は次の目標と一緒に1回で言う（最初の実機確認で、完成の実況が直後に始まった頼みの目標と食い違った）

## 4. 安全の下限

コメントで行動を変えられるようになるが、変えられるのは述語の選択だけ。ブリッジの判定・安全の制約（夜は外に出ない、`cleared` は昼だけ、クリーパーと戦わない）は頼みの目標にもそのまま効く。M2 のフィルタができるまでは、これがプロンプトインジェクションに対する下限になる。

## 5. 構成

| 層 | 追加・変更 |
|---|---|
| domain | `Goal.requested_by`、`GoalOutcome`（application から移す）、`Activity`、`ViewerRequest`。`PlaySession` に「これまでの目標」「最後の観測」「頼み」と `activity()`。イベント: `GoalSetEvent.requested_by`、`GoalEndedEvent`、`ViewerRequestRejectedEvent` |
| application | `GenerateResponseUseCase` を書き換える（返答と目標を1回で出す）、`GenerateCommentaryUseCase` は `Activity` ときっかけを受け取る。`AdvancePlayUseCase` は頼みの反映・目標の終了イベント・会話を目標のプロンプトに渡す。述語のスキーマ・解析は `use_cases/goal_vocabulary.py` で共有 |
| infrastructure | `prompts/stream_context.py`（`Activity` と会話の書式、述語の説明。3つのプロンプトで共有）。返答のプロンプトに「約束するなら目標を出す」規則 |
| presentation | `GameService.session`、`LLMService.generate_response(..., session)`、`generate_commentary(recent_events, activity)`、`Narrator`（目標の終了と次の目標を1回の実況にまとめる。頼みの目標の開始は繰り返さない。断った頼み・未達成の頼みは必ず言う） |
| factories | `Conversation` を実況・返答・目標の決定で共有する |

## 6. 検証

- 単体テスト: 頼みがステップの区切りで反映される、目標の決定中に来た頼み、拒否が実況される、頼みの目標の開始を実況で繰り返さない、返答のプロンプトに実際の目標が入る
- 実機（Gemini、台本のコメント約8件）: 昼の行動の頼み（「ベッド作って」）、今は無理な頼み（夜の「外で戦って」）、「今なにしてるの？」、雑談
  - 行動を約束した返答には必ず目標の変更がついているか（ついていなければ失敗として数える）
  - その目標が次のステップで実際に追われているか
  - 「今なにしてるの？」の答えが実際の目標と合っているか
  - 返答の遅延（前の返答との比較）

## 7. 範囲外

- Twitch の取り込み（M2）とフィルタ、Phase 8 のオーケストレーター
- 後回しの頼み（キュー）、自由文の約束
- 実況の頻度・間合いの調整（今はイベントごとに1回）

## 8. 実機確認（2026-09-25、`spikes/coherence_live.py`、Gemini 3.8 Flash、ブリッジの実際の観測）

家の中、昼の目標 `have(log, 3)`（剣の材料）、夜の目標 `through_night`。

**1回目**（修正前）: 行動の頼み 2/2 で目標つき（ベッド、探検）。ただし次の3つの失敗があった。
- 探検の頼みが、まだ始めていないベッドの頼みを黙って置き換えた
- 目標なしで先の予定を約束した: 「朝になったら羊探して」への「剣を作ってから探しに行こうかな」、夜の「ゾンビ倒して」への「朝になって剣を作ってからにしようね」
- 家の完成の実況が、生成中に始まった頼みの目標と食い違った（「原木を集めに行く」と言ったが、目標は探検になっていた）

→ 置き換えを知らせるイベント、先の予定の約束の禁止、出来事が起きた時点の `Activity` で実況する、完成の実況は次の目標と一緒に言う、の 4 つで直した。

**2回目**（修正後、昼 6 件 × 2 周 + 夜 2 件）:

| 種類 | 結果 |
|---|---|
| 行動の頼み（ベッド） | 2/2 で目標つき。次のステップで `placed(bed, home)` が目標になり、材料のクラフトを始めた |
| 目標なしの約束 | 0/14 |
| 「今なにしてるの？」 | 3/3 で実際の目標どおり（昼: 剣のための原木、夜: 家で朝を待つ） |
| 今は無理な頼み（夜の戦い、ダイヤ） | 断って理由を言った |
| 遅延 | 1.1〜2.2 秒（以前の文章だけの返答は 1.4 秒前後） |

残る弱点: ベッドの頼みを引き受けたあとの探検の頼みに「今は原木集めを優先する」と答えた。実際には次のステップでベッドの目標に切り替わる（ベッドも板材を使うので、行動は大きくは食い違わない）。「次に取りかかる頼み」を今の目標より先に言うようにするかは、配信で見て判断する。
