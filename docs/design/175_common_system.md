# 175. すべての呼び出しに共通のシステム指示を入れ、用途ごとの決まりは本文の先頭に置く

2026-10-12、user: 「おすすめのほうで話を進めて」（案 A、`reading` と教訓の統合は共通なし）

## 1. 見つけた問題（コードは変えずに集計した結果）
- 同じ用途のシステム指示は常に同じだが、**用途ごとに有り無し・中身・置き場所がばらばら**だった。21 用途のうち 13 は空、8 は有り。
- ペルソナの入れ方が 4 通り（システム指示に全文 / 本文の先頭に 1 行 / 「AI 配信者として」だけ / 何も無し）。道具選びの `intent` は「配信者の口調」で書かせるのに、口調を決める情報が無かった。
- `reply` と `promise` のシステム指示は、ほぼ同じ文（約 9.8K 字）のコピー。直すとき片方だけ漏れる。
- 固定の決まりの置き場所が、`goal` はシステム指示、`tool` は本文の先頭 + `CACHE_BREAK` で流儀が違う。

## 2. 決めたこと（案 A）
1. **共通のシステム指示**（`prompts/common_system.COMMON_SYSTEM`、約 265 字）をアダプター（`OpenAICompatTextGenerator`）が `generate` / `generate_json` / `choose_tool` のすべてに入れる。中身は、誰か（Twitch の AI 配信者）、どこか（Minecraft Java 1.21.4、サバイバル）、入力の約束（ブリッジが測った事実を書き換えない）、言語の約束（声は日本語の話し言葉、識別子は原文）、形の約束。用途や状況で変えない。呼び出し自身のシステム指示（`skill_write` の 4K、教訓の食い違い判定）は、その後ろに続ける
2. **共通なしにした用途**: `reading`（読み上げ用のカタカナ変換）、`lesson_compaction`（教訓の統合）。ゲームの文脈が要らず、入れると変換せず配信者として答えかねない（`NO_COMMON_SYSTEM`）
3. **用途ごとの決まりは本文の先頭に移した**（`text_generator.with_rules`: 決まり + `CACHE_BREAK` + 本文）。対象: 実況・`live`（性格と話し方）、`reply` / `reply_final` / `promise`（返事の決まり）、`goal` 系（目標の決め方の規則 9.3K）。Claude のキャッシュは、これまでシステム指示の終わりに付けていた印の代わりに、この境目に付く（ツール定義 → システム → 本文の順に先頭から固まるので、固まる中身は変わらない）。Claude 以外では印は取り除かれ、本文が 1 本につながるだけ

## 3. 効果と限界
- 一貫性: 誰が・どこで何をしているかが、どの用途にも同じ文で入る。道具選びの `intent` の口調の根拠は、まだ共通には入っていない（ペルソナは声に出す用途の本文の先頭だけ。案 B は取らなかった。`goal` / `plan` の理由欄に口調が混ざるのを避けるため）
- **キャッシュ率はこの変更では上がらない**（固まる中身が同じ）。直近の実測は `plan` 0%、`commentary` / `live` 11%（約 6.8K 字のうち固定は約 0.8K）、`goal` 約 30%。これを上げるには、本文を「変わらない世界・方針（INFO）→ 毎回変わる今の状態（STATE）」の 2 段にして、境目を増やす必要がある。Anthropic の印は 1 リクエスト 4 つまで（今は共通のシステム指示 + 用途ごとの決まり + 活動の階層で最大 3）。次の設計で扱う
- 共通のシステム指示だけでは、キャッシュの最小トークン数（1024〜）に満たないので、それ単独ではキャッシュされない。後ろの印が先頭からの全体を固める
