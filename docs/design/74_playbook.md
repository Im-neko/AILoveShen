# 74. 定石（寝床 → 食料 → 建材 → 資材）

2026-10-01。状態: 実装済み、実機では未確認（配信の再起動が要る）。

## 1. きっかけ

user（2026-10-01）: 「生活の優先順位を付けたいです。寝床→食料(畑)→建材(植林場)→資材(鉄等)を最初の定石としたいです。他にも街開発にむけての定石があれば追加していきたいです。」

それまでは、大目標の並びを LLM が自由に入れ替えられ、畑と植林場は「家が建ったら足す」（設計書 72 の `_ensure_infrastructure`）だけだった。足されたあとも、LLM が別の大目標を前に出すと畑は進まない。順序を守る仕組みがなかった。

## 2. 決めたこと（user の答え）

- 強さ: コードで守らせ、守らせていることをプロンプトにも書く
- 段の終わり: 設営できて、栽培・回収のサイクルが回るようになってから次へ（畑なら畑と最初の収穫）。畑の水に要る桶（鉄 3）のための鉄集めは、その段の中で許す
- 置き場所: 設定ファイルの一覧（追加は設定に 1 つ足すだけ）

## 3. 仕組み

- `config/default.yaml` の `minecraft.playbook`: 順序つきの `{name, title, conditions, reason}`。今は、家 → ベッド → 木の剣（こちらで足した。畑より先に武器がないと、死んで持ち物を失う）→ 畑（`facility(wheat_farm_1)` + `have(wheat, 3)`）→ 植林場（`facility(oak_grove_1)` + `have(oak_log, 16)`）→ 鉄の道具（`have(iron_pickaxe)` + `have(iron_sword)`）
- 大目標になるのは、まだ済んでいない最初の段だけ（`ObjectiveKeeper._ensure_playbook`、`judge` で `_next_stage` の前）。`Objective.playbook` に段の名前。建てる・施設の条件にほかの条件が混ざってよい（街の段階と同じ扱い）
- 済みは一度きり（`ObjectivePlan.playbook_done`、`mission.json` に保存）。大目標の完了、または足す前にもう条件が満たされていたとき。畑が壊れても戻さない。収穫した小麦をパンにして `have(wheat)` が減っても、先頭に戻らないため
- 守らせる所（`ObjectivePlan`）: `add` は定石以外を定石の後ろに入れる。`move` は定石を動かせず、定石の前へ出すと `ValueError`（LLM の決定は理由つきで差し戻される）。`drop` は定石を断念できない。街の段階（`_next_stage`）は、定石の大目標がある間は足さない
- 施設の段: 設計（`FacilityDesigner`）してから足す。家が建っていて 64 m 以内、街の引っ越し中でないときだけ。そうでない間は、その段で待つ（次の段へ飛ばさない。60 秒ごとに調べ直す）。設計に 3 回失敗した段は飛ばす
- 育成中（2026-10-01 追記、user: 「回収まで待ちますが、待ってる間に非同期で植林場を作るのはアリです。但し、必ず完成を待ちます」）: 段に `ready`（設営ができて、育つのを待つだけの条件。畑なら `facility(wheat_farm_1)`）を書くと、それが満たされている間、その段は「育成中」で、次の段を同時に進めてよい。同時に進めるのは 2 段まで（`PLAYBOOK_PARALLEL`）。手を動かす段が先頭、育成中の段が後ろ（`ObjectivePlan.order_playbook`。育成中どうしは段の順）。どの段も、完成（全条件）まで待つ: 後ろに回った段もリストに残り、定石として動かせない・やめられない。畑が熟したら、次の判定で後ろの段が先頭に戻る（実際は、手を動かす段が済むか育成中になるまで）
- 生存の小目標（夜、空腹、体力、死亡）は小目標なので、これまでどおり割り込める
- プロンプト: 目標の決定のシステム指示に「定石」の決まり、状況に「定石（この順に。コードが守る）: [済] … → [今] … → [先] …」、大目標に `[定石 名前: 動かせない・やめられない]`。ゴールボードの大目標にも `playbook`
- 桶のための鉄: 畑の段の中目標に鉄の `have` を書いてよい（施設の条件がある大目標には `aimless_jobs` が働かない）

設計書 72 の `_ensure_infrastructure` は、これに置き換えた（畑・植林場は定石の段）。

## 4. 弱いところ（分かっていて入れた）

- 視聴者とディレクターの `when=now` も、定石の段の後ろに入る。返答は「今やる」と言うので、言うこととすることがずれうる。ディレクターだけ前に出す例外は、必要になってから
- `have(oak_log, 16)` は、野生の木で足りても満たされる（植林場の収穫と区別できない）。施設が完成していれば植林場はできているので、段は進む
- 畑の最初の収穫は、育つまでの実時間がかかる（小麦は 1 ゲーム日ほど）。その間は、次の段（植林場）を同時に進める（上の「育成中」）。畑が熟していても、手を動かす段が先頭にいる間は収穫に戻らない（食料の備蓄は `food_options` が別に回す）
- 家から 64 m 以上離れていると、施設の段は足されず待つ。それまで定石以外の大目標が進む
- 保存済みの `mission.json` にある古い大目標（旧版の「夜に寝られるようにする」など）は残り、定石の後ろに並ぶ

## 5. 定石の足し方

`config/default.yaml` の `minecraft.playbook` に、名前（重複しない）・題名・条件・理由を並べる。施設は `facility` の名前を決めておくと、初めて足すときに設計される。材料は段の中目標になる（段にしない）。

## 6. リストがいっぱいで足せないとき（2026-10-01）

定石の段の大目標も `max_goals`（6）の枠を取る。LLM の編集が「足す → 落とす」の順だと、足す時点で満杯で 3 回差し戻され、`no acceptable goal after 3 attempts: the objective list is full (6)` で決定が失敗した。

- `ObjectiveKeeper._apply`: 落とす編集を先に適用する（同じ編集の中で落としたあとの足しは通る）
- `ObjectivePlan.check_room` の文言: 落とせるもの・落とせないもの（定石、視聴者の頼み、街の段階と準備）を書く
- `_absorb`: 条件がすべて有効な定石の段の条件に含まれる、配信者自身の大目標を閉じる（設計書 72 の旧い `facility(wheat_farm_1)` など）。足す前と、開いている段に対して行う。まだ開いていない段の旧い大目標は閉じない
- やらなかったこと: 定石の大目標を枠に数えない案。実機で見てから決める

## 追記（2026-10-03）: 断られる並べ替えを書き続ける決定

夜の野外で、決め直しが 4 分以上通らなかった。ローカルのモデルが `plan_changes` に定石の大目標の `move`（先頭へ）を毎回書き、コードが「動かせない」と断る。理由を返しても同じ編集を 3 回書き、3 回目で決定ごと失敗した（5〜10 秒待ってやり直す、の繰り返し）。小目標（`at_home`）は妥当だった。`ObjectiveKeeper.without_refused` が、最後の試行で、プランが断る並べ替え・断念だけを捨てて、決定の残りを通す（足す編集は捨てない）。ほかの検査の「最後の試行は通す」と同じ扱い。

## 追記（2026-10-06、設計書 88）

- `shelter` に `keep: true`: 家を作り終えた後に壊れる（壁・屋根・ドア・足元）と、また先頭の段になる。畑は今までどおり戻さない
- 段 `yard`（`leveled(home, 6)`）と `lights`（`lit(8)`）を `food` と `lumber` の間に足した。どちらも `keep` にしない（家から離れると未達に数えられ、呼び戻される）

## 7. 種・苗木は全マスの 1/4 だけ集めて、残りは育ったものから増やす（2026-10-07）

状態: 実装済み、実機では未確認（ブリッジと配信の再起動が要る）。

user（2026-10-07）: 「小麦の種や苗木はある程度集まったらその後は成長させたものからさらに回収する形で目標数まで数を揃えるほうが探索せずに済み、その間に別のことも出来て効率的です。このことを定石の戦略に追加してほしい」。範囲は「文言＋橋も変える」、「ある程度」は「全マスの 1/4」（user の選択）。

それまでは、畑の種を全マスぶん（上限 16）、植林場の苗木を全マスぶん集めてから植えていた。草の種は 1 割、葉の苗木は 5% しか落ちないので、最初の調達が探し回る時間の大半だった。畑は全マスが植わるまで `facility(...)` が成り立たず、定石の `ready`（次の段を同時に進める条件）もそれまで成り立たなかった。

- `facility` 条件に `started`（`GoalSpec.started`、橋の `spec.started`）: 全マスの 1/4（`START_SHARE`、`facilities.mjs` の `startQuota`: 切り上げ、最低 1）が植わっていれば成り立つ。数えるのは作物・苗木のマス（水のマスは含めない）。`facility(name)` 本体の完了（全マス・柵・整地）は変えない。段の完了条件は全マスのまま
- 定石の `food` と `lumber` の `ready` を `started: true` にした。`PlaybookStep` の `ready` は、`started` を外した形が `conditions` にあればよい
- 種・苗木の最初の調達量（`goals.mjs` の `facility`）: 植わったマスが 1/4 に届くまでは、その不足分だけ集める（畑 5 マスなら種 2、植林場 4 本なら苗木 1）。種・苗木を持てば、まけるだけまく・植える（耕すのは、まく種が耕し済みのマスより多いときだけ、は今までどおり）
- 1/4 が植わったあと: 畑は、作物があれば既存の solver が熟したものを収穫して種を取り、育つ間は畑のそばで待つ（探しに出ない）。植林場は、育った木があればその葉から苗木を集め、なければ「育つのを待つ」と状況に書いて探しに出ない
- プロンプト: 定石の節、`abilities.yaml` の `get_seeds`・`plant_trees`、定石の `reason`

### 弱いところ

- 畑・植林場が育成中として後ろに回っている間は、収穫して残りを植える作業は進まない（手を動かす段が先頭にいる間は戻らない。§4 のとおり）。1/4 で育成中にしたぶん、この状態が早く始まり、全マスが埋まるのは遅れうる。`PLAYBOOK_PARALLEL` が 2 なので、`food` と `lumber` が両方育成中になれば、2 つの順に戻る
- 植林場は、育った木がまだ 1 本もないうちは、苗木を足す手がない（待つだけ）。苗木が育つには実時間がかかる。骨粉を持っていれば使えるが、橋はそれを集めはしない
- 植林場で、育った木の葉から苗木を集める手は solver 任せ（見えている葉を掘る。見えなければ探す）。自分の木の葉だけに限ってはいない
- 実機では未確認。再起動後、`food` の段が 1/4 の植えつけで育成中になり、次の段（`yard`）が先頭に来ること、種の収穫で残りが埋まることを見る

## 追記（2026-10-16、設計書 180）
