# 159. 返答の言葉を、決まった行動に合わせる

2026-10-10、user: 「言葉と行動の食い違いは1番避けたい。どうしてずれちゃうのか」「1から順に 2、3 もやって」
設計書 158（基本は従う）の続き。158 の「3 回直らなければ行動だけ `when=now` にする」は、この設計で外した。

## 1. ずれる原因（調べたこと）
1. **文と行動を 1 回の生成で別々に書いていた。** 返答の JSON は `reply` が最初で、そのあとに `request`・`when`・`conditions` が続く。モデルは先に流れで文を書き、行動は後から揃える（21:36 は「今の小目標 through_night、夜は明けていない」から「朝になったら」と流れた）
2. **食い違いを見る場所がなかった。** `PromiseCheck` は「約束があるのに何も登録されていないか」だけで、時期は見ない。12:37:54 は `placed(bed, home)` が後ろに登録済みなので `already` と判定されて通った
3. **文が確定した後に、行動側が変わる。** 上限・荒らし対策・158 の強制 `now` が `when` を直しても、文は直らない
4. **「今やる」と決めても、今動かない。** `PlaySession.defers_rethink` は、夜の待ち（`through_night` が夕方・夜）の間は考え直しを朝まで待たせる（2026-10-07、コメントの約束で夜越しが切られた対策）。しかも `through_night` が家の中で出す手は、置いたベッドで寝る `sleep` だけで、持っているベッドを家に置く手がなかった。`when=now` を守っても、朝まで待つ手しかなかった（これは 158 の検証で見えていなかった）
5. 小目標を決める呼び出し（`_decide_goal`）は、約束した「今やる」を知らなかった

## 2. 直したこと
### 2.1 行動を先に決め、文はあとで書く（1）
- 返答の生成（段 A）は今までどおり行動を決める。その `reply` は**下書き**になる。すべての関門（`unanswered`・`unjudged`・`rethink` の間引き・約束の確かめ・上限）を通って行動が確定したあと、その結果（`ReplyOutcome`）を事実として、段 B（`purpose=reply_final`）が返答を書き直す。話すのは B
- 結果の時期は**コードが決める**（`GenerateResponseUseCase._timing`）: 今やる（`now`）／すでに今していること（`already`）／後で（`later`）。`when=now` でも、夜の待ち（`defers_rethink`）の間は夜が明けてから、と事実に書く。`when=next` は「今の中目標『X』のあと」「今の大目標『Y』のあと」。断ったときは理由（cannot / wrong / unsafe / off_mission / limit）と詳しい説明
- 下書きは口調と質問への答えだけを使い、やるか・いつやるかは事実だけに従う。事実にない理由を作らない
- 段 B をしないとき: 雑談・質問（行動に関係しない `none`）、すでに大目標にある約束（時期を言えない）。B の生成が失敗したら下書きを話す（結果と食い違うなら一言に置き換える）
- 実機のモデル（claude-haiku-5-5）で試した: 下書きが「朝になってから」でも、事実が「今すぐ」なら「今すぐ置くね」、事実が「夜が明けてから」なら「夜が明けてから置くね」（各 3 回とも）

### 2.2 結果と文の照合（2）
- `ReplyOutcome.mismatch`: 今やるのに「朝になったら・あとで・終わったら…」、後でやるのに「今すぐ・さっそく・今から…」、断った・何もしないのに「〜するね」を検出する。検出したら書き直させ（1 回）、それでも合わなければ、結果だけから作った一言（`ReplyOutcome.fallback`）を話す。食い違った文は話さない
- 断った・何もしない結果では、Jev の約束の確かめ（`PromiseCheck`）も書き直した文に使う。外国語のコメントへの日本語、持ち物の事実（`ReplyFactCheck`）の確かめも書き直した文に移した
- 限界: 言い回しの辞書なので、辞書にない言い方は通る。言い回しの分類を Jev に聞く質問は足していない

### 2.3 「今やる」が、小目標の決定に届く（3）
- 夜の家の中の例外: ベッドを家に置く頼み（`placed(…bed, home)`）は、考え直しを夜の待ちに止めさせない（`request_rethink(urgent=True)`）。ブリッジの `through_night` は、家の中にいて、ベッドを持っていて、家に置いていないとき、`place_bed` の手を出す（`goals.mjs`）。置いたら次の手で `sleep`。ほかの物（チェストなど）の頼みは夜の間は動かない: 事実として「夜が明けてから」と言う
- `PlaySession.promised_now`: 「今やる」と受けた頼みを覚える（`PromisedNow`）。次の小目標の決定（`_decide_goal`）は、それを進める小目標（ブリッジが判定した、今進められる中目標とその次の一歩。大目標なら一番上の大目標のための小目標）を選ばないと差し戻す（`_check_promised`。最後の試行は通す）。食料・戦いなど、`through_night` と `at_home` 以外の身を守る小目標は先でよい。今は進められない約束（済んだ、手立てがない）は見ない
- 守れた約束は外す。守れないまま決定が通ったら 3 回の決定で諦め、WARNING に残す（約束が嘘になった記録）

### 2.4 続き: もうできている頼み（2026-10-10 22:11、user: 「なんぼ言ってもベッドで寝てくれない」）
- ログで確かめたこと: 再起動の後、ベッドを置いて（`place the bed in the house`）、21:55 と 22:06 に実際に寝ている（`slept through the night`）。寝ないで朝まで待っていたのは、置いたベッドがなかった 21:41〜21:43（上の修正の前）。昼に「ベッドで寝て朝にしようよ」と言われたときは、昼は寝られない
- その返答が食い違っていた: ベッドは家にあるのに、頼みを大目標 `placed(bed, home)` にして「今やるね」と言い（46 秒後に達成）、下書きは「もうベッドに入ってる」と事実でないことを言った
- 直し: 頼まれた条件がもう満たされているなら（`ObjectiveKeeper.all_met`）、大目標にも考え直しにもせず、結果を `MET`（新しくやることはない）にする。事実に「ベッドは家にある。寝られるのは夜になってからで、夜になれば家のベッドで寝る」を添える。`MET` で「今やる・さっそく」と言う文は書き直させる
- 試した（claude-haiku-5-5）: 「昼はまだ寝られないけど、夜になったら家のベッドでちゃんと寝る」と言う

## 3. 直していないこと
- 返答が遅くなる: 受けた・断った返答は、生成が 1 回増える（Haiku、思考なしで 1.5〜2 秒ほど）
- 夜に家の中でできる、ベッド以外の頼み（チェスト、作業台）は、夜の間は動かない（事実を言うだけ）。ブリッジに手を足せば広げられる
- 「諦めた約束」を視聴者に伝える言葉は出さない（記録だけ）
- 約束の確認が言い回しの辞書であること、ブリッジの状態との照合（「置く場所がない」と言うが本当にないか）はしていない
- 実機（Python とブリッジの再起動が要る）
