# 129. チェストに入れたのに「もう持っていない」と失敗する

2026-10-09、user: 「1から直してください」（畑の調査で見つかった、チェストにしまう手の失敗）。

## 1. 起きていたこと
「要らないものをチェストにしまう」手（`tidy`）が、2026-10-07 以降 125 回（10/7 に 42、10/8 に 83）失敗していた。成功は 10/4 までの 176 回が最後。メッセージは「could not put anything in the chest: what was to be put in is no longer in the inventory」。

実際にはしまえている。20:29Z の持ち物 `dirt 38, peony 3, orange_tulip 1, rose_bush 1` が、失敗が返った後の 20:30:30Z の持ち物からなくなっていた。失敗の結果は、5 分間この手を出さなくし（`tidyBlockedUntil`）、目標の失敗の数にも入った。体力が少ないときの緊急の預け入れ `stash` も同じ数え方だった。

## 2. 原因（`primitives.mjs` `putInChests`、`36acf96`: 10/6 23:52）
預けた数を、預けた直後の `bot.inventory` の減りで数えていた。mineflayer は、チェストの窓を開いている間は `bot.inventory` を更新せず、窓を閉じるとき（`copyInventory`、`node_modules/mineflayer/lib/plugins/inventory.js:444`）にまとめて写す。そのため減りは常に 0、`put` は空になり、窓を閉じた後の持ち物を見る `noRoomReason` が「もう持っていない」と答えた。

それまでは、預けるのに失敗しなければ数どおり入ったとして数えていた（入りきらない分を取りこぼす）。直前の `tidy` のテストは歩く部分を省いて、成功の経路を確かめていなかった（結果が失敗でも成功でも通る書き方）。

## 3. 直したこと
- 入った分は、窓の中身（`window.containerItems()`）の増えで数える。チェストがいっぱいで一部しか入らないときも、入った分だけ数え、残りを次のチェストへ回す
- 預ける部分を `depositInto` に切り出した（歩く部分と分けて、テストで動かせる）
- テスト: `tidy.test.mjs` に 2 件（窓を閉じるまで `bot.inventory` が変わらない窓で、数どおり数える。いっぱいのとき入った分だけ数える）。数え方を元に戻すと 2 件とも落ちる。ブリッジ 901 件通過
