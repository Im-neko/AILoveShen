# 設計書 37: ボートで水を渡る、アイテムを使う（use_item）

## 1. きっかけ

ユーザー（2026-09-27）:「ボートって今使えるようになってる？」→「実装して使えるようにしてください。長距離水の上を移動する予定の場合は積極的に使いたい。これもアイテムを使うという仕組みで汎用化されてたりしないんですか？」→ 汎用の use_item も一緒に作る。

配信のボットは oak_boat を手に持っていたが、乗る手段がなかった。ブリッジにはアイテムを「使う」（右クリック）汎用の仕組みがなく、`activateItem` / `mount` を呼ぶ所が一つもなかった。道具モードで Gemini が呼べるのは決まった道具の一覧だけで、一覧にない操作はできない。

## 2. Mineflayer でボートが動かない理由（実測）

- 乗ると Mineflayer は自分の物理計算を止め（`physics.js` の `mount` で `shouldUsePhysics = false`）、`moveVehicle` は入力（`player_input`）を送るだけ。ボートの位置は乗っている側（クライアント）が計算してサーバーに送る仕組み（`vehicle_move`）なので、入力だけでは動かない
- `dismount()` は 1.21.2 以降で「ジャンプ」の入力を送るが、降りるのはスニーク。`entity_action` の `start_sneaking` で降りられた（`player_input` の shift は押し続けても降りなかった）
- 降りたとき（`set_passengers` から自分が外れる）に `bot.vehicle` を消さない
- 乗っている間は自分の位置（`bot.entity.position`）を動かさない

試験用のボット（BoatTest、配信のボットから 900m 離れた海）で確かめた（Paper 1.21.4）:
- 水面を見て `activateItem` でボートが置ける。岸のすぐ隣（まわりにブロック）は置けない（バニラはボートが当たる所を断る）
- 自分で計算した `vehicle_move` を 1 ティック 0.35 ブロック（毎秒 7m、バニラの水上の速さに近い）で送ると、サーバーは修正なしに受け入れた（5 秒で 35m）
- 乗ったまま叩いて壊すと、降りてボートが持ち物に戻る。降りてから叩いても壊れる
- 降りるとサーバーが位置を送り直し（`position`）、Mineflayer の物理が戻る

## 3. 仕組み

### 3.1 boat.mjs（低いレベル）

- `waterCrossing(bot, target, lookM, from, minWater)`: まっすぐな道のりを 1m ずつ見て、列のいちばん上（草・花は飛ばす）が水の区間のうち最初に `minWater`（既定 `BOAT_MIN_WATER` 12m）以上続くもの: `{ from, length, entry, waterY, landAfter }`。読み込まれていない所で打ち切る（`CROSSING_LOOK_M` 96m まで）
- `placeBoat`（水面を見て置く、出てきたボートのエンティティを待つ）、`mountBoat`、`drive`、`leaveBoat`（スニーク、位置の送り直しを待つ、`bot.vehicle` を消す）、`breakBoat`（叩いて壊す）
- `drive(bot, boat, target, signal, { maxMs })`: 1 ティックごとに次の位置を計算して `vehicle_move` と `steer_boat`（櫂の見た目）を送り、ボートと自分の位置も動かす。高さは水面のセルから置いたときの高さのまま。前 2.5m をボートの幅（±0.7）で見て、水で上が空いていれば進む
  - 前が陸: まっすぐ先の陸の向こうに長い水があれば島なので、±20〜90° の向きを試してよける。なければ向こう岸（`reached the shore`、landed）
  - 行き先の 3m 以内（`arrived`、landed）、`signal`（乗ったまま止まる）、先のチャンクが 3 秒届かない（時間では止めない: 設計書 38）
  - サーバーが位置を直したら（clientbound `vehicle_move`）、その位置から続ける
- `watchVehicle(bot)`: 降りたのに `bot.vehicle` が残る不具合を直す（index.mjs が 1 回呼ぶ）

### 3.2 長い移動に組み込む（primitives.mjs）

遠くへ行く行動はどれも `legToward` を通る（goto_pos、explore、go_home、goto_memory、survey、smelt・chest の行き来、家の建築場所）。その最初に `crossWater`:
- 乗っていれば続きを漕ぐ
- 道のりに長い水があり、ボートを持っていて、水が `BOARD_WITHIN_M`（24m）以内から始まれば: 届く所に置ける水面がなければ水際まで歩き、ボートを置いて乗り、漕ぐ。岸に着いたら降りて、ボートを壊して拾う
- ボートがなければ今まで通り（泳いで歩く）で、`state.waterAhead`（長さと時刻）を覚える
- 置く水面は、まわり 8 マスも水で上が空いていて、目から届く所（`waterToBoard`）
- explore は近い所でも `legToward` を通す（近くの長い水もボートで）

### 3.3 ボートを作る（goals.mjs）

`state.waterAhead` が 10 分以内で、ボートを持っていなければ: 今の持ち物から作れるなら（ソルバーで作る・置くだけ）その手順を `also`（「a boat to cross the water on the way」）で候補に出す。材料からなら行で知らせる（板材 5 枚、作業台）。ソルバーのグループに `boat`（チェスト付きは除く）を足した。

### 3.4 乗っている間の実行（runner.mjs、reflex.mjs）

- 水の上で続きを漕げる行動（`TRAVELS`: legToward を通るもの）以外は、始める前に降りてボートを拾う（`disembark`）
- 乗っている間はダメージで行動を止めない（止まるより漕いで離れる）。反射も動かない（ボートは敵より速い）。水に浮くためのジャンプも押さない
- 夕方・空腹などの必要（設計書 38）も、乗っている間は見ない（岸まで漕ぐ）

### 3.5 ミラー

ボートの位置はボットが決めて送る（サーバーは送り返さない）: ボットの `vehicle_move` を視聴者に clientbound の `vehicle_move` で送る。乗っている間のカメラは位置を送らず向き（`player_rotation`）だけ。視聴者の画面での見え方は実機（OBS）で確かめていない。

## 4. 道具

- `ride_boat {x, z, y?}`: x,z に向かって水の上を進む（短い水でも: `RIDE_MIN_WATER` 3m）。ボートがなく乗ってもいなければ断る
- `use_item {item, entity?, x?,y?,z?, hold?}`: 手に持って使う（右クリック）。entity のモブに（`useOn`）、x,y,z のブロックに（固いブロックは目に向いた面に `activateBlock`、水や空気はそこを見て `activateItem`）、どちらもなければ向いている方へ。`hold` 秒（0〜3）押し続けて離す。結果は持ち物の増減、道具の傷み、ブロックの変化、近くに出た落とし物。何も変わらなければ失敗（成功と言わない）
  - 使わない: 火打石・ファイヤーチャージ・溶岩バケツ（火事）、TNT・TNT 付きトロッコ・エンドクリスタル（爆発）、スポーンエッグ
  - 専用の道具へ: ボート（ride_boat）、食べ物をモブなしで（eat）、チェスト・樽・かまど・燻製器・シュルカーボックス・作業台・ベッド（deposit / withdraw / craft / smelt / sleep / move_furniture）
  - 今の家・建物・建てている家のブロックには使わない（`protectedReason`: 斧で家の原木の皮をはぐ、など）
- 技（skills）からも `t.use_item` / `t.ride_boat` で呼べる（`SKILL_ACTIONS` は行動の道具から作る）

## 5. 実測（2026-09-27、試験用ボット、本物のコード）

- 川: 土手の上（水面の 4 ブロック上）から水際まで下りて置き、16.4m 渡って向こう岸で降り、ボートを拾って、目的地まで歩いた
- 海: 岸から 200m 先へ: 1 回目の行動で 136.8m（そのときの 20 秒の上限。設計書 38 で外した）、2 回目で 54.9m 漕いで着き、降りてボートを拾った。位置の修正は 0 回
- use_item: 牛 2 頭に小麦 → 子牛が生まれた（3 頭）。バケツで水を汲めた（`-1 bucket, +1 water_bucket`）

## 6. 決めなかったこと・あとで

- 時間の上限（1 回 20 秒）はユーザーの指示で外した（設計書 38: 必要なとき（夕方・夜、空腹・体力、考え直し、見張り）だけ止める）
- 乗っている途中に夜・空腹になっても、行き先の岸まで漕ぐ（海の上では止まらない）
- 流れる水・滝・氷の上は試していない（氷は陸として止まる）
- 視聴者の画面でボートがどう見えるか（ミラー）は実機で確かめる

## 追記: 岸の角でサーバーに戻され続けて漕ぎ続けた（2026-09-27）

ユーザー:「ボートに乗ると何の行動選択もしなくなる」。実機: `go_home` の途中、(21.8, -177.5) でボートが止まり、5 分以上 1 つの行動が終わらなかった。
- 事実: サーバーのボートは同じ位置のまま、ブリッジの位置は毎回「サーバーの位置 + 西南西へ 0.35」だった。`drive` は毎ティック一歩を送り、サーバーが `vehicle_move` で戻し、また同じ一歩を送っていた
- サーバーが戻した理由（Paper 1.21.4 の `handleMoveVehicle` を逆アセンブルして確かめた）: 動いた後のボートの箱に、前はなかった当たりがあると、ログなしで戻す（`hasNewCollision`。ログが出る「moved wrongly」「moved too quickly」とは別）。ボートの箱は軸にそろった 1.375 x 0.5625 で、西南西へ進むと北西の角が、水面と同じ高さの草ブロック (20, 62, -179) にかかった（RCON で確認）
- ブリッジの見落とし: `clearAhead` は、進む向きに垂直な幅 1.4 の線の上の水面のセルだけを見ていた。斜めに進むと箱の角は線の外に出る
- 止まらなかった理由: `drive` には、戻され続けたら止まる条件がなかった（時間の制限は設計書 38 でなくした）。乗っている間は `needNow` も止めない

直したこと:
- `boxFree(bot, x, y, z)`: ボートの箱（幅 1.375、高さ 0.5625）がかかるブロックに当たり判定のあるもの（`boundingBox === 'block'`）がないか。`clearAhead` は 1 ティックの歩みごとに、真ん中の下が水で箱が何にも当たらないかを見る。睡蓮も当たり判定があるので止まる（前は通れるとしていた。サーバーで確かめてはいない）
- `drive`: 続けて 20 ティック（1 秒）戻されたら `the server kept pushing the boat back at x,z (something is in the way)` で止まる（時間ではなく、進めないことで止める）
- `legToward`: 岸に着かずにボートの上で止まったら、歩こうとせず（乗っている間 pathfinder は動かない）、理由を付けて行動を失敗にする。次の行動が移動なら続きを漕ぎ（向きを変えてよける）、ほかの行動なら降りる
- テスト: `boat.test.mjs`（実測の岸の角で箱を当てない、戻され続けたら止まる）
