# 119. 座標のマイナスの落ちは、符号を戻して実行する

2026-10-08、user: 「直してください」（決定項目 3「座標のマイナス落としの自動修正」）

## 1. 起きていたこと
ローカル LLM が負の座標のマイナスを落とし（z=-214 を 214）、`dig 26,70,214: 420.8m away (at most 32m); did you drop a minus sign?` と断られる手が続いた。断りには符号を戻した座標を添えていた（設計書の記録: 2026-10-03）が、次の手でも同じ書き間違いが起き、01:57Z〜03:40Z の畑の作業で 3 件、手が無駄になった。

## 2. 決めたこと
- 届かないほど遠い座標は、符号を戻して（x、z、両方）届く座標があれば、その座標に読み直して実行する。
- 届く候補が複数あるときは、いちばん近いものが次の 2 倍以上近いときだけ読み直す（書くのは近くのものだから）。同じくらいなら、どれか分からないので今までどおり断る（断りには符号のヒントが付く）。
- 直したことは結果に添える: `done (read 54,77,285 as 54,77,-285: coordinates are signed, and … is 56m away (you are at …); write the minus sign next time)`。モデルが次から正しく書く。
- 対象: `dig` / `place` / `move_furniture` / `use_item` / `inspect` / `plant` / `till` / `sow` / `water`（座標を取る手のうち、近くのものを指す手）。`goto` と `ride_boat` は遠くへ行く手なので、遠い座標は本当にそこかもしれず、読み直さない。
- 直す場所は `tools.mjs` の `signFixed` / `reach`（`within` の前）。断りの履歴（`noteRefusal`）は書かれた座標のまま。

## 3. 代償・未対応
- y と z の取り違え（`did you swap y and z?`）は今までどおり断る側が言う。
- 近くに本当に同じ形の別の座標があれば、そちらに読み直すことがある（比が 2 倍以上のときだけ）。

## 4. テスト
