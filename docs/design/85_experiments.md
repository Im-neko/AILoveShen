# 85. 行き詰まったときの実験: 見る・1 つだけ変える・もう一度見る・うまくいったら覚える

作成: 2026-10-04。実機では未確認。ユーザー: 「ほんとうはこういう試行錯誤を動的に LLM がやってくれるようにしたい」「より普段私たちがしていることに近い試行錯誤ができるように整備してほしい」。

## 1. 何ができて、何ができないか

私たち（人間と Claude Code）が家のドアで詰まったときにしたこと: ① ログを読む、② そのマスの状態を細かく見る（開閉・向き・隣・届くか）、③ 仮説を 1 つ立てて 1 つだけ変える（スニークを外す・素手で押す・面を指定する）、④ もう一度見て比べる、⑤ 効いたものを直す。

配信中の LLM に渡せるのは、**ゲームの中で完結する**①〜④と、効いた手を覚えること。ブリッジのコードを読んで書き換えること（原因が分かってから直す部分）は渡さない（技 `write_skill` が書くのは道具の並びで、ブリッジの規則ではない）。

## 2. 新しい仕組みを作らない

「実験モード」という状態やカウンターや帳簿は作らない（似た仕組みが増えるのを避ける: 設計書 52 §0）。すでにあるものを使う。

| 要るもの | 使うもの |
|---|---|
| いつ実験するか | 行き詰まり: 続けて 2 回失敗（`Activity.failing`）、同じ理由が 3 回（`same_cause_run`）、状況が動かない（`Stagnation`）。`tool_stuck` と同じ条件 |
| 同じ実験を繰り返させない | `same_cause_run` が 4 回目で、その道具を出さない（設計書 51 追記 2）。プロンプトで「3 つ試して通らなければ別の手」 |
| 安全 | 新しい道具も `protectedReason`・`liquidReason`・断りの台帳・避難中の外出禁止を通る。素手のクリックは壊さないので、家のドアも押せる（`use_item` に品物があるときは、これまでどおり断る） |
| うまくいった手を残す | 覚えた候補（設計書 52）。座標を含まない手だけ覚える規則は変えず、家のドアには座標の代わりに `target: home_door` を書けるようにした。さらに `WORLD_CHANGE_TOOLS`（`use_item`）は、成功そのものを「効いた」印にする: ドアを開けても持ち物も小目標の残りも変わらず（家に入るのは次の手）、これまでの「持ち物か進み具合が変わったら覚える」では覚えられなかった（`begin → settle` のテストで確かめた）。`use_item` は何も変わらなければブリッジが失敗にするので、成功＝世界が変わった |

## 3. 道具

行き詰まったときだけ道具の定義に加える（道具の定義は 1 手の時間の大半を占める: 設計書 51。`look_screen` と同じ作り）。`tool_specs(experiment=)`、`AdvancePlayUseCase` が手番ごとに決める。

- **`inspect {x?, y?, z?}`**（調べもの、すぐ返る、`src/inspect.mjs`）: 座標があればそのマス（ブロック名、`props`＝ドアの `open` / `facing` など、6 方向の隣、目からの距離と届くか、目との間にあるブロック、断られる理由＝`protected`（家や建物）/ `liquid_holder`（水を抱えるブロック）/ `refused_before`（そのマスへの手が前に断られた台帳の項目。どの動詞でも。なければ空の配列）、そばのモブ）。座標がなければ自分（位置、向き、スニーク、手に持つ物、地面か水か、視線の先のブロック）。
- **`diagnostics {kind?, n?}`**（調べもの）: ブリッジが残した失敗の記録の最後の `n` 件（`door` = `door-toggles.jsonl`、`place` = `place-refusals.jsonl`、`stuck` = `stuck-walks.jsonl`）。`kind` を省くと種類ごとの最後の 1 件。場所は各記録を書くモジュールと同じ環境変数。
- **`use_item` の拡張**: `item` を省くと素手で `x,y,z` のブロックを右クリックする（ドア・レバー・ボタン）。`face`（押す面 up/down/north/south/east/west。押す点はその面の真ん中）、`sneak`（指定したときだけスニークを触り、終わりに外す）、`target: home_door`。結果には、ドアの開閉などブロックの状態の変わり（`open: false -> true`）も数える（これまでは名前が変わらないと「何も変わらなかった」になった）。新しい `interact` 道具は作らなかった（`use_item` と 2 つになるため）。
- 調べものなので、失敗や同じ理由の数には数えず（`is_query`）、覚えない。1 手番の調べものは 5 回まで（`MAX_QUERIES_PER_STEP`）。
- 技（`t.inspect` / `t.diagnostics`）にも `QUERY_TOOLS` として自動で付く。

## 4. プロンプト

行き詰まりの節（`TOOL_STUCK_SECTION`）に手順を書いた。実験の道具が出るときは必ずこの節も出る。**変えるのは 1 回に 1 つ**:

1. `diagnostics` で記録を読み、`inspect` でそのマスと自分を見る
2. 仮説を 1 つ立て、`use_item` の押し方を 1 つだけ変える
3. もう一度 `inspect` で変わったか確かめる。変われば続ける（効いた座標なしの手は覚えた候補になる）。変わらなければ別の 1 つを変える
4. 3 つ試して通らなければ別の手（家に戻る・小目標を変える）へ

能力帳（`abilities.yaml`）に `experiment` の項を足した。`tool_stuck` は思考なしで動くため、「自由に実験して」ではなく手順を固定した。

## 5. 限界（してほしい人は言ってほしい）

- 実験できるのは、**今ある道具で変えられるもの**に限る。この道具で変えられるのは `use_item` の押し方だけ。置く・掘る・歩くの細かい手（向き、ためらい、足場）は、同じ形で足せるが、必要になってから足す
- 「何を変えるか」はモデルの知識で決まる。Qwen は Minecraft の細部を知らないので、`inspect` の出力が原因を指さないと当てずっぽうになる（`props` と隣の見え方が頼り）。ドアのように記録がある場面向き
- 覚えた候補に残るのは座標を含まない手だけ。座標が要る手（遠くの 1 マス）は残らない
- mineflayer の `activateBlock(block, direction, cursorPos)` は 3 引数形があり、`face` は実際に block_place に載る（型定義と実装で確認）。スニークは `setControlState('sneak')` が物理のパケットで伝える。ただし `activateBlock` 自身が最後に視線をマスの中心へ向け直す
- 実機では未確認。次に実機で見る: 行き詰まりで本当に `inspect` が呼ばれるか、呼んだ後に違う手を選ぶか、ドアが開いたときに `learned use_item(target=home_door…)` が覚えられるか

## 追記（2026-10-04、ドアが開かないと言い続けた約 50 分: 設計書 87）

採掘場の底（家の 14 ブロック下）で閉じ込められた原因は「ドアが開かない」ではなかった。実験の道具は使われていたが、ドアのマスを調べ続け、自分の位置（`inspect {}`）を見なかった（18 分）。「前提を確かめる」手順を足した: 行き詰まりの手順の 0 番に、家や行き先に着けないときは先に `inspect`（座標なし）を見る、とした。`inspect {}` は `closed_space`（歩いて出られない閉じた所か）と `home_door`（ドアまでの水平距離と高さの差）を返す。`diagnostics.kind` は enum（door / place / stuck）にした（モデルが `dig` と作って `unknown kind` になった）。
