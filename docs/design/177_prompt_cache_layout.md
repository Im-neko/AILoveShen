## 2. 決めたこと・したこと

1. **ツールの集合を固定する**（全部入り、並びも固定）。`tool_specs(can_look, skills, advisor, write_skill)` は `ACTION_TOOLS` → `SKILL_TOOLS` → `QUERY_TOOLS` の定義順に全部を返す。`groups_for` / `TOOL_GROUPS` / `CORE_TOOLS` / `search_abilities` で道具を足す仕組み（設計書 169）はやめた。`inspect` / `diagnostics`、素手・面・スニークの `use_item`（`item` は省略可）、`pickup`、`write_skill`（技を書く設定のとき）を常に出す。変わるのは、この実行で決まっていること（画面、advisor、技の有無）だけ。一覧の中の出し入れが残るのは、同じ問いを繰り返して調べものを閉じたとき・同じ理由で数字を変えて繰り返すのを止めたときの、ごくまれな場合だけ
2. **道具の 1 手は 決まり / 目標の階層 / 覚えた技 / 今の状態 の 4 つ**に分け、手前に印を置く（`format_activity` を `format_goals` と `format_doing` に分けた）。技の一覧（約 3K 字）は小目標が変わるまで同じなので、状態の前に置く。実況（`commentary` / `live`）は階層と状態の間に印を置く
3. **印は最後の 1 つだけ 5 分、ほかは 1 時間**（長い方を前に）。システム指示の印は、道具の定義が前にあるときだけ（ツールのない呼び出しのシステム指示は約 240 字でキャッシュの最小に届かず、印の枠を 1 つ使うだけ）。1 時間の書きは 2 倍だが、5 分を超える間隔で呼ばれる用途（`plan` の 25%、`tool_stuck` の 35%、`goal` 系）は 5 分だと毎回書き直しになる
4. **スキーマの説明は `SCHEMA_SLOT` の所に入れる**（印がなければ今までどおり本文の最後）。`plan` と `goal` は決まりの最後（最初の印の手前）に置く。`goal_schema(after_failure)` は呼び出しごとに変わらない: 述語は全部、大目標・メモの ID は文字列、小目標の番号に上限なし、`remedy` は `retry` / `change` の両方、`jobs` は常にある、`lesson` は任意。変わる値は本文（「今使える小目標」、ID つきの一覧、「やり直しは選べない」、死んだ様子）に書き、答えのあとにコードで確かめる: `_check_remedy` に、やり直しを選べないのに `retry`、死んだのに教訓なし、を足した（述語・ID・メモの根拠・計画が持つ中目標は前からあった）
5. **印を外した用途**: `advice`（間隔の中央値 524 秒。`situation` に入る道具の本文の印を取り除く）。**「稀な失敗系は印を外す」はやめた**: `tool_after_failure` / `tool_stuck` は 12 時間で 380 / 135 回（間隔の中央値 71 / 69 秒）で稀でなく、同じ先頭を分け合える。外すのは間隔が 5 分を超えるものだけ
