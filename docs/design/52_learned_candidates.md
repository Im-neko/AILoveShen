# 52. 覚えた候補: LLM が思いついてうまくいった手を、似た状況でもう一度出す

作成: 2026-09-29。2026-10-04 に「手の帳 / MoveBook」から「覚えた候補 / LearnedCandidates」へ名前を変えた（§0）。34（Jev が先に選ぶ）、22（技）、35（教訓帳）、51（判断の遅さ）に関係する。

## 0. 名前と、ほかの「覚える仕組み」との違い（2026-10-04）

ユーザー: 「元から用意されている手の名前と近くしたい」「それぞれの役割が名前から分かりやすいように」。ブリッジが用意する手は**候補**（`Candidate`、`candidates.mjs`。実行するのは**基本動作**＝`primitives.mjs`）で、Jev はその候補から選ぶ。LLM が見つけて覚えた手は、その選択肢に足されるので、**覚えた候補**（`LearnedCandidates`、Jev には `learned craft(...)` と見える）と呼ぶ。

| 仕組み | 覚えるもの | 作り方 | 出し方 |
|---|---|---|---|
| 候補（元から） | ブリッジが今すぐ実行できる 1 手 | ブリッジが世界から作る | Jev が選ぶ |
| **覚えた候補**（この設計書） | LLM が選んでうまくいった 1 手（道具の呼び出し 1 回） | 自動（効いたら覚える） | Jev の選択肢に `learned …` として足す |
| 技（22） | LLM が書いた複数手の手順（JS） | LLM が `write_skill` で書く | Jev の選択肢（検証済み・引数なし）と `run_skill` |
| 教訓（35） | 助言や失敗の学びを文章で | LLM が書く | プロンプトの「思い出したこと」 |
| 定石（74） | インフラを作る順番 | 設定ファイル | コードが順を守り、プロンプトにも出す |

統合はしない（覚えるものも出す先も違う）。覚えた候補は「1 手だけで、自動で覚える技」に近いが、技は書くのに時間がかかり、1 回きりの学びを拾えないので、別に持つ。以下の本文は、改名前の「手の帳」「move」の書き方が残っている（`MoveBook` → `LearnedCandidates`、`Move` → `LearnedCandidate`、`data/moves.json` → `data/learned_candidates.json`、`logs/moves` → `logs/learned_candidates`、設定 `moves*` → `learned_candidates*`、Jev に見える `remembered` → `learned`）。


## 1. きっかけ

ユーザー（2026-09-29）: 「道具が壊れたりこういうゲーム内のイベントを LLM や Jev に伝えられないか。また、なにかが足りなくなったときに LLM が判断して出した手を永続化して、その後また同様の状況では再提示できるようになっていてほしい」→ 提案（状況と手の組を覚えて Jev の選択肢に出す）に「その方向で進めていってほしい」。

畑の小麦（設計書 51 の実機ログ、2026-09-29）: クワが壊れ、種を使い切ると、Jev の選択肢が `wait` だけになり、10 秒ずつ待ち続けた。LLM が 06:59 に草を掘って種を集める手を自分で思いついたが、Jev はそれを知らず、次に同じことが起きればまた LLM を呼ぶ（1 手 10〜20 秒余分）。ブリッジの候補にない手を LLM が見つけるたびに、その学びは 1 回きりで消えていた。教訓帳（35）は文章で、Jev の選択肢にはならない。技（22）は JS で、LLM が書く手間がかかる。

## 2. 何を覚えるか

**LLM が選んだ 1 手（道具の呼び出し）が成功し、そのあと持ち物か小目標の進み具合が変わったもの。** 状況（目標の種類・対象・場所）といっしょに `data/moves.json` に保存する。ワールドを作り直すときは `data/moves-<日付>.json` に取っておき、新しいワールドでは空から始める（1 回うまくいっただけの手が多く、前のワールドの偶然が混じる）。

覚えてよい道具は、座標や対象の id を引数に持たないものだけ（`moves.py` `REMEMBERED_TOOLS`）:

| 覚える | 覚えない |
|---|---|
| craft、eat、equip、smelt、use_item、pickup、build_next、level、plant / till / sow（x, y, z なし） | goto、dig、place（座標）、attack、flee（id）、move_furniture、ride_boat、wait、sleep、do_suggestion（すでにブリッジの候補）、技の呼び出し、withdraw / deposit（数はそのときの不足で決まり、ブリッジが正しい数の候補 `take N from the chest` を出している） |

数の引数（`count`、`times`）は保存しない（省略した既定で足りる: craft は 1 回、smelt は持っている分）。数だけ違う同じ手が別々に増えていた（2026-09-29 の実機: `withdraw` の `count` 3 / 2 / 8）。

座標のある手を覚えないのは、場所が変わると意味を失うため。今回の畑の草掘りのように座標つきで LLM が選んだ手は覚えられない: そちらはブリッジの候補で直した（設計書 33 の追記、`solver.mjs` の `growing`）。手の帳が受け持つのは、クラフト・持ち替え・チェストの出し入れ・かまどなど、対象が名前で決まる手。

## 3. 効いたかどうか

手を選んだ次のステップの初めに（`MoveBook.settle`）:

- 持ち物が変わった、または（同じ小目標のまま）残りの作業が減った・目標が満たされた → 効いた
- どちらも変わらない → 効かなかった（何も起こさない手は覚えない）
- 実行が失敗した・断られた → 見ない（LLM の手なら覚えない、帳の手なら効かなかったと数える）

## 4. 思い出す・出す

小目標のステップごとに、状況（`situation_of`: 目標の種類、対象、場所）が同じ手を最大 `moves_shown`（3）件、効いた順に Jev の選択肢へ `remembered craft(item=wooden_hoe)` として足す（`StepPicker.options`）。選ぶのは Jev のまま。選ばれたら、その道具をそのまま実行する（`do_suggestion` でなく元の道具。見張りは付けない）。状況の照合は目標・対象・場所と、そのとき選択肢に出ていた手の種類（`offers`: `offers_of`。dig+explore のように、どの場面にも出る equip / eat / pickup を除いた動詞の集まり。待つだけなら `wait`）が同じ手だけ（時刻や体の様子は問わない）。LLM が呼ばれるのは Jev の選択肢に合うものがないときなので、選択肢が豊かな場面（実機で 12 個並び、Jev の確信度が 0.1 になった `have(food)`）で覚えた手が、別の目的の同じ目標の場面に出ることを減らす。覚え方が変わる前に保存した手（今は覚えない道具、キーが足りないもの）は読み込むときに捨てる。

## 5. 効かない手は消す

帳から選んだ手も、選んだ次のステップで効いたかを数える（`worked` / `failed`）。効かなかった数が効いた数を超えたら消す。同じ手が LLM の選択でもう一度うまくいけば `worked` が増える。上限は `max_moves`（100）で、超えたら効きの薄い古いものから消す。

## 6. 設定・記録

`minecraft.agent.moves`（既定 true、道具モードのみ）、`moves_path`（`data/moves.json`）、`moves_record_dir`（`logs/moves/*.jsonl`: `remember` / `worked` / `failed` / `drop` / `forget`、状況、手、数）、`moves_shown`、`max_moves`。選択肢に出たかは `logs/steps` の `options` に `remembered …` で残る。

## 7. 限界と次

- 座標のある手（掘る・歩く・置く）は覚えられない。対象を名前で表す道具（「一番近い草を掘る」）が要る。ブリッジの候補で足りるなら不要
- 状況の粒度は粗い（目標・対象・場所）。似ているが別の状況でも出る（選ぶのは Jev、効かなければ消える）
- 道具の破損などの出来事は、すでにブリッジが記録して LLM のプロンプトに出している（`wear.mjs`、「壊れた道具」）。Jev の状態（`build_action_context`）にはまだ入れていない
