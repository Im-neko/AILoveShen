# 172. 採掘場は使いまわし、掘り切ったら幹を延ばして枝を足す

2026-10-12、user: 「ブランチマイニングって上限はなくて、必要になったら必要になっただけ枝を伸ばしながら掘るもんじゃないんですか？」「行き止まりや洞窟にぶつかったらおそらく手元に大量にある丸石で床・壁・天井を作り空洞を突っ切るのが想定されている挙動です」「上限無しに伸ばして」「必要な個数目的の鉱物が取れるまで掘ります。採掘場は目的の度に作らず、使いまわします。どんどんながくなるイメージです」

## 1. 以前の形（設計書 68・86）
採掘場は、作るときに全セル（階段・部屋・東西の幹 8〜32・3 マスおきの長さ 10 の枝）を決める。掘り切ると `done`、壁に鉱石が出ないまま底に着くと `exhausted` の印を付け、別の入口に新しい採掘場を作る。2026-10-11 の夜は、`mine_2`（y16、幹 8＋8）が `done` で鉄が出ず、「底に着いて新しい採掘場を作る」手が選ばれないまま、別の手を繰り返した（設計書 171）

## 2. 決めたこと
- 掘り切った（`done`）採掘場の底にいて、探している鉱石が壁に見えないなら、**新しい採掘場を作らず、今の採掘場の幹を延ばす**（`minePlan` が `{ extend: 名前 }`、solver の `dig_mine` の leaf に `extend: true`、候補 `make the mine mine_N longer and dig it (…)`）
- `extendMine`（`facilities.mjs`）: 幹を短い向きから `EXTEND_LENGTH`（16）マス延ばし、設計と同じ並び（3 マスおき、最後の 1 マス手前まで、長さ `branch_length`、左右）で枝を足す。足したセルは配列の末尾に、幹 → 枝の順（どのセルも先に空けた隣に立って掘れる）。`layout.reach[向き]` に幹の長さを持ち、状態を `building` にする。`dig_mine` が掘る前に呼ぶ（`c.extend`）
- **上限は置かない**。幹が終わるのは、(1) 危ないもの（水・溶岩・岩盤）で `stopMine` に打ち切られたとき（幹の長さが `reach` より短くなった向きは延ばさない）、(2) 延ばす先がほかの採掘場のセルに突き当たったとき（`layout.closed`）。どの向きも延ばせなくなって初めて、`exhausted` にして新しい採掘場を作る
- 掘る量: 「必要な個数、目的の鉱物が取れるまで」。`dig_mine` は壁に探している鉱石が出たら止まって、掘るのを次の手に任せる（既存）。取るのは小目標の個数が満ちるまで続き、見えなければまた延ばす
- 採掘場の使いまわし: 鉱石の高さ（`ORE_Y`）の底から ±8（`TOLERANCE`）の採掘場は、目的が違っても同じものを使う（`minesAt`）。高さの違う鉱石（石炭 y32、鉄 y16、ダイヤ y-58）は、別の高さの採掘場が要る（坑道と枝は底の 2 マスの高さしか見えない）
- `stopMine`: 幹が危なくて打ち切るとき、その向きの幹の先と、先に付く枝だけを外す（以前は、そこから先のセルをすべて外し、もう一方の向きと全部の枝も消えた。延ばした分を末尾に足す形にしたため）

## 3. 空洞（洞窟）
想定どおり、洞窟に出たら丸石で床・壁・天井を作って突っ切る（`sealing.mjs`、設計書 86 §4。実装済み）。枝や幹を切るのは、水・溶岩・岩盤、丸石が足りないとき（足りなければ坑道の横の石を丸石にして、それでも足りなければ `paused` で待つ）、面に置けないときだけ

## 4. 未確認・限界
- 実機で、延ばした幹が掘られるか、枝の並びが正しいか、は未確認（ブリッジの再起動が要る）
- 幹が長くなると、入口から幹の先まで歩く距離が増える。松明は 8 セルごと（`MINE_TORCH`）に置くので、延ばした分の松明が要る（`torch` が足りなければ作りに戻る既存の流れ）
- 一度 `exhausted` の印が付いた採掘場は、もう延ばさない（印は「延ばせない」ときだけ付く）
