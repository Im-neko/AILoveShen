# 160. 街・家・建物・施設の名前を、シェン（LoL）の世界観にする

2026-10-10、user: 「配信内での施設等の命名は LoL やシェン意識で名前付けてほしい。面白いから」。確認した答え:
街の名前、家のコンセプト名、建物・施設の表示名にする。識別子は変えず、表示名を別に足す。方向はシェン中心。

## 1. 方針
- 識別子（`workshop`、`wheat_farm`。`built(workshop)` のように判定・目標・道具に使う a-z の名前）は変えない。変えると、LLM が何の建物か取り違え、判定のプロンプトが壊れる
- 視聴者に見せ、配信者が話す名前（**呼び名**）を別に持つ。大目標・中目標の題名（日本語）は対象外（意味が分かりにくくなる）
- シェン中心: 均衡の結社キンコウ、アイオニア、黄昏、気（Ki）、影、精神の刃、結束、均衡、忍者、守り手。何の建物か分かる言葉（工房・畑・倉庫・塔）は残す。2〜12 文字ぐらい、24 文字まで、かぶらせない

## 2. 実装
| 対象 | 内容 | 場所 |
|---|---|---|
| 街の名前 | 場所を選ぶプロンプトに名前の約束（`NAMING_THEME`）を足し、`town_name` の説明も同じ方向 | `game_prompt_template_builder.py` `SITE_TEMPLATE`、`goal_vocabulary.py` |
| 家のコンセプト名 | 最初の家・本家の設計のヒントに、シェンの世界観で付けると足した | `game_prompt_template_builder.py`（家の設計） |
| 建物・施設の呼び名 | ブリッジが `plan.design.title`（建物）と `fac.title`（施設）に持つ（`state.json`。ワールドのリセットで一緒に退く）。`PUT /titles` で置き、`GET /builds` `GET /facilities` と `/observe` の `titles` で返す | `minecraft-bridge/src/titles.mjs`、`builds.mjs`、`facilities.mjs`、`index.mjs` |
| 呼び名を付ける | `NameGiver.name_missing`: 呼び名のない建物・施設を見つけ（もうあるものも）、`purpose=naming` の 1 回の生成でまとめて付ける。目標を決めるたびに裏で試し（決定は待たせない）、付けられなかったものは 10 分あけて試す。長すぎる・かぶる・知らない名前は捨てる | `naming.py`、`play.py` `_start_naming`、`factories/game.py` |
| 見せる・話す | 目標ボードのラベル（建てる・作る・「建物」に置く）は呼び名で出す。プロンプトの状況に「建物・施設の呼び名（人に話すときはこの呼び名で言う。目標・判定・道具には元の名前を使う）」を出す | `goal_board.py`、`stream_context.py` |

実機のモデル（claude-haiku-5-5）で、今ある建物・施設 13 件に付けた: 「精神の刃の工房」「均衡の大倉庫」「黄昏の小麦畑」「結束の植林場」「気の坑道」など。

## 3. 直していないこと
- 大目標・中目標の題名、小目標の説明（`have(planks, 64)` の日本語）は変えない
- 呼び名は一度付けたら変えない（付け直す手はない。ブリッジの `/titles` を叩けば置き換わる）
- 配信者が識別子を口にする場合（目標の書き方や道具の引数）は変わらない。プロンプトに「話すときは呼び名」と書いただけで、強制はしていない
- 家の名前そのもの（`home`、`base_house`）にも呼び名は付くが、「家」の表示（`家: …`）は変えていない
- 実機（ブリッジと Python の再起動が要る）。既にある建物・施設には、再起動後の最初の目標の決定で付く
