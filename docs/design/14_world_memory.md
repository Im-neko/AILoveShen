# 世界の記憶（拠点・見た場所・チェスト）

作成: 2026-09-25。`11_primitive_actions.md`・`13_goal_hierarchy.md` の上に、今は見えないが前に見たことを覚える仕組みを足す。

## 1. 目的

ユーザーの方針（2026-09-25）:
- 目標の進み具合、チェストの中身、装備、拠点の場所などの進行情報を、状態として持っておきたい
- 役割は永続化と判断材料が大きい。中目標の選択肢にも効く

frun2 で見えた問題:
- 起動のたびに家を設計し直して、完成済みの家が「未完成」に戻った（`2869b8b` で、拠点があれば設計しないように直した。ただし家の名前と設計は引き継げない）
- ベッドに要る羊を、前に見たかどうかに関係なく毎回探し回る。近くの半径 32 マスに無ければ「探索」しか候補が出ない

## 2. 原則: 写しを持たず、見えないものだけを覚える

| 種類 | 例 | 持ち方 |
|---|---|---|
| 今いつでも読めるもの | 持ち物、装備、体力、時刻、目標の進み具合 | **持たない。** 毎回世界から読む（写しは世界とずれる。「判定は世界から」の原則）。装備は `f73bf79` で観測に足した |
| 前に見たが今は見えないもの | 拠点の場所と名前、資源や動物を見た場所、チェストの中身 | **覚える。** いつ見たかを必ず一緒に持ち、古い記憶は古いと分かるように見せる |

記憶はブリッジに置く（`minecraft-bridge/src/memory.mjs`、`data/state.json` に保存）。理由は次の2つ。
- 世界を直接見て、ソルバーと候補がそのまま使える
- 家・プラン・目標をすでに `state.json` に保存している

Python 側は `/observe` の要約を読むだけ。中目標（`data/mission.json`）とは分けたまま。

## 3. 拠点

- 家（`state.home`）に名前と設計を持たせる: `{ name, design, door, bounds, bed, breach }`。拠点を複数持つ形（倉庫・畑）は、2軒目の建物を建てる M3 で足す（それまで使う場所がない）
- 家の設計（名前、コンセプト、大きさ、ドアの向き）は `PUT /build-plan` と一緒に送り、プランと拠点に持たせる。設計を飛ばした起動でも、`GET /build-plan` から設計図を戻せる（家の名前が実況に残る）
- 今の `state.json`（設計の情報がない家）は、名前なしの拠点として読み込む
- 付随する修正: 起動時に「拠点はあるが、プランが別の未完成の家」になっている状態（frun2 の起動で2軒目のプランが上書きされた）は、実行の前に手で戻す（介入として記録する）。設計を飛ばすようにしたので、これ以上は起きない

## 4. 見た場所

- 採掘・狩りの対象を探すとき（`digTargets` / `huntTargets`）と、探索の途中で見つけたものを記録する
  - 対象: 原木（木の種類ごと）、羊・牛・豚・鶏、石、石炭、鉄、水、砂
  - 近いものはまとめて1か所として持つ（16 マス四方の区画ごとに、位置・数・最後に見た時刻）
  - 種類ごとに最大 8 か所。古い順に消す
  - 動物はすぐ動くので、一定時間（ゲーム内の1日）で古いものとして扱い、候補には出さない
- 使い方
  - ソルバーの「探索」の葉に、覚えている場所へ行く候補を足す: `go to sheep seen at 120,-310 (4 min ago, 3)`。方角だけの探索より先に出る
  - 行って何もなければ、その記憶を消す（空振りを繰り返さない）
  - 採った・倒した分は数を減らす
- 死んだ場所も覚える（落とした物を拾いに行く候補。M5 の前提）
- **探索した範囲**も覚える（16 マス四方の区画ごとに、行った時刻）。探索の方角は、行っていない区画が多い方を先に出す。frun2 では食料探しが起点のまわりを 21m ずつ往復し、何も見つけられずに飢えた（`366949e` で、目標を設定した地点から離れる方向だけを出すように直した。区画の記憶はその先で、目標をまたいでも同じ場所を探し直さないためのもの）

## 5. チェスト

**プリミティブ**（今は無い）:

| プリミティブ | 内容 |
|---|---|
| `place_chest` | 拠点の中に置く（置き場所は拠点の床の空き） |
| `deposit(item, n)` | 開けて入れる |
| `withdraw(item, n)` | 開けて出す |

- 開けたときに中身を記録する（位置、中身、時刻）。サーバーは配信専用で、チェストを触るのは bot だけなので、記録した中身は次に開けるまで正しいとみなす。開けたときに記録と違えば、上書きしてログに出す

**ソルバー**:
- `have(item, n)` は持ち物だけで判定する（今のまま）
- 足りない分を満たす方法として、チェストから出すことを足す（葉 `withdraw`）。採掘・クラフトより前に考える（近くて確実なため）

**入れるとき**:
- 持ち物の空きが少ない（空きスロット 8 未満）ときに、拠点の中で `deposit` の候補を出す。何を入れるかは、今の目標に要らない物から
- 決め方は Jev の候補選びに任せる。規則では決めない（11 の方針）

**中目標の条件を足す**:
- `stored(item, n)`: チェストに n 個ある（記憶から判定）
- 例:「食料を蓄える」= `stored(food, 16)`、「木材を備蓄する」= `stored(log, 32)`
- 持ち物の `have` は、使うと減るので「一時的に持った」だけで完了してしまう。`stored` は備蓄として意味がある（13 §3 の「`have` は使うと減る」への答え）

## 6. 判断材料としての見せ方

`/observe` に `memory` の要約を足し、`stream_context` で3つのプロンプト（小目標の決定、実況、返答）に同じ書式で出す。

```
- 拠点: ぽかぽかログハウス（家、ここから 12m、ベッドあり）、倉庫（チェスト 1: 原木 20、丸石 14）
- 覚えている場所: 羊 3（北東 80m、4 分前）、鉄（西 40m、12 分前）
```

- 小目標の決定: 「羊がいない → 探索」ではなく「北東で羊を見た → そこへ行く」を選べる
- 中目標の選択肢: 覚えている資源から、足せる中目標が分かる（鉄を見た → 石の道具のあとで鉄を目指す）。`stored` で備蓄を中目標にできる
- 返答: 「羊どこにいた？」に記憶のとおり答える（作り話をしない）
- ゴールボード: 拠点の名前とチェストの中身を JSON に足す（配信画面でどう見せるかは、ここでは決めない）

## 7. 構成

| 場所 | 追加・変更 |
|---|---|
| bridge | `memory.mjs`（拠点・見た場所・チェストの記録、区画ごとのまとめ、古さ、保存）、`state.json` に `memory`。プリミティブ `place_chest` / `deposit` / `withdraw` / 覚えた場所へ行く `goto_memory`。ソルバーの葉 `withdraw`、探索の葉に記憶の候補。述語 `stored`。`PUT /build-plan` に設計、`GET /build-plan` で返す。`/observe` に `memory` の要約 |
| domain | `CONDITION_PREDICATES` に `stored`。`GameObservation` に記憶の要約 |
| application | 起動時: 拠点があれば `GET /build-plan` の設計から `HouseBlueprint` を戻す。`goal_vocabulary` に `stored` |
| infrastructure | `stream_context` に拠点と記憶の書式。述語の説明 |
| presentation | ゴールボードに拠点とチェストの中身 |

## 8. 決めた既定値（ユーザー承認 2026-09-25）

- 動物を見た記録は、ゲーム内の1日で古いものとして扱い、候補に出さない
- チェストの中身は、次に開けるまで記録どおりとみなす（チェストを触るのは bot だけ）
- 持ち物の空きスロットが 8 未満のとき、拠点の中で `deposit` の候補を出す。選ぶのは Jev

## 9. 実装の順番

1. 拠点（設計の保存と復元、複数の拠点の形）。小さく、家の名前の問題がすぐ直る
2. 見た場所（記録、候補、要約）。ベッドのための羊探しに直接効く
3. チェスト（プリミティブ、記録、`withdraw` の葉、`deposit` の候補、`stored`）。一番大きい。倉庫の建物（M3）はこの後

各段階で `npm test` と `pytest` を通し、実機で確認してから次へ進む。

## 10. 検証

- 単体テスト: 区画ごとのまとめと上限、古さの扱い、空振りで消えること、保存と読み込み、`withdraw` の葉がクラフトより先に出ること、`stored` の判定、設計の往復
- 実機
  - 羊を見た場所から離れ、ベッドの小目標で覚えた場所へ直接向かうか
  - チェストに入れて出し、再起動後も中身の記録が残るか
  - 設計を飛ばした起動で、家の名前が実況に出るか
  - `stored(food, n)` の中目標が、チェストに入れた時点で完了するか

## 11. 範囲外

- 地図全体の地形の記憶（ブロック単位の記録はしない）
- 他のプレイヤーがチェストを触る場合の整合（配信専用サーバーの前提）
- 倉庫・畑の建物の設計と建築（M3）
- 記憶を MCP サーバー（Phase 5）に出すこと
