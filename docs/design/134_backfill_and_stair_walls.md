# 134. 鉱石を取った穴を埋め直す、階段も洞窟に面したら丸石で塞ぐ

2026-10-09、user: 「鉱石取るのに掘ったところは埋め直すのってはいってませんでしたっけ？」→「水がなくても通路がわかりにくくなるので埋め直したいです。また、坑道までの階段掘りやブランチマイニング中に空洞にあたったときは安全のために壁や屋根を作るのも入ってなかったら入れたいです」。

## 1. 調べたこと（入っていなかったもの）
- 水が流れ込んだ掘り跡の埋め戻しは入っていた（`plug_hole`、設計書 55 §3）。水のない穴は、整地・畑・家の壁以外では埋めていなかった
- 坑道・枝・部屋のセルが洞窟に出たときの丸石の床・壁・天井は入っていた（設計書 86 §3）が、**階段は対象外**だった。家がない間の階段掘り（`dig_down`）には塞ぐ仕組みがなかった

## 2. user の答え
- 範囲: 採掘場の外（地表・洞窟・普通の岩）と、採掘場の壁で鉱石を取った跡まで、全部（鉱石を取った穴）。土や丸石を掘った穴は含めない
- 時期: 取った直後、その場で
- 階段（`dig_down` と採掘場の階段）にも、洞窟に面したら壁・天井・床を丸石で作る

## 3. 鉱石の穴の埋め直し（`backfill.mjs`、`PRIMITIVES.dig`）
- 道具 `dig` も候補の `dig` も同じ行動 `PRIMITIVES.dig` を通る。取ったブロックが `*_ore` で、ドロップを拾い終えたあと、その穴を埋める。`ledger.mjs` の `bot.dig` は包んだだけなので使わない（整地・採掘・階段掘りの掘りまで埋めてしまう）
- 埋める物: 手元の土 → 丸石 → 深層の丸石（丸石は坑道を塞ぐ分に残すので土が先）
- 埋めない（結果に理由を書く）: 手元に埋める物がない、体力 10 未満、10 m 以内に敵がいる、穴に水・溶岩が入っている（水は `plug_hole` の番）。後で埋め直す仕組みは作っていない（そのまま開けておく）
- **理由を書かずに埋めない**もの: 通路のセル。採掘場の計画のセル、家（壁のまわり 1 マスを含む高さ 4）、建物の計画のセル。取った鉱石が計画のセルにあるときは、そのあと `dig_mine` が空けるので
- 足元の鉱石を掘って穴に落ちたとき: 掘る前に立っていたセルへ戻ってから、真下の穴を埋める
- 失敗は掘ったことの失敗にしない（`; could not fill the hole at …: <理由>` を足すだけ）。埋められたら、掘った跡の台帳（`state.dug`）に `plugged` の印を付け、`plug_hole` が二重に動かない

## 4. 階段の壁（`sealing.mjs`、`dig_mine` の階段、`dig_down`）
- 採掘場の階段（`part: stairs`、高さ 3 のセル）は、坑道・枝と同じ規則（設計書 86 §3）で塞ぐ。枝を持つ設計（`layout.sealing`）だけ。LLM が設計する採掘場は今までどおり
- `dig_down`（家がない間の階段掘り）: 1 段ごと（3 マスの縦の列）に、掘る前に洞窟に面した面を数え、丸石が足りなければ掘らずに止まる。足りれば掘って、床 → 壁 → 天井を塞ぐ。塞げなければ手前から丸石で階段をふさいで止まる。結果に `walled off N cave openings …`
- **入口から 4 段より深くなってから**（`SEAL_FROM_DEPTH`）: 浅い所は地上の空気に面しているだけで洞窟ではない。これを外すと採掘場の入口の段が空気に囲まれていて丸石を使い切る（テストで確かめた）
- 掘ってきた階段のセル（前の段の頭・足、自分の立つ所）は塞ぐ面に数えない（`enclosure` の `skip`）。採掘場のセルは今までどおり数えない
- 階段の向きの先に洞窟があると、次の段で今置いた壁を掘ってしまう。洞窟の中へ階段が入る形になり、洞窟のまわりを順に塞ぐ。丸石が尽きたらそこで止まる

## 5. 振る舞いが変わるところ（注意）
- **家がない間の `dig_down` は、深さ 4 より下で洞窟に面して丸石が 0 なら、今までと違い止まる**（今までは洞窟の側面を無視して下りた）。止まる文に「先に石を掘る」と書く。石を掘る階段の途中は丸石が増えるので、普通は足りるはず（実機では未確認）
- 鉱石を取るたびに土か丸石を 1 個使う。土は整地・畑でも使う
- 計画していない、普通の石・土・丸石を掘った穴は、今までどおり開いたまま（user の範囲）
