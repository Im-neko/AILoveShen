# 53. 開いた画面（チェスト・かまど・作業台）を視聴者に見せる

ユーザー（2026-09-29）: 「チェストや作業台を開いた時クライアント側の画面にはなにも映らなくて見てる側が微妙な気持ちになる。可能ならクライアント側にもその画面を反映してほしい」

## 1. 原因

`open_window` / `window_items` / `set_slot` は、ミラー（`mirror.mjs`）がサーバーのパケットをそのまま視聴者へ中継している。開くことは伝わっていた。映らなかった理由は 2 つ。

1. **一瞬で消える**: ボットは開いて数十〜数百 ms で操作し、すぐ閉じる。閉じる（クライアント → サーバーの `close_window`）を `relayCloses` が即座に視聴者へ送っていたので、画面が出る前に消えた。
2. **ボット自身のクリックの結果が届かない**: 取り出す・入れる・クラフトの結果を取るは `window_click` で、サーバーは結果のハッシュを受けて一致すれば `set_slot` を送り返さない（持ち物と同じ理由。`relayOwnState`）。視聴者の開いた画面の中身は、開いた時のまま変わらなかった。かまどの投入、チェストの出し入れ、作業台の結果の取り出しがすべて該当（レシピブックの材料の並べ込みだけはサーバーが送る）。

## 2. 直し（`relayWindows`、`relayCloses` の置き換え）

- 開いた画面（`open_window`）ごとに記録する。サーバーの `close_window` は中継せず（`fromServer` が true）、ボットの `close_window` の書き込みと同じく「閉じる要求」として扱う
- ボットの `window_click`（ウィンドウ 0 以外）の後、`INVENTORY_SYNC_MS`（100 ms）まとめて、Mineflayer の `bot.currentWindow`（クリックの結果を先に反映している）の全マスを `window_items` で送る（`windowPacket`。部品は `safeSlot` で数だけに絞る）
- 閉じる要求: 閉じる前の最後の中身を送り、視聴者側で閉じるのは、開いた／最後に変わった時刻から `WINDOW_HOLD_MS`（2 秒）後。過ぎていればすぐ。待つのは視聴者に送る分だけ（タイマー）で、ボットの操作は待たせない
- 次の `open_window` が来たら、閉じるのを待っていた画面は捨てる（新しい画面に置き換わる）。リスポーン・再ログインでも捨てる
- あとから参加した視聴者には、開いている画面（`open_window` の生のバッファと今の中身）を `replay` する
- ウィンドウ 0 の `close_window`（`resetInventory`）は今までどおり即送る

## 3. 限界

- 作業台なしのクラフト（2x2、ウィンドウ 0）は、視聴者のクライアントが持ち物の画面を自分では開かないので、映らない（サーバーから開かせる手段がない）。作業台を使うクラフト、チェスト、かまどが対象
- 中身の動きは、クリックごとではなく 100 ms ごとの最終状態（出し入れの途中は見えない）。カーソルに持ったアイテムは送らない
- 画面を見せる間もボットは次の行動に進む（歩き出しても、最後の変化から 2 秒は画面が出ている）
- 実機のクライアントでは未確認（ユニットテストは `test/mirror.test.mjs`）
