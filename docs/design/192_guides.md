# 192. 手引き（文章のスキル）

2026-10-18。ユーザーの案: 「ブランチマイニングの方法のような、よく使う手順は skill にしておくと良い」。技（JavaScript。設計書 22）は
動かす手順で、手引きは LLM が読む文。通常の `tools` と判断なしの `raw`（設計書 191）の両方で使う（ユーザーの選択）。

## 決めたこと
- 置き場: `guides/<名前>/SKILL.md`。Claude の SKILL.md と同じ形（frontmatter の `name`、`description`、本文）。`description` は
  必須（プロンプトの一覧に出す一行。「いつ読むか」を書く）。設定は `minecraft.agent.guides_dir`（既定 `guides`）。
- プロンプトには名前と一行の説明の一覧だけを出し（「## 手引き」。`tools` ではキャッシュの前の部分、`raw` では技の欄の前）、
  本文は道具 `read_guide {name}` で読ませる。本文を載せないので、手引きが増えてもプロンプトは大きくならない。
- `read_guide` は検索の道具（`SEARCH_TOOLS`）の一つで、ブリッジを通らず Python が返す（`WorldSearch`）。raw でも使える
  （`RAW_GUIDE_TOOLS`）。同じ問いを繰り返すと断る仕組みは検索と同じ。
- 道具の定義が 1 つ増える。`test_context_budget.py` の上限を約 100 トークン上げた（production 10028 → 10125 など）。毎ステップ
  送る固定部分が増える理由は、手引きという入口が要るから。名前は一覧にしか出ないので、手引きを増やしても定義は変わらない
  （キャッシュは崩れない）。
- 判断ではなく知識の文。raw の「ブリッジの判断 0」とは別の変数として足す（比べるときは、手引きの有無を揃える）。
