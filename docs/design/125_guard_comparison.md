# 125. 断りの標準と free を、同じ場面・2 つの LLM で比べる

2026-10-08、user: 「1,2,3を進めてください」の 3。「モデルの性能依存の問題かどうかは gemini 3.8 flash を使って比較検証します」

## 1. 問い
植林場の詰まり（設計書 122）は、(a) 弱いローカル LLM の問題か、(b) 断りが抜け道を塞いでいる問題か。標準（断る）と free（警告で通す、設計書 124）を、ローカルの Gemma と Gemini 3.8 Flash で同じ場面に当てて、成功率の違いを見る。

## 2. 場面 grove（`tools/bench_fixtures.py`、`config/benchmark.yaml`）
- ベンチ用のサーバーに、RCON（fill / setblock のみ）で平らな草地・家・植林場（6 マス）を作り、ブリッジを止めて `state.json`（家、施設、植えた記録、整地の記録）を書き、起動し直す。ボットが入った位置を基準にするので、座標は 1 回ごとに違う。
- 植林場: 4 マスに苗木、1 マスは空き、最後の 1 マスは設計の高さが地面の 2 段下で、その土地が整地の記録に載っている（2026-10-08 に 3 時間半詰まった形）。持ち物は白樺の苗木 2・石のツルハシ・パン 16。成功は `facility(birch_grove)` をブリッジが世界から判定する。
- LLM なしの確認（`probe_grove.py`）: 標準では、植える手が「固い」、掘る手が「整地の保護」、`level` が「平ら」と断り、台帳が掘る手を 5 分禁止にした。抜け道は `place` で苗木を地面の上に置く手と、free で掘って植える手の 2 つ。

## 3. 条件
4 通り × 3 回、1 回 10 分まで（`run_compare.sh`）。

| | 標準（`BRIDGE_GUARDS` なし） | free（`BRIDGE_GUARDS=free`） |
|---|---|---|
| ローカル（Gemma-4-26B-A4B-NVFP4） | local-standard | local-free |
| Gemini 3.8 Flash（`LOCAL_LLM=0`） | gemini-standard | gemini-free |

違うのは `LOCAL_LLM` と `BRIDGE_GUARDS` だけ。コミットは同じ（5278370）。植林場のマスの柱による判定（設計書 124 §5）と `ensureTreeCells` は両方のモードで効いている（この場面ではマスが 2 段下で、上が土なので `ensureTreeCells` は動かない）。配信用のブリッジ・サーバー・配信は止めて走らせた（記録: `logs/bench-grove-<条件>/`、1 回ごとに `grove-N/bridge/bridge.log` と `play.log`）。

## 4. 結果
| 条件 | 成功 | 秒(中央) | 歩(中央) | 断り(中央) | 警告(中央) | 死亡 |
|---|---|---|---|---|---|---|
| local-standard | 1/3 | 261 | 28 | 4 | 0 | 0 |
| local-free | 2/3 | 52 | 5 | 0 | 1 | 0 |
| gemini-standard | **0/3** | - | 18 | 6 | 0 | 0 |
| gemini-free | **3/3** | 54 | 4 | 0 | 1 | 0 |
| 標準 計 | 1/6 | | | | | |
| free 計 | 5/6 | | | | | |

環境の不具合は 0 件。標準と free を合わせた比べ方は、Fisher の正確検定で p = 0.08（両側。標準 1/6 対 free 5/6）、Gemini だけで 0/3 対 3/3 は p = 0.10。**5% では有意でない**。ただし向きは両方のモデルで同じで、free の成功はすべて 4〜5 手で終わっている。

## 5. 1 回ごとに何が起きたか（`bridge.log` の `[tool]` 行）
- **free の成功 5 回**: 毎回 同じ形。`plant` が「空いている地面がない（`dig it if it may be removed`）」と失敗 → `dig` が通る（結果に `(not enforced: will not dig dirt at …: the ground there is being leveled …)`）→ `plant` が成功。Gemini は 3/3 がこの手を最初に選んだ。
- **gemini-standard 0/3**: 同じ失敗の文に従って `dig` すると、整地の保護で断られる。その後、`plant`（座標指定）、`plant`（座標なし）、`level`、`inspect`、`find_blocks`、`go_home`、遠くの調査、泳ぎ、と手を変え続けたが、どれも抜けなかった。`demolish: true` も `override: true` も `place` も、3 回とも一度も試していない（`demolish: false` と明示する呼び出しは 4 回あった）。`level` は 2 回で成功（75・85 ブロック掘った）したが、別の中心だったので記録された土地のマスは直らず、植えるのは断られたままだった。
- **local-standard 1/3**: 成功は 261 秒の 1 回だけ。`plant` ×2 と `dig` ×2（2 回目は台帳）が断られた後、`level`（中心を別の座標、半径 5）が 79 ブロック掘り、そのあと植えられた。標準の 3 つめの抜け道（`level` の中心をずらす）で、私が LLM なしの確認で見つけていなかったもの。ほかの 2 回は 4 手前後で断られ、以降は別の方向に流れた（§6）。
- **標準での断りの数は少ない**（中央値 4〜6）のに、10 分で 13〜45 手しか進んでいない。断りの数より、断られたあと何をするかが成績を決めている。

## 6. 失敗した free の 1 回と、標準のローカルの 2 回（モデルの失敗）
local-free の 1 回目、local-standard の 1・3 回目は、同じ流れで終わった。**植えられなかった失敗のあと、目標の見直し（Gemma）が「既存の植林場は満杯」と診断して `birch_grove_2` という新しい植林場を足し、残り 1 本の苗木をそこに植えてしまう**。苗木が尽きたあとは葉から集める作業に入り、10 分に収まらなかった。ここは断りと関係なく、free でも防げない。Gemini はこの流れに入らなかった（6 回中 0）。原因は失敗の文の一部（「空いている地面がない」）を「満杯」と読むこと。

## 7. 解釈（言えること・言えないこと）
言えること:
1. 標準では、**弱い方のモデルだけでなく、Gemini 3.8 Flash も 0/3 で詰まった**。「ローカル LLM が弱いから」では説明できない。Gemini は、断りの文に書かれた「外から取れ」「`demolish`」のような抜け道を使わず、同じ種類の手を繰り返した。
2. free の 4 手（失敗 → 掘る → 植える）は、Gemini が毎回選んだ最短の手だった。標準では、その手そのものが断られる。失敗の文（「`dig it if it may be removed`」、設計書 122）が勧める手を、標準のゲートが断る。これは文とゲートの矛盾。
3. 弱いモデルの失敗（§6）は free でも残る。ゲートを外すことと、モデルの判断の質は別の問題。

言えないこと:
1. この場面は、free を作るきっかけの事故から作った。**free の効く場面を、free の効くように選んでいる**。ほかの作業（採掘、建築、畑）で free が良いとは、この結果から言えない。むしろ、free は安全でない手も通すので、ほかの場面での死亡・資源の損は測っていない。
2. 3 回ずつ。p = 0.08。ローカルの 1/3 対 2/3 は差と言えない（p = 1.0）。
3. 10 分の上限は、標準の流れ（調査・泳ぎ）が長く、Gemini が数分の計画の待ち（gemini-free 1 回目は計画の呼び出しが 160 秒かかり、成功まで 201 秒。ゲートと関係ない）に左右される。秒の比較は使わず、手数と成否を見る。
4. `BRIDGE_GUARDS=free` で警告に変えたのは作業知識の上位 10 箇所だけ。動きの途中の断り（水際で掘らない等）は変えていない。

## 8. 決めること（user）
- 既定を free にするか。この場面では標準が 6 回中 5 回詰まり、free が 6 回中 5 回通った。一方、free が他の作業で害を出さないことは測っていない。提案: **全部を free にせず、この比較で出た「抜け道のない断り」だけを直す**。具体的には、(a) 失敗の文が勧める手を、ゲートが断らないようにする（どちらかを揃える）、(b) 断りの文に、使える上書き（`demolish`、`level` の中心）を必ず書く、(c) 台帳で同じ手を 5 分禁止にするのを、断りに抜け道がないものは外す。その上で、別の場面（`night`、`pond`、`food`）で free と標準を比べ、害が出ないことを確かめてから既定を決める。
- 同じ比較を `food` / `pickaxe` で走らせるか（1 条件 15 分 × 3 回 × 4 条件 ≈ 3 時間）。

## 9. 測定の道具
`python tools/benchmark.py run --tasks grove --repeats 3 --cap-minutes 10 --out logs/bench-grove-<名>`（`LOCAL_LLM=1/0`、`BRIDGE_GUARDS=free` をシェルで）、`report <jsonl>`、`compare <前> <後>`。結果の行に `guards`、`tool_calls`、`tool_refused`、`tool_advised` が入る（`bridge.log` の `[tool]` 行を数える）。配信用のブリッジ（:3000）と配信が動いていると断る。
