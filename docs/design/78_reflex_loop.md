# 78 反射の繰り返しを止める

## 1. きっかけ（2026-10-01）

壁際の y=-22 の洞窟で、丸腰のまま、0.6 m のスケルトンから 6 秒ごとに `flee: now 0.6m from skeleton` を 20 分続けた（08:44:31〜）。Python の Stagnation と StuckCheck は動かず、user が気づくまで止まらなかった。

## 2. なぜ検知できなかったか

1. `flee` は 6 秒（`STUCK_MS`）離れられなくても、例外を投げず `now 0.6m from skeleton` を成功として返していた
2. 反射（`reflex.mjs`）は終わると状態を戻し、4 ティック後にまた発火する。同じ相手に何回続けたかの記憶がなかった（Jev も毎回新しい危険として聞かれ、毎回「逃げる」）
3. `fight` は相手が倒れるまで時間の上限なしに続く（設計書 38）。殴っても倒れない相手と、永久に殴り合う
4. Python の `_wait_out_reflex` は、反射が終わるまで 0.5 秒おきに待つだけで上限がなく、その後ろにある Stagnation / StuckCheck に届かなかった

## 3. 直したこと

- `flee`: 離れられずに止まったら失敗にする（`could not get away from <mob>: still Nm after 6s`）
- `fight`: 上限 `maxMs` を引数に足した（反射だけが 20 秒 `FIGHT_MS`。ツールの `attack` は今までどおり上限なし）
- 反射の記憶（`reflex.mjs`）: 逃げる・距離を取る・戦う・帰る、が終わっても相手が射程にいたら、その相手の `stalls` を数える（倒した・離れたら消す）。1 回続いたら、逃げる手を選択肢から外し、家が近ければ帰る（user: 「やむを得ない場合は逃走よりも帰宅を優先してもいい」）、帰れなければ戦う。`LOOP_FIGHT`（2）回続いたら帰る手も外して戦わせる（クリーパーは戦えないので、逃げる手を残す）。`LOOP_GIVE_UP`（4）回続いたら、その相手には `MUTE_MS`（1 分）反応しない（ダメージを受けたときは反応する）
- `POST /reflex/release {seconds}`（`releaseReflex`）: 動いている反射を止め、`seconds` の間、近づいた相手に反応しない
- Python: `_wait_out_reflex` は `REFLEX_WAIT_LIMIT_SECONDS`（60 秒）を超えたら `release_reflex(30)` を呼び、選ばせる（`IMinecraftBridge.release_reflex`）

## 4. 弱いところ

- 反応をやめた相手が本当に撃ってきたら、ダメージで反応が戻る（`hurt` は止めない）。そのあとの戦い・逃げも数えるので、4 回続けばまた 1 分やめる
- 丸腰で戦っても勝てない相手には、20 秒殴ったあとにやめるだけ。ツルハシを作る・持ち物を取りに戻る、は LLM が決める
