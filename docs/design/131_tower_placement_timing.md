# 131. 足場積みが「置けなかった」を繰り返す

2026-10-09、user: 「なんかめっちゃブロックの設置失敗してない？」→「修正して」。

## 1. 起きていたこと
ブリッジのログの `[place] 置けなかった`（`place-report.mjs` が記録）が、10/3 から毎日出ていた（10/4: 941、10/7: 1438、10/9 は 10:39 までで 351）。型は 7 割以上が「ボットが立っているマスに、浮いている間に置こうとして、サーバーが断る」（`the block is still air`、`standing_in_dest`、`on_ground: false`）。置いているのは経路探索（`mineflayer-pathfinder`）の足場積み（高い所へ上がるとき、真下に土を置いて上る）。

01:38:44〜01:39:16Z の約 30 秒、`(3,75,-293)` への設置が、`y=75.42`、`y=75.75` で断られる跳びを繰り返していた。頂点（`76.0` 以上）には一度も届かなかった。

## 2. 原因（`node_modules/mineflayer-pathfinder/index.js:544`）
真上置き（`jump: true`）の置く条件が `placingBlock.y + 1 < bot.entity.position.y`。`placingBlock` は土台のブロック（足元の 1 つ下）で、置くマスは足元のマス（土台の 1 つ上）。ボットの体は足から 1.8 上まで重なるので、サーバーは足が置くマスの上端（土台の `y + 2`）に届くまで置かせない。条件は、地面から少し浮いただけで満たされ、毎回断られる。

断られると `placeBlock` が失敗し、`resetPath('place_error')` が経路を作り直し、跳びのボタンも離れる。次の跳びも頂点に届かない前に置こうとして断られ、を繰り返す。

## 3. 直したこと（`patches/mineflayer-pathfinder+2.4.5.patch`、`patch-package` で `npm install` のたびに当たる）
置く条件を `placingBlock.y + 2 <= bot.entity.position.y` にした。1 回の跳びの足の高さを `prismarine-physics` で出すと、立った状態（足 75）から `75.42 75.753 76.001 76.166 76.249 76.252 76.177 76.024 75.797 …`。足が `76` 以上の tick が 6 回（約 0.3 秒）あり、この間に置ける。旧い条件が満たされていた 75.42 と 75.753 は、ログの断られた高さと一致する。

テスト（`test/tower-jump.test.mjs`）: パッチが入っていること、物理で足が届く tick があること（置ける 2 tick 以上、旧い条件だけが満たす浮いた直後が 3 tick 以上）。

## 4. 未確認・限界
- 実機（ブリッジの再起動後）。直ったかは、ログの `[place] 置けなかった` の数と、足場積みを使う作業（高い木の伐採、穴からの脱出）の所要時間で見る。置く窓は 6 tick と短いので、装備や経路の遅れで外すことはあり得る
- 失敗の約 2 割は別の型（地面に立って自分のマスに置く、`other` など）。この変更では直らない
- `climb out of the hole` など、ブリッジ自前の積み上げ（`primitives.mjs`）は別の処理で、今回のパッチの外
