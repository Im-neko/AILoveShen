# 75. 畑の柵と整地

2026-10-01。状態: 実装済み、実機では未確認（ブリッジの再起動が要る）。

## 1. きっかけ

user（2026-10-01）: 「畑は柵で囲ったり高さを揃えたりするのも設計にいれてほしいです。」

それまでの畑（設計書 33、47 §7、§17）は、同じ高さ（±1）に耕せる地面が多く並ぶ四角を選び、水のマスを足すだけだった。高さは選ぶだけで揃えず、柵はなく、獣や人の出入りは自由だった。

## 2. 設計（`facilities.mjs` の `registerFacility` → `farmLayout` / `fenceRing`）

- 高さ: 作物と水のマスの地面の高さを、いちばん多い高さ（`layout.y`）にそろえる。四角（`layout.rect` = `{x0, z0, w, d}`）の外れていた列は、整地で揃える
- 柵の輪: 四角の 1 マス外側（`layout.fence`、高さは地面の上 `y + 1`）。1 か所をゲート（`layout.gate`、角でなく、家に近い辺。開いている所を優先。`out` は輪から外へ向かう向き）にする。輪が家・建物・ほかの施設の範囲にかかれば、設計を断る（`FacilityError`: 「柵の輪に 1 マスの空きが要る」）
- 施設の範囲（`box`）に、柵とゲートも入る（ほかの自動の作業が避ける）
- 保存済みの旧い畑（`rect` も `fence` もない）は、これまでどおり（柵も整地も要らない）

## 3. 済みの判定と進め方

- `layoutStatus` に `fence`（まだ立てていない柵のセル）と `gate`（まだなら、そのセル）。柵・壁・柵のゲートが立っているか、固いブロック（木、石、崖）で塞がっていれば、その輪のセルは済み。ゲートは柵のゲートが立って済み
- `farmLevel`（`leveling.mjs`）: 四角と輪の列を、`levelColumns`（円の整地と同じ `columnWork`）で数える。耕地、作物、水、木、柵などは触らず数えない。出っ張り（掘る）と穴（土で埋める）が残りの列
- 畑が済み = 作物・水・柵・ゲートがそろい、整地が済んでいる（`goals.mjs` `facility`）。`updateStatus` の `done` は作物・水・柵まで
- 手の順: 整地が先（それだけを手にする。そろう前に耕すと掘り返される。耕す `workCell` も断る）。道具がなければ作り、穴を埋める土がなければ集める。そのあと、水・まく・耕す、柵（持っていれば立てる。なければ `oak_fence` を作る手をソルバーが出す。まとめて 3 本できる）、ゲート（`oak_fence_gate`）
- 候補（`candidates.mjs`）と行動: `level`（`facility` 付き。`primitives.mjs` の `level` が畑の列で動く）、`fence`（近い順に、持っている柵が尽きるまで立てる）、`fence_gate`（輪の外に立ち、ゲートに向かって置く: 向きは置くときに向いている向きで決まる）。道具モードでは `do_suggestion` で動かす（abilities.yaml の `make_farm`）

## 4. 弱いところ（分かっていて入れた）

- 実機では確かめていない: ゲートの向きが輪と合うか、柵のゲートを通って畑に入れるか（`teachDoors` が柵のゲートを通すのは、ゲートの向きに沿った直進だけ）
- 柵は多い: 16 x 16 の畑の輪は 68 本ほど（板 100 枚以上）。柵は 1 回の `craft` で 3 本。畑の大きさは設計で決まる（LLM に任せている）ので、小さい畑から作る方が早い
- 整地は掘る・埋めるので、時間がかかる。段差が大きい（崖、深い穴: `DY` 8 を超える）列は触らず、輪の外れた所は済みと数える
- 植林場の柵、動物の囲い（pen）は別（設計書 47 の予定）
