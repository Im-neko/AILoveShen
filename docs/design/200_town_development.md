# 設計書 200: 街の発展を最終目標の向きにする

## 1. きっかけ

ユーザー（2026-10-19）:「最終目標の例に街の発展も欲しいな。綺麗に道を舗装して建物を大きくしたり、デザイン性を高めたりというのが考えられますがどうですか？あとはいろんな建築をデザインしてやってみるというのとか」。

次の最終目標を書かせるプロンプト（設計書 180、`MISSION_TEMPLATE`）は「街づくりの続きにせず」と言っていて、街の発展は選べなかった。設計書 180 には、街が完成したあとに蔵を `storehouse_4` から `_13` まで 10 棟並べた空回りの記録がある。「発展」を「建物を増やす」と書くと同じ空回りに戻る。

## 2. 決めたこと

1. **最終目標の向きを二つにする**: ①冒険と資源（探索、装備、掘る、新しい施設） ②街の発展。達成した最終目標を見て、直前が①なら②、②なら①を選ぶのを基本にする（プロンプトの決まり）
2. **街の発展の軸**（プロンプトに例として出す。LLM が段に混ぜる）:
   - 道: 街の道を全部敷く（新しい述語 `paved`）→ 街灯（`lit`、`placed` の松明）で夜も歩ける道にする
   - 建物を大きくする: 家や倉庫の増築（`built(増築の名前)`）。前より大きく、2 階建てなど
   - いろいろな建築: 種類の違う建物を 1 段に 1 つずつ設計して建てる（`built(新しい名前)`）。番号だけ違う同じ建物は、種類が違うと言わない
   - デザイン: 窓、屋根、庭、池、並木など。述語で書けない成り立ちは `custom(名前)`（判定コードは LLM が書く。設計書 199 §5）
3. **空回りを防ぐ検査**（`TownPlanner._next_mission`）: keep でない段の条件がもう全部満たされている（すでにある建物を条件にしている）答えは、理由をつけて差し戻す（`_step_met`）。持ち続ける段（武器、防具）は満たしていてよい。まだ判定のない `custom` や、これから作る施設の段は、確かめずに通す。プロンプトにも「keep でない段は、まだ満たしていないこと」を書いた
4. **述語 `paved`（引数なし）**: 街の理想図の道（設計書 167）が、すべて土の道になっている。ブリッジ（`goals.mjs`）は `roadStatus` で、敷く所（todo）が 0 で、見えない所もなく、道が 1 マス以上あるとき達成。道の計画がないときは `NotYetError`（目標にはできず、条件としては未達）。シャベルがなければ `stone_shovel` を作るところから（ソルバー）。敷く手は設計書 167 §4 の `pave`（候補 `lay the dirt path of the town's roads`）のまま。Python の `GoalPredicate.PAVED` は家があるとき小目標に選べ、`CONDITION_PREDICATES` に入る（大目標・定石・街の段階の条件にできる）

## 3. 作っていないもの・弱いところ

- 舗装は土の道だけ（`dirt_path`）。石やレンガで敷く、道幅を広げる、はまだない。「綺麗に」舗装するには、道の材料を選べる手と、その材料で判定する述語の拡張が要る
- 「建物を大きくする」の「前より大きい」は、プロンプトの案内だけ。大きさの比較は検査していない（`built` は設計した建物がすべて置かれたかだけ）
- 「種類が違う建築」は、名前の重なりを機械で見ていない（`tower_2` で抜けうる）。段が既に満たされている検査と、LLM の自己申告だけ
- デザインの出来（きれいさ）は判定しない。`custom` の判定コードで書ける成り立ち（窓がある、屋根がある）だけ。見た目の採点は、配信画面を見せて LLM に採点させる案（`ScreenReviewer`、設計書 23）があるが、達成条件には入れていない（辛さ次第で次に進めなくなる）
- 今の最終目標（鉄の防具とダイヤのつるはし）は、この変更の前に決まっている。次の最終目標から効く
