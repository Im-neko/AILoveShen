# 171. 坑道の壁の鉱石を掘れない・床の穴のセルへ歩けない（一晩の鉄集めの停滞）

## 1. 事実（`logs/goal_ends`、`logs/bridge.log`、`data/state.json`、bridge の HTTP `/tool inspect`）
- 再起動（2026-10-11 23:56 JST）から朝までの小目標 182 個のうち、`have(raw_iron)` が約 85 回・約 454 分（約 85%）。「8 手進まず停滞」約 45 回、「Jev が見て考え直し」約 17 回。一度も取れなかった
- 見かけは「成功」の繰り返し: 「坑道 mine_2 の底（y16）へ下りる」（約 55 秒）→「`123,33,-275` の鉄鉱石へ行って掘る」（約 60 秒）を交互に約 50 回。着くだけで掘れない
- 掘れない理由 1: 鉄鉱石 `123,33,-275` は坑道（`124,32,-275`）から 1〜2 m で手が届くのに、`dig` が `Took to long to decide path to goal!`（経路探しの時間切れ）で失敗した。`dig` は「立つ場所への経路がなくても手が届けば、その場で掘る」（設計書 163 続き、2026-10-11）を持つが、その判定 `isNoPath` は `No path` だけを見て、時間切れ（`Took to long`）を見ていなかった。壁に埋まった鉱石は、見える面に立てる場所がなく、`GoalLookAtBlock` の探索が空回りして時間切れになる
- 掘れない理由 2: mine_1（121/281）が `dig the mine mine_1` で `124,32,-271`（1 m 先）への時間切れを 22 回繰り返した。坑道 `x=124, z=-270〜-276` の床（y31）に穴があり（`-270` は空気、`-271` は松明）、`dig_mine` が前のセルを `GoalBlock` で立つ場所にしたため。床が抜けたセルは立つと落ちるので、pathfinder には「立てる場所」ではなく、探索が時間切れになる
- 床の穴は塞げなかった: `openings`（塞ぐ面）は松明を「空き」と数えるが、`placeSeal` は松明の上に置こうとして失敗する
- 設計書 68 §6 / 86 の定石どおり、鉱石は採掘場の壁に出たものを取る。採掘場は固定の設計（幹 32、枝 10 を 3 マスおき）で、`mine_2` は水（`106,16,-242`）で幹が 16 に切れて `done`、鉄は壁に出ず、`exhausted` の印は付く手前で止まっていた

## 2. 変更
- `move.mjs` `isPathTimeout`、`primitives.mjs` `dig`: 立つ場所への経路が `No path` でも時間切れでも、手が届く（`bot.canDigBlock`）なら、その場で掘る
- `sealing.mjs` `floorSolid` / `mendStand`、`primitives.mjs` `dig_mine`: 次のセルへ立つ前のセルの床が抜けていたら、床の固い前のセルまで戻って、近い順に丸石で埋めてから立つ。埋められなければ、床の固いほかの隣のセルを使う
- `sealing.mjs` `placeSeal`: 置く場所に松明など当たり判定のないブロックがあれば、先に壊す
- `primitives.mjs`: 設計書 167 の変更（2da8c8a）で、`pave` から `clear_former_home` までの約 570 行が重なって入っていた（後のものが先のものを上書きする）。古い方（`clear_former_home` が `clearGround` を使わない版）を消した。`test/primitives-unique.test.mjs` が、同じ名前の手が 2 回書かれたら失敗する
- 実機: ブリッジの再起動の 3.5 分後に、`dig(123,33,-275)` と `dig(123,33,-276)` が成功し、鉄のインゴット 2 個 → 鉄の剣ができて、目的「鉄の道具をそろえる」が済んだ（01:31 JST）。mine_1 の床の穴は、まだ歩いていないので未確認

## 3. 作っていないもの（user の判断待ち）
- ブランチマイニングを「上限なしに必要なだけ延ばす」: 今は固定の設計図を掘り切ると `done`（幹の端・枝の端は延びない）。鉄が壁に出ないまま `done` になった採掘場は `exhausted` になり、別の入口に新しい採掘場を作る。延ばす形にするなら、`done` の採掘場の幹と枝の列を、鉄の高さで、危ない・丸石不足でない限り足す（「必要」は壁に鉄が見えるまで／必要な個数が取れるまで、のどちらか）
- 空洞（洞窟）は丸石で床・壁・天井を作って突っ切る、という想定は実装済み（`sealing.mjs`）。枝を切るのは、水・溶岩など丸石で安全にならないとき、丸石が足りないとき、面に置けないときだけ
- 底に着いて鉄が見えないとき `make_mine`（別の入口に新しい採掘場）が候補に出ない理由は、読み切れていない（`minePlan` を実際の `data/state.json` で動かすと、底では `{make:16, exhausted:'mine_2'}` を返す。候補の並びで落ちているのか、LLM に見せる 3 件に入らないのかは未確認）
