# 193. 判断なしのプレイの失敗の記録を読めるようにする

2026-10-18。raw の実験（設計書 191）の 2 回目（14:17〜）で、作業台を置く技が 8 回使われて成功 0 回、4 分以上止まった。原因は LLM の限界ではなく、
フィードバックの穴だった（ユーザー: 「修正にはフィードバックが必要」）。

## 見つけた穴
1. 成功の条件が書けない: 置いた物は持ち物から消える。LLM は `have crafting_table count 0` と書き、ブリッジの検査に
   「count must be 1-256」と断られ、技が動いても毎回「判定できない」で失敗に見えた。
2. 置けなかった原因が記録に出ない: 「サーバーが置くのを断った。そのブロックはまだ空気」だけで、立っていた所・向き・手の物・
   足元とまわりが分からず、置き方を 5 通り書き直しても原因に届かなかった。

## 入れたもの（世界の事実だけ。判断は足さない）
- `expects block_near { block, distance? }`（distance は 5、最大 32）: そのブロックが近くにあれば成功。名前は走らせる前に確かめる
  （知らない名前は動かさず断る）。raw では 5 つ目の条件。`bot.findBlock` で探すだけ。
- `have` / `stored` の count が 0 以下の数なら、書くときに断る。理由に block_near を案内する（走らせたあとで判定できないと分かる、より前）。
- 失敗した生の bot の技（`raw: true`）の結果に `scene`（`src/scene.mjs`）: 位置、向き（yaw / pitch）、地面に立っているか、スニーク、
  手の物、足元・足・頭・頭の上・東西南北の足元のブロック、視線の先のブロック、3 m 以内のもの。Python の `SkillRun.describe()` が
  「scene when it ended: {...}」として次の選択と技の書き直しに見せる。
- 技を書くシステム指示（raw）に、5 つの条件と、現場の読み方を足した。

## 残している判断（実験の結果に書く）
ブリッジの「同じ理由で 5 回失敗した版は 10 分動かさない」（設計書 168）は raw でも働く。ブリッジの規則なので、「判断 0」とずれる。
今回は外さず、結果を読むときにこれが働いた回数を数える。

## 確認
ブリッジ 1114、Python 1920 通過。実機（ベンチ）は 14:4x に再開する。
