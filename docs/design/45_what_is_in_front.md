# 設計書 45: 目の前にあるものを毎回見せる、見直しで効率化を確かめる

> 語彙は 50（目標の 4 層）で入れ替わった: 旧「大目標」= 最終目標（`Mission`）、旧「中目標」= 大目標（`Objective`。旧 `MidGoal`）、旧「手順」（`plan_steps`）= 中目標（`Job`。旧 `PlannedStep`）。この文書の本文は書いた時の語彙のまま。

状態: 実装（2026-09-27）

## 1. きっかけ

ユーザー（2026-09-27）:「常に自分の周囲何マスかのブロックとアイテムの情報を常に LLM に渡せると良い。眼の前にあるのに無視するケースが結構あった。高さは自分と同じかそれより ±2 マスくらいまで」「積極的に効率化を考えるようにしてほしい」。

今まで LLM に見えていたもの:
- `nearby`（目印: ベッド、ドア、作業台、かまど、チェスト、松明。24 m）
- `memory.places`（覚えた場所。**今は見えていない**ものだけ）
- ソルバーの候補（道具モードではソルバーの提案。目標に要るものだけ）
- `/state` の `surroundings`（道具のプロンプトの 7x7 の高さの格子。ブロックの名前はない）
- `/observe` の `mobs` と `drops` はブリッジが出していたが、Python の表示（`stream_context`）には出ていなかった

そのため、目の前の原木・作物・石・落ちている苗木は、どこにも名前が出ていなかった。

## 2. 目の前（`/observe` の `around`）

ブリッジ `src/around.mjs` の `aroundMe(bot, dropsOf)`:
- 範囲: 足元のマスから水平の半径 8（円）、高さは足元の高さ ±2（`AROUND_RADIUS`、`AROUND_DY`）
- ブロック: 空気でなく、空気に面している（`world.mjs` の `exposed`: 埋まった鉱石は見えないので出さない）もの。種類ごとに数、一番近いもの（座標、距離、方角、高さの差）、取れる物（`Knowledge.dropsOf`。同じ名前だけなら出さない）、作物なら熟した数。一番近いものが近い順に 24 種類まで
- 落ちているアイテム: 同じ範囲（高さの差 ±2）の item エンティティを名前ごとに、数（スタックの数の合計）と一番近いものの距離・方角
- 観測ごとに作る（17x17x5 のマスを読む。1 マスにつき周りの 6 マスも読む）

Python `stream_context._format_around`: 「近くにあるもの」の次に 2 行。
- `- 目の前のブロック（半径 8m、足元の高さ ±2、見えているもの）: wheat 6（熟した 2、→ wheat・wheat_seeds、一番近いもの 1,70,2 南 2.1m、高さ +0）、…`
- `- 目の前に落ちている物: oak_sapling 3（西 2.0m）`

`activity()` の状況に入るので、目標の決定、道具の選択、実況、返答のどれにも出る。道具の決まりに「目の前にあるなら遠くへ探しに行く前に使う（座標はそのまま dig などに使える）」を足した。

## 3. 見直しで効率化を確かめる

目標の決定の見直し（設計書 31）の例を「毎回確かめる」一覧にして、次を足した:
- 目の前にある材料と落ちている物を先に使う
- 何度も要る物・近くで見つからない物は増やす仕組みを作る（木は苗木、食べ物は畑を作って広げる: `farmed` の数を上げる）
- 待つ時間（作物が育つ間、夜、家の中）は、そばでできること（畑を広げる、クラフト、置く、しまう）に使う

システム指示の長さの上限（`TestPromptLength`、8000 字）に収めるため、ほかの所で重なっていた文を削った（「数分で終わる大きさ」は中目標と小目標の説明と重なる、夜の家の中の文を短く）。

## 4. やらないこと・残ること

- 高さ ±2 の外（木の上の方の原木、崖の下）は出さない。ユーザーの指定どおり
- 24 種類を超えると遠いものから落ちる。種類が多いと、1 回のプロンプトで 1000〜1500 字ほど増える
- 実機では試していない（ブリッジの再起動が要る）
