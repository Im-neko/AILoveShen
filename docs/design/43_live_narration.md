# 設計書 43: 行動の途中の一言

## 1. きっかけ

ユーザー（2026-09-27）:「ローカル LLM 使う時は頻繁に考えてること、やろうとしていることを喋るようにしたい」→「10 秒間隔くらい。同じ内容の繰り返しにはならないように」。

原因: 実況は小目標の切れ目（`GoalSetEvent`）と見どころでしか話さない。`max_silence_seconds`（60）も切れ目で見るだけで、タイマーではない。時間で止めない行動（設計書 38: 歩く、漕ぐ、焼くのを待つ）の間は何分も黙っていた。道具の `intent` は配信者の口調の 1 文なのに、目標ボードに出すだけで読んでいなかった。

## 2. 話すとき

`LiveNarration`（`presentation/services/live_narration.py`、配信の裏のタスク、1 秒ごとに見る）:
- 黙っている時間は**読み上げが終わってから**測る（`TTSService.is_idle()`: キューが空で、合成も再生もしていない。割り込みも数える）。TTS がなければ最後に話した時刻から
- `stream.live_interval_seconds`（10）黙っていたら 1 行:
  - 道具に添えた日本語の `intent` が前と違えば、それをそのまま読む（LLM を呼ばない）。Jev の手の intent は候補の英語の id なので読まない
  - そうでなければ一言を作らせる（`generate_commentary(purpose="live", record=False)`、実況と同じシステム指示）。渡すもの: 今の行動、直近 3 つの行動の結果（`GameActionExecutedEvent`）、前の一言からの持ち物の増減と動いた距離、直前に話した 4 行と「同じ内容・言い換えは言わない」「短い 1 文、40 字くらい」「次の段取りは今していることの目標と手順から（ない予定を作らない）」
- プレイしていない（小目標がない）間は話さない
- 作っている間にほかの発話（返事、切れ目の実況）が始まったら、その行は捨てる（古くなる）
- 話しても捨てても、次はもう 1 間隔待つ（捨てた直後に作り直さない）

## 3. 繰り返さない

実況の読み上げ（`factories/stream.py` の `say`: 切れ目の実況も一言も）は、直前の 8 行（返事も含む: `SpokenLines`）と文字の 2-gram の Jaccard が 0.5 以上なら読まない（ログ `[say] 直前と同じ内容なので言わない`）。Narrator と一言が同時に作っても 2 行目は読まれない。言い換え（「木を切るね」と「原木を集めるよ」）は文字では捕まらないので、プロンプトに直前の行と変わったことを渡して防ぐ。

一言は会話の履歴に残さない（10 秒ごとの行が、返事の文脈から視聴者のコメントを押し出す）。

## 4. 費用と負荷

- 用途は `live`（`gemini.thinking_levels.live: low`、`llm.routes` で振り分けられる、`tools/gemini_usage.py` で別に数えられる）
- ローカルの LLM は同時 2 本（`llm.local.max_concurrent`、セマフォ）。一言は常に 1 本だけ（tick は生成を待つ）なので、1 枠を最大で「生成の秒数 / (10 秒 + 読み上げ)」だけ使う。道具の判断（6〜8 秒）が待たされるかは、入れた後に `1 手` の秒数をログで比べる（まだ測っていない）
- ローカルの LLM がなければ Gemini で 1 時間に最大 360 回

## 5. 実測（2026-09-27、本物の Gemini、偽の時計で 60 秒の 1 つの行動）

10 秒: intent をそのまま → 20〜60 秒: 「森の近くまでやってきたよ…」「まずは四つゲットできたよ…」「これで六個集まったよ、目標の十六個まで…」「木こりって無心になれて結構楽しいよね…」。繰り返しはなく、1 回 1〜2 秒。最初の指示では、状態にない予定（木のオノ、羊毛）を話し、2 文になることがあったので、予定は目標と手順から・40 字くらいを足した。

## 追記（2026-09-28）: 行動を実行している間だけ話す

目標の決定（ローカルの LLM で約 4 分）を待つ間、一言は終わった行動の結果（小麦は食べられないと断られた）から「作業台でパンにして空腹を満たすね」を作り、4 回話した（ほかにも似た行を 10 回ほど作って捨てた）。行動はまだ選ばれていなかった。また、断られた・終わった行動の intent が残り、10 秒後に「家の中に入るね」と読んでいた。

- `PlaySession.start_action(intent)` / `end_action()` と `Activity.acting`: 行動を実行している間だけ真。終わったら intent も消す
- 一言は `acting` の間だけ話す。次の行動や目標を選んでいる間は話さない（小目標の切れ目の実況は `Narrator` がする）

## 追記（2026-09-29）: 状況が変わったときだけ、行き詰まっている間は黙る

ユーザー:「実況は頻度を下げていい。小目標が変わったときや状況が変わったときだけでいい。スタックして動けていないときにずっと似た発言をするのはやめて、ちゃんと考えて違う方法を検討してほしい」。
- 一言は、黙っている間隔（`live_interval_seconds`、10 → 30）に加え、前の一言から状況が変わっていたときだけ（持ち物、位置 10m、体力 3 以上、時間帯、家の出入り。最初は今を基準にするだけ）。変わらなければ何秒でも黙る
- `Activity.failing`（続けて失敗した行動の数）が 2 以上の間は話さない。代わりに道具の選択が `tool_stuck`（考える）になり、別の方法を選ばせる（設計書 51 §3）
- `max_silence_seconds` 60 → 180（切れ目の実況が黙り続けないための上限）

## 追記（2026-09-30）: 考え始めたときの定型の一言

ユーザー:「思考に入る時、定型文でいいので『今からちょっと次どうするか考えるね』とか喋らせてほしい」。目標の決定と大目標の計画書きは LLM に何十秒〜何分もかかり（ローカルで 39 秒〜4 分）、その間は行動がなく（`acting` が偽）、切れ目の実況もまだなので、完全に無音だった。
- `PlaySession` ではなく `AdvancePlayUseCase._while_deciding`（LLM の決定を待つ 2 か所、`_decide_goal` と `_plan_objective` だけが通る）が、待つ前に `GoalDecidingEvent(after_failure)` を発行する。Jev が選ぶ小目標（1 秒未満）は通らないので、言うのは LLM が考えるときだけ。`after_failure` は、行き詰まり・停滞・考え直し・死亡・大目標が進まない（`REPLAN_REASONS`）のあと
- `Narrator.on_goal_deciding` が定型文を順に言う（`THINKING_NOTICES` 3 つ、失敗の後は `RETHINKING_NOTICES` 2 つ）。LLM は呼ばない。イベントの発行はハンドラーを待つので、背景で言う（決定の開始を遅らせない）。90 秒以内に続けては言わない（計画を書いてから目標を決めるときの 2 回目）
- 出し先は `factories/stream.py` の `say_notice`。`say` と違い `SpokenLines.repeats`（直前 8 行と似ていれば捨てる）を通さない: 定型文は同じ内容なので、通すと 2 回目から必ず捨てられる。言った文は `SpokenLines` に覚えさせる（実況の一言が同じことを言わないため）。会話の履歴には残さない（目標の決定が直近の実況として読み、定型の一言が文脈を汚すため）
- 文言は定数（リリース前なので設定項目は足していない）。読み上げの優先度は実況と同じ（20 秒待つと捨てる）: 考え始めた瞬間に出ることに意味があるので、詰まっていれば出ないほうがよい
- 未確認: 実機（配信を再起動して、目標の決定が始まったときに声が出るか。avatar は TTS の再生で口が動く）

## 追加（2026-09-30）: 待っている間の独り言

直近 30 分のログで、発話の空白が最大 270 秒あった。目標の決定・計画・行き詰まり（`tool_stuck`）の間は、`Activity.acting` が偽か、`failing ≥ 2` で、`LiveNarration` は何も言わなかった（選ばれていない行動を言わないための決まり）。

- 待ちが `stream.live_thinking_seconds`（40）続いて、その間ずっと黙っていたら、考え中の独り言を 1 行（purpose=live、会話の履歴には残さない）。渡すのは今の小目標と状態だけで、「体は止まっている。何かを始めた・やっていると言わない。新しく約束しない」と書く。行動の intent は渡さない
- 待ちが続いている起点を覚える（`_waiting_since`）。行動と行動の間の数秒の選び直しでは話さない（行動中に戻ると起点が消える）
- 直前の数行と似ていれば捨てる（`_duplicate_of_recent`）。話した／捨てたあとは、また `live_thinking_seconds` 待つ
- 0 なら話さない（従来どおり）。未確認: 実機。独り言が長い待ちで単調にならないか

## 追記（2026-09-30）: オーバーレイの「考え中」

- LLM が次の小目標か大目標の計画を考える間（数十秒から数分）は行動も声もなく、オーバーレイは前の小目標のままだった。`GoalDecidingEvent` には終わりがなかったので、`GoalDecidedEvent` を足し、`AdvancePlayUseCase._while_deciding` が `finally` で必ず発行する（決定が失敗・取り消しでも「考え中」が残らない）。
- `GoalBoard` は 2 つのイベントで `thinking: {after_failure} | None` を持ち、`/api/goals` と SSE のスナップショットに載せる。`/overlay/vtuber` は小目標の吹き出しに「🤔 つぎにやることを考え中 ●●●」（失敗の後は「うまくいかなかったから考え直し中」）の跳ねる点つきの帯を出し、`/overlay` は小目標の行に「💭 考え中…」を足す。Jev が選ぶ小目標（1 秒未満）は通らないので出ない。
- 対象は目標の決定と計画の作成だけ（ステップごとの道具の選択・返答の生成は数秒なので出さない）。実機では未確認（Python の再起動が要る）。
