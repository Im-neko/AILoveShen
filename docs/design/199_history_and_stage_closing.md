## 2. 履歴（`Deed`）

- `Deed(title, done, because, day, requested_by)`: 終わった大目標 1 件の記録。完了か断念か、終わった理由、終わったときのゲームの日、視聴者の頼みだったか
- `ObjectivePlan._history`: `_finish`（完了・断念の両方）で足す。`HISTORY_KEPT`（200 件）を超えたら古いものから消す。日は `PlaySession.observe` が `plan.note_day(obs.day)` で知らせる（観測がまだなければ None）
- 保存: `data/mission.json` の `history`（`JsonMissionStore`）。`history` のない古いファイルは空で読む。ワールドを作り直すと `mission.json` ごと退避されるので、`reset_world.sh` に足すものはない（履歴は「このワールドで自分がやったこと」）
- 見せる: 目標の決定（`with_ids`）の「今していること」の最後に「自分がやったこと」として、直近 `HISTORY_SHOWN`（30）件を古い順に、日・題名・頼んだ人・完了／断念の理由で出す。実況・返答・1 手の選択（`step`）には出さない。目標の階層の側（キャッシュの境目の前）にあり、大目標が終わるたびにだけ変わる
- 盤面: `/api/goals` の `history` に全件
- 記録を持つだけで、判断はしない: 「また足さない」は LLM への文面（「済んだことをまた大目標に足さない」）。畑や植林場が今もあるかは、世界（施設の記憶、状況）が決める
- この日（2026-10-19 17:00 以降）のログの `[objective✓]` `[objective×]` から 16 件を `mission.json` に写した（日は不明）

## 3. 街の段階が閉じなかった問題（原因と直し）

段階 4「家のそばに小麦の畑を作る」は、条件 `facility(wheat_farm)` が満たされたのに終わらなかった。

1. 未解決の `farmed(wheat, 9)`（畑がなかったときに「まだ手に入らない」と書いた文）は、書き直しが「語彙の版が変わったときだけ」（`vocabulary_version()`）だったので、畑ができても再評価されなかった。`TownPlanner._version()` に、完成した施設の名前と、段階の条件が全部そろったかを足した（施設が増えたときと、条件がそろったときに一度ずつ書き直す）
2. 書き直させても、`_already_done` が「未解決に書いてあった条件が今そろった」ことを言い換えとして 3 回差し戻した。未解決の文に書いてある条件そのものは、解決として通す
3. 通すと、LLM が元になかった未解決（「食料が減らないことを判定する条件がない」）を足した。書き直しの指示に「上に書いていないことを足さない」を入れ、`_added_unresolved` が、元の未解決より多く残す書き直しを差し戻す

この間、段階が閉じないので大目標が空になり、同じ畑の大目標を足し続けた。

## 4. 理想図を描けないと配信が始まらない問題

段階 5 に進んだ理想図の描き直し（`town_plan`、thinking high）が、LiteLLM の出力上限 `llm.litellm.max_output_tokens`（8192、思考を含む）で毎回「答えなしで切れ」、`TownPlanner.prepare` の例外で `play` を始められないまま約 10 分待った（再起動した 18:34〜18:44）。

- 上限を 16384（ローカルと同じ）に上げた。次の描き直しは 7899 トークンで描けた
- 理想図は進めるための地図で、描けなくても止めない: `_keep_map` は `TextGenerationError` を警告にして前の図のまま続け、`MAP_RETRY_SECONDS`（300 秒）たってから描き直す

## 5. 最後の段階が閉じなかった問題（述語で書けない部分）

最後の段階「植林場と倉庫」は、条件が全部そろっても、未解決「畑や家を柵で囲むこと」が残り、段階が終わらなかった（街が完成せず、大目標が空のまま差し戻しが続いた）。

- 経緯: ブリッジが世界から判定するのは速くて安いからで、原則ではない。述語や `custom(名前)`（JS、50ms、読むだけ）で書けない判定には限界がある。ユーザー（2026-10-19）は、そこを LLM に任せる案を出した（ブロックの配置を Jev / LLM に渡して判定させる、何を渡すかも LLM に決めさせる、判定コードを LLM が動的に書く `custom`）。この向きで考える
- 述語で書けなくても、ブロックや生き物を読めば分かるもの（囲い、並び、数）は、`custom(名前)` を段階の条件に書けるようにした。判定コードは、段階が大目標になるときに `ObjectiveKeeper._write_stage_checks` が `CheckWriter` で書かせる（この経路はもとからあった）。書かれる前の `custom` が保存できなかった（`bridge.check` が拒否し、`_settle` が書き損じとして捨てた）ので、`TownPlanner._unwritten` で、まだ判定がない `custom` は確かめずに通す。街の定義と段階の書き直しのプロンプトに、`custom` で書くことを案内した
- ところが、この段階の柵は余計な部分だった: 段階の題名と意味（why）に柵はなく、畑の柵は畑の施設が自分で置く（facility が済めば柵もある）。街の定義のプロンプトが「柵、道などは unresolved に書く」と案内していたせいで、定義のときに混ざった。書き直しのプロンプトに「題名と意味にない部分は外す」を足したところ、未解決が外れて段階が閉じ、街が完成して、次の最終目標（鉄の防具をそろえ、ダイヤのつるはしを作る）が決まった（実機、2026-10-19 19:1x）
- 弱いモデル（haiku-5-5）は、`custom` で書く案内だけでは、元の未解決をそのまま写した（「柵は建物に使えず、判定も実行もできない」）。本当に `custom` が要る部分で LLM が書くかは、まだ実機で確かめていない
