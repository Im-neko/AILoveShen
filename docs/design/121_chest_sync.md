# 121. 家にあるチェストを記録と合わせる

2026-10-08、user: 「別件でチェスト増やしたのに全然使ってなさそうなのなんとかしたいです」

## 1. 起きていたこと
家には単独のチェストが 5 つある（(43,-202)、(43,-201)、(43,-200)、(45,-201)、(45,-200)。向きがそれぞれ違うのでラージにならない）。ブリッジが覚えているのは (43,-202) の 1 つだけで、27/27 の満杯。預ける手は毎回その満杯のチェストを開けて「いっぱい」と失敗し（05:07〜05:14Z だけで 8 回）、ほかの 4 つ（空き 108 スロット）は使われなかった。

## 2. 原因
チェストが記録されるのは、(1) `place_chest`（「家にチェストを置く」候補の手）で置いたとき、(2) 開けたときだけ（`withOpenChest`）。LLM が `place` の道具で置いた 4 つ（設計書 116・118 で隣に置き直した分）は、どちらにも当たらず、記録に載らなかった。載らないので開けられず、開けられないので載らない。

副作用: 観測の `chest_free`（満杯の判断、設計書 116 の「増設を強制」）は記録から出すので、空きが 0 のまま。`chest_blocks`（家のチェストのブロック数）は世界から数えるので 5 を示していた。増設しても記録が増えず、また増設に回る。

## 3. 直し方（`minecraft-bridge/src/storage.mjs`）
- `syncHomeChests`: 家（`homeChests` と同じ範囲）のマスを見て、チェストのブロックで記録にないものを空として覚え（中身 `{}`、使用 0、サイズ 27。ラージは左の半分に 54）、チェストでなくなったマスの記録を消す。右の半分の記録は消す（二重に数えない）。読み込まれていないマスは触らない。開いたときに本当の中身に直る（`withOpenChest`）。
- 呼ぶのは、判断の前（`decisionView`）と観測の家の項目（`chestFacts`）。どの置き方でも、どの経路でも合う。
- `roomyChests`: 預け先を、空きのあるチェストが先、その中でボットに近い順に。`deposit`（`toChest`）、`tidy`、`stash` の最初に開けるチェストに使う（満杯の記録のチェストを毎回先に開けない）。あふれた分は、これまでどおり `putInChests` が次のチェストへ回す。
- `chestRecordPos` は `primitives.mjs` から `storage.mjs` へ移した（同じもの）。

## 4. 代償・未対応
- 覚えるときは「空」と置くので、前から入っていた物のあるチェストは、開くまで空きがあるように見える（開けて入らなければ次のチェストへ回る）。
- 家の外のチェストは対象外（`homeChests` の範囲の外）。
- 家の置き方で置かれた家具の位置などは変えない（記録だけ）。
