# 120. 同じ理由で失敗し続ける技は動かさない

2026-10-08、user: 「2をまずやってほしいです」（技が同じ理由で失敗し続けても止まらない仕組みの穴を直す）

## 1. 起きていたこと
01:16Z にローカルモデルが書いた畑の技 `till_and_sow_on_farm_v2` が、143 回使われて成功 3、失敗 140。失敗の理由は 140 回とも `expects not met: the small goal's remaining work 41 -> 41` で、約 2 時間半、別の手に変わらなかった。

止まらなかった理由（調べた順に）:
1. 同じ理由の失敗を数える `same_cause_run`（設計書 99 など）は、直近の道具の結果の末尾が連続して同じ理由で失敗しているときだけ数える。この場面は `equip`（成功）→ `run_skill`（失敗）の繰り返しで、間の成功が数えを切っていた。`run_skill` を止めない例外（`NEVER_WITHHELD`）は、原因ではなかった（外しても止まらない）。
2. 技の `verified` は「一番新しい版が 1 回でも成功した」だけで、その後 140 回失敗しても消えなかった。モデルにも、Jev の選択肢（`step_picker` は `verified` の技だけ出す）にも、確認済みの安全な手に見え続けた。
3. 技の一覧の行は「成功 3/143、最後の失敗: …」までは出ていた。連続して失敗している、という情報はなかった。

## 2. 決めたこと（`minecraft-bridge/src/skills.mjs`）
- 版ごとに `streak`（同じ理由の失敗の連続）を数える。成功で 0、違う理由の失敗で 1 に戻る。理由は数字（座標、個数、id）を除いて比べる。数えるのは技ごとで、間にほかの道具が成功しても切れない。
- `streak` が `SKILL_STREAK_LIMIT`(5) に達した版は `failing`。`verified` は「成功したことがあり、かつ今 `failing` でない」。
- `failing` の版は、ブリッジが動かさない（`blockedReason` → `runSkillOnce` が `ended: refused` を返す。数えない）。断りには、書き直す・前に成功した版を動かす・ほかの道具でやる、を書く。前の失敗から `SKILL_PROBE_MS`(10 分) たてば、世界が変わったかもしれないので 1 回だけ試せる（失敗すれば、また止まる）。
- 新しい版（書き直し）は数え直す。
- Python（`SkillInfo`）は `streak` と `failing` を受け取り、一覧の行に「同じ理由で N 回続けて失敗中。書き直すか、ほかの手で」（上限の手前は「同じ理由で N 回続けて失敗」）を出す。`verified` が偽になるので、Jev の選択肢にも出なくなる。
- 動かさなかった断り（`refused`）は、技を直すときに見せる「前の失敗」（`_skill_failures`）に入れない（本当の失敗の理由を残す）。

## 3. 代償・未対応
- 動かさない決まりは、技の外から見える失敗の理由が同じ間だけ。理由の文が毎回変わる失敗（座標がない数字以外の違い）は数え直しになる。
- 上限の 5 回は決め打ち。本当に 5 回では足りない技は、10 分後の 1 回で試せる。
- 保存済みの技（`data/skills/*.json`）には `streak` がない。最初の失敗から数え始める（既存の `last_failure` と同じ理由なら、次の失敗から 1、2、…）。
- 技を書き直す力そのもの（モデルが失敗の理由から技を直せるか）は、この変更では上がらない。止めて、考え直させるだけ。
