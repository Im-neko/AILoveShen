# 142. 記憶から、もう持っている施設で大目標を済みにする（satisfy）

2026-10-09、user: 「目標は自動判定に加えて記憶からLLMが完了判定も出来るようにしたい。例えば記憶で畑をもう作っていたらLLMが目標を更新出来るようにしたい。目標の再設定をLLMがするときにこれを走らせたい」

## 1. 決めたこと（user の選択）
- 根拠を付けさせ、ブリッジ（記憶）が確かめる（LLM の言うことだけでは済みにしない）
- 済みにする + 条件の付け替え（施設の条件を、もう持っている別の名前の施設で満たしたとする）
- 目標リスト（大目標の並び）か家が変わったときに走らせる

## 2. なぜ要るか
定石の「食料」の段は `facility(wheat_farm_1)` と名前で判定する。引っ越しや、モデルが付けた別名（`wheat_farm_2`）の畑があっても、名前が違えば畑を作る目標が立ち、畑が増えていく。完了はこれまで世界の判定だけで、LLM は宣言できなかった（設計の原則: 完了はモデルでなく世界から）。

## 3. 作ったもの
- **`satisfy` 操作**（大目標リストの編集 `plan_changes` の 4 つ目。`add` / `move` / `drop` / `satisfy`）: `{op: satisfy, id: <大目標>, by: <施設名>, reason}`
- **確かめ**（`facility_satisfy.py` `check_satisfy`、`ObjectiveKeeper._check_satisfy`。決定を通す前の `check_new`）。合わなければ理由を付けて決定ごと差し戻す（今までの編集の差し戻しと同じ）:
  - その大目標が施設の条件を持つ（施設のない大目標には使えない）
  - 施設以外の条件（`have(wheat, 3)` など）はブリッジの判定で満たしている
  - 満たしていない施設の条件は 1 つだけ（`by` は 1 つ）
  - `by` は登録された施設で、家ではなく、求められた施設と同じ種類（畑は同じ作物）、完成（`status: done`）、家の中心から 64 m 以内（`SATISFY_NEAR_HOME_M`。定石の施設の段を家のそばに置く `PLAYBOOK_NEAR_HOME_M` と同じ値）
- **済みにする**: `ObjectivePlan.complete(id, "already served by the facility <by>")`。定石の段なら `playbook_done` に入り、戻らない。配信には完了として伝わる
- **走らせるとき**: 目標の決定のプロンプトに「作った施設」の節（名前、種類、完成か作業中か、家からの距離と家の近くか）を出す。大目標に施設の条件があり、大目標の並びか家の場所が前に見せたときから変わったときだけ（`AdvancePlayUseCase._facility_memory`）。決定が通ったときに「見せた」印を更新するので、差し戻しの再試行では出続ける。失敗診断の再設定（`goal_after_failure`）も同じプロンプトなので同じ

## 4. できないこと・見送り
- **遠い施設は代わりにならない**: 今の世界では `wheat_farm_2`（完成）は新しい家から 110 m。64 m を超えるので断られる。`wheat_farm_1`（家から 25 m）は作業中で、作るのをやめない。この変更は「次に近くに畑があるのに、名前が違って作り足す」ことを防ぐもので、今の 3 つ目の畑は防げない
- **施設の条件だけ**: `have` や `built` などの記憶（チェストの中身など）からの完了は作っていない。世界の判定が今まで通り
- **残るもの**: 済みにした大目標が設計した施設（今回なら `wheat_farm_1`）は登録されたまま残る
- **条件の付け替え**は、完了にする形だけ（残りの条件が満たされているときに限る）。施設の条件だけ書き換えて続ける形（他の条件が未達のまま）は作っていない
- 実機では未確認
