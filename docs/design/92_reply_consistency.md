# 92. 返事の文と判断の食い違い: 判断を先に書かせ、関わる助言を後に回すなら差し戻す

2026-10-07、user: 「ねこかもさん、確かに！木をたくさん集めるなら斧があったほうがずっと楽だよね。今の材料集めが終わったら、次は斧を作ることにするね！っていう 1 行で矛盾するようなこと言ってる。どうしたら LLM に気付いてもらえるか」→「1、2 進めてみて」。

## 1. 起きていたこと

`logs/generations/`（`purpose=reply`、21:17〜21:18）の返答 4 件はどれも `request: accept`、`relevance: related`（理由は「斧は今の原木・板材集めをずっと速くする」）、`when: next`、`position: 2`、`rethink` なし。「今の作業に効く」と判断しながら「今の作業の後」に回し、文は `when=next` の規則（「返答ではリストの位置のとおりに言う」）どおりに「終わったら作るね」と言った。モデルは規則に従っていて、矛盾を判断する場所がなかった。

原因は 2 つ:
1. **スキーマで `reply` が最初のキー**。モデルはキーの順に書くので、扱い（`relevance`、`when`、`position`）を決める前に文を書き終える。文が判断を縛らず、判断が文を見ない。
2. **差し戻しの隙間**。`generate_response.unjudged` は、`related` で `when=next` なら `rethink`（今の小目標の見直し）を求める。ところが `rethink` は荒らし対策で 60 秒に 1 回しか使えず（`_rethink_wait`）、使えない間は `can_rethink=False` で何も検査しなかった。斧の助言は 21:17:04 の「斧作らない？」の直後だった。

## 2. 直したこと

- `reply_schema()`: `reply` を判断の後ろ（`lesson_when` の次、`name_reading` と `self_facts` の前）に移した。`reply` の説明に「判断に合わせる。when=next なら今の作業の後。今の作業に効くと言いながら待つと言わない」を足した。
- `unjudged`: `related` で、引き受け（accept）、`when` が now でなく、`rethink` もなく、`rethink` が使えない間は差し戻す。「今やるなら when=now にして『今やるね』と理由を言う。後でよいなら relevance を partly にして、なぜ後でよいかを返答で言う」。引き受けない返答（教訓だけ、など）は今までどおり通す（`test_no_rethink_is_demanded_while_the_chat_cap_holds`）。
- `rethink` が使えるときの差し戻しは変えていない。`rethink` があれば、今の小目標が決め直されるので食い違いにならない。

## 3. 確かめたこと・確かめていないこと

- テスト: `TestRelatedAdviceIsNotParkedForLater`（5 件）。差し戻しの条件を外す変異と、`reply` を先頭に戻す変異で、それぞれ落ちる。
- **実際の LLM での効果は測れていない。** 記録した斧の助言のプロンプトで、`reply` 先頭と最後の 2 通りを 12 回ずつ流して `related` + 後回しの割合を比べるつもりだったが、ローカルの LLM サーバーが `maintenance failed (restart required)` で 503 を返し続けた（`/private/tmp/.../order_experiment.py`）。サーバーが戻ったら同じ実験をやり直す。順序の変更が決定を変えるか（`partly` や `now` が増えるか）は、それまで分からない。
- ローカルのサーバーは `response_format` を受け付けず（400）、スキーマは強制されていない。キーの順は、サーバーの出力の並び（記録では `reply` が先頭だった）でしか確かめられない。

## 4. 別に見つけたこと（直していない）

- 同じ時間帯の返答のうち 1 件は、完了条件が `have(wooden_pickaxe, 1)` と `have(stick, 2)`（斧ではない）だった。別の 1 件は `request` がオブジェクトの入れ子で出た。どれが最終的に受理されたかは追っていない。受理されていれば、斧を作らなくても中目標が済む。
