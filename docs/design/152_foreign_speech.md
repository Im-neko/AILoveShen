# 152. 外国語を、カタカナ読みで一生懸命喋らせる

2026-10-10、user: 「外国語対応もできるようにしたいです。喋れるのかな？」「カタカナ英語や外国語でも良いから外国語も一生懸命喋ってみてほしい」「実装してください。主要な言語大体対応できるようにしときたい」

## 1. 事実（実測）
- 声のモデル `shen_clean` は JP-Extra で、日本語以外の言語を拒否する（`tts_model.py:411`。言語 EN は 500）。Irodori-TTS も日本語専用
- 言語 JP のままなら、どんな文字列でも音声は出る。ただし英字の文は一文字ずつ読むらしく、`Hello, thank you for watching!` が 5.6 秒（カタカナ `ハロー、サンキュー、フォー、ウォッチング！` は 2.4 秒）。漢字だけの中国語は日本語の音読みになる

## 2. 設計
- 声は変えない。読み上げる直前に、外国語の部分を聞こえるとおりのカタカナにして日本語の声に渡す。画面の字幕・イベントの文は元の文のまま
- `ForeignSpeech`（`application/use_cases/foreign_speech.py`）: `needs_katakana(text)` が、ラテン文字の単語（アクセント付きを含む）、日本語以外の文字種（ハングル、キリル、ギリシャ、アラビア、ヘブライ、タイ、デーバナーガリーなど）、仮名のない句の漢字 3 つ以上の並び（中国語）を見つける。なければ LLM を呼ばずそのまま。あれば用途 `reading` で LLM に書かせる（日本語はそのまま、外国語の部分だけカタカナ、例つき）。同じ文は 64 件まで覚える
- 置く位置: `SpeakTextUseCase` で、名前の読みの置き換え（`pronounce`）のあと、合成の前（`transliterate`）。日本語の文は呼ばない
- 変換できない・遅い（8 秒）・答えが外国語のままなら、元の文のまま読む（黙るより読む）。外国語のままの答えは覚えない
- 用途 `reading` は `llm.routes` で remote（LiteLLM）。小さなローカルモデルは中国語・韓国語などが苦手なため
- 返事の決まり（`REPLY_RULES` の「外国語」）: 視聴者が日本語以外で話しかけたら、その言語で短く返す。名前は日本語のまま。日本語で話しかけられたら日本語。実況・一言は日本語のまま

## 3. 実機で確かめたこと（2026-10-10、LiteLLM + 声のサーバー）
英語・中国語・韓国語・フランス語・スペイン語・ドイツ語・ロシア語・タイ語・ベトナム語・アラビア語、日本語混じり（`good morning everyone`）の 11 文を変換して合成し、すべて音声が出た（2.7〜5.2 秒）。変換の例: `你好，谢谢你来看我直播。` → `ニーハオ、シエシエ ニー ライ カン ウォー ジーボー。`。ベトナム語の `Xin chào` は `ホァシン チャオ` と少しずれた

## 4. 直していないこと
- 発音の正しさ。日本語なまり（カタカナ）の発音になる。変換の誤りは LLM の出来次第（ベトナム語など）
- 英語の文を英語の声で読むこと（多言語の声モデル、設計書にしていない）。声を変えずに正しい発音にするなら、多言語の声に学習し直す
- 実況・一言が外国語になること（日本語のまま）。Twitch のチャットの字幕表示は、元の文のまま
- ラテン文字の単語は 2 文字以上で見つけるので、`OK` のような短い英単語を含む日本語の文も 1 回 LLM を通る（結果はキャッシュ）
- Python の再起動が要る
