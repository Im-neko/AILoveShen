（費用の目安 = 未キャッシュ 1.0、読み 0.1、書き 1.25 のトークン換算の合計。全体で約 5.1M）

- 読まれているのはツール定義 + システム指示（約 2.7K トークン）だけで、本文の約 5.3K トークンは毎回新しく読まれていた
- 原因 1: raw の道具選びの本文（`RAW_TOOL_TEMPLATE`）に境目の印（`CACHE_BREAK`）が 1 つもなかった。先頭の一致も、毎回変わる「いま」の状態の手前で終わる（隣り合う 354 組中 284 組）
- 原因 2: 並びが 課題 / 決まり / **いま** / 手引き / 技 / メモ / 直近の道具 で、毎回変わる状態が、ほとんど変わらない技とメモの前にあった
- 原因 3: 技の一覧の 1 行に成績（`成功 25/26`、`最後の失敗: ...`）が入っていて、技を動かすたびに変わる。一覧の節は隣り合う呼び出しの 77%（362 組中 280 組）で違った。さらに並びが成功の数の順で、成功のたびに入れ替わった
- 原因 4: 技を書く呼び出し（`skill_write`）は、システム指示が約 3.3K 字と長いのに、印がなく読みが 0%（ツールのない呼び出しは、本文の印がないとシステム指示も固まらない: 設計書 177）
- `advice` は、間隔が長い用途の印を外す決め（設計書 177 §2.5）のままにした

## 2. したこと
1. **道具選び（raw）の並びを、変わらないものが先、毎回変わるものが後ろ**に変えた（`RAW_TOOL_TEMPLATE`）: 課題 / 決まり / 手引き ‖ 覚えた技（固定の部分）/ 自分のメモ ‖ 技の成績 / 直近の道具 / いま。‖ が `CACHE_BREAK`。システム指示の印と合わせて 3 つ（1 時間、1 時間、5 分）。変わるものは、後ろから、状態 → 直近の道具 → 技の成績の順
2. **技の 1 行を、固定の部分と成績に分けた**（`SkillInfo.describe_fixed()` / `record()`。`describe()` は従来のまま、通常のプレイは変えない）。固定の部分は版を書き直すまで変わらない（名前、版、説明、生の bot、引数）。成績（試し中か、成功の数、最後の失敗、同じ理由の連続、呼ぶと動く版）は「技の成績」の節に分けて、毎回変わる側に置く
3. **raw の技の一覧は名前順**（`RawAdvancePlay._skill_list`）。成功の数の順だと、成功のたびに入れ替わって一覧の前方一致が壊れる。選ぶ 12 個は従来どおり成績で決め、選んだあとを名前で並べる
4. **技を書く本文（`SKILL_TEMPLATE` / `SKILL_TEMPLATE_RAW`）の先頭に `SCHEMA_SLOT` + 印**。変わらないスキーマの説明が先頭に来て、システム指示と合わせて最初の印の手前に入る。ローカルの LLM では、本文の最後にあったスキーマが先頭に移る（`plan` と `goal` は前から同じ）
5. 生成側（`_messages`）は変えない

## 3. 見積もり（確かめていない）
道具選びの本文の固定の部分は、課題・決まり（約 940 字）+ 技の固定の一覧（約 1.5〜2K 字）+ メモ（0.2〜1.2K 字）で、本文の約 50%。読み 0.1 なので、道具選びの 1 回あたり約 25〜35% の減り（技の一覧は技を書くたびに、メモは書くたびに書き直し）。技を書く呼び出しは、システム指示 + スキーマの約 3K トークンが読みに入る。
