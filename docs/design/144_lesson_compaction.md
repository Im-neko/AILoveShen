# 144. 教訓帳がいっぱいになったら、似た教訓を統合する（コンパクション）

2026-10-09、user: 「教訓帳がいっぱいになって消す時、コンパクションして整理するようにしてほしい」

## 1. なぜ要るか
教訓帳（`LessonBook`、`data/lessons.json`）は 200 件で満杯になり、足すたびに「効いた − 失敗」が最も低いものから消えていた。中身を見ると、同じ助言が言い回しだけ違って何件も入っている（水が流れ出る話が 16〜18 件、種をまく前に収穫する話が 12 件、苗木を草ブロックに植えない話が 8 件）。消すと、新しい教訓の枠は空くが、冗長な山は残り、別の話の教訓が先に消える。

## 2. 決めたこと（user の選択）
- 満杯（`max_lessons` 200）を超えたら、1 回だけ統合して 150 件ほどまで減らす
- 統合してよいが、実績は合算し、LLM が教訓を消すことはしない

## 3. 仕組み
- `LessonBook.learn` が新しい教訓を足して 200 件を超えると、裏で `compact()` を始める（書く側は待たない。イベントループがなければ次に回す）。統合する LLM（`LessonCompactor`）がある間は、統合が間に合わなくても 250 件（`max × 1.25`）までは消さない
- `LessonCompactor.propose`（`lesson_compaction.py`）は、教訓を目標（`goal` のキー、なし）ごとに分けて、1 グループ 1 回ずつ LLM に聞く（用途 `lesson_compaction`、ローカルのモデル、考えない）。全部を 1 回で見せると 2〜26 組しか見つからず、別の目標の教訓も混ぜた。目標ごとに分けると 200 → 約 120 件まで統合できた（実機のデータ、2026-10-09）。答えは `{merges: [{ids (2 つ以上), text (80 字まで), condition (60 字まで)}]}`
- 反映（`LessonBook._merge`）は、答えを待つ間に変わった今の教訓で数え直す。ない id・重なる id・目標が違う組・本文が長すぎる組は見送る。統合した 1 件は新しい id で、`taught` / `used` / `helped` / `failed` は合算、状況（`situation`）は全員が同じキーだけ、出どころは視聴者の教えを優先、`learned_at` は最も古い日、`last_used_at` は最も新しい日。`explicit` は全員が `explicit` のときだけ。統合は `logs/lessons/*.jsonl` に（`moment: compaction`、元の本文と統合後）残る
- LLM が答えない・統合が足りないときは、これまでどおり弱いほうから消して 200 件に収める（`_prune`）

## 3.1 食い違う教訓は advisor に決めさせる（user: 「矛盾して判断できないときはadvisorも使ってください」）
- 実機のデータでは、水の話の 16 件に「周囲より高く置く」と「低く置く」の両方があり、整理担当（ローカルのモデル）が選んで混ぜると、間違いを正しい顔で残した
- 整理担当は、同じ話で助言が食い違い、どちらが正しいか決められない教訓を、統合せず `conflicts`（その話の教訓の ids を全部と、何が食い違うかの 1 文）に書く
- `LITELLM_ADVISOR_MODEL` があるとき（`has_advisor`、設計書 143）は、グループごとに食い違いをまとめて 1 回、advisor（用途 `advice`。リモートの LiteLLM）に渡す。記録（教わった・効いた・失敗の回数）を添え、Minecraft の仕組みに照らして話ごとに正しい 1 文を書かせる（元のどちらも正しくなければ書き直してよい。自分でも決められなければ書かない）。答えは統合の組として反映（実績は合算）
- advisor がない・答えない・決められないときは、その教訓はそのまま残る（消さない）
- advisor の解決を先に反映し、あとの統合からその教訓を外す（残りが 2 件以上なら統合する）。丸ごと捨てると、食い違う 2 件のせいで同じ話の十数件が統合されずに残った（実機）
- 実機（コピーの教訓帳、`claude-sonnet-5-5`）: 食い違いが 2 組出て、どちらも advisor が決めた。水の話は「水は設置した場所から横に流れ落ちるので、留めたいなら周囲を壁や段差のブロックで囲い、低い窪みに置く」。全体は 200 → 139 件（112 秒、うち advisor は 2 回）。この実行の反映前の版では、水の十数件の統合が重なりで捨てられたので、上のように外して残す形に直した

## 4. 分かっていること・していないこと
- **advisor が使えないと、食い違う教訓は統合されずに残る**: 食い違いを選んで混ぜることはしない
- **統合で実績が合算されるので、既存の「4 回思い出して一度も効かなければ消す」（`WEAK_AFTER_USES`）が統合した 1 件にかかる**: 実機のデータでは、統合した直後に 2 件（5 回・13 回思い出して効いていない）が消えた。これは「消さない」とは食い違うが、元の教訓の実績どおり（効いていない）なので変えていない
- 件数は 150 を目安に LLM へ頼むが、保証はしない（実測 200 → 約 120）。統合したあとに 200 件を超えていれば、弱いほうから消す
- 実機では未確認（コピーした教訓帳に本物のモデルで通して、201 → 118 件を確かめたが、`data/lessons.json` には書いていない）
