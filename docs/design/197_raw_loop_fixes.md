## 2. 夜に止められた技への案内（`skill_feedback.py`）
- 技が反射で止められたときの案内は「コードのせいではない。原因（近くの敵）に対処して、そのまま再実行せよ」だった。昼なら正しいが、夜は原因が「夜に外にいること」で、同じ技をそのまま動かせばまた次の敵に止められる。この文に従って `find_wood_far` が夜に繰り返された
- `feedback(..., phase)` に終わったときの時間帯を渡し、dusk / night なら「いまは夜: 外にいる限り止められる。先に危険から離れる（避難所、掘って入る、昼を待つ）。それから動かす」と案内する。day / dawn は従来どおり。時間帯は技が止められたときだけ `raw_state` から読む（`RawAdvancePlay._phase`）。通常のプレイ（`play.py`）は引数を渡さず従来どおり

## 3. メモの書かせ方（`raw_notes.py`、`write_note` の説明、決まり）
- 実行 10 は書き直し 0 回、書き込み 36 回。12 件の上限で古いものから黙って消えるため、計画や教訓が、新しい状態の実況に押し出された。仕組みが教訓を消していた（設計書 196 では「書かせ方」の問題と見ていたが、それは誤り）
- いっぱいのとき足せないことにした: 「いっぱい。いちばん役に立たないメモを replace=<番号> で書き直せ」と返す。残すものを選ぶのは書く側
- `write_note` の説明と決まりに「死んでも残る学びだけ。体力・敵の位置・持ち物など『いま』に出ている状態は書かない。変わったら replace」を足した

- ベンチへの影響: raw_free は実行 8〜10 と条件が変わる（advisor つき、夜の案内、メモの規則）。比べるときは、この 3 つが同時に入ったことを前提にする。効き目を分けたいなら、`LITELLM_ADVISOR_MODEL` を空にした実行と比べる
