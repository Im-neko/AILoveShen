# 130. 自作の技が失敗したら、原因を調べて直す

2026-10-09、user: 「LLM が自作スキルの失敗時は原因調査・修正するようにしてほしいです」（畑の失敗の調査で見つかった `till_and_sow_on_farm_v2` の 145 回の失敗から）。

## 1. 起きていたこと
01:16Z にローカルモデルが書いた技が、148 回使われて成功 3、失敗 145。耕す手が「耕しただけで何も植わっていない地面がある」と断られると `break` して `t.done` で終わる作りで、耕し済みのマスにまく手へ進まなかった。失敗の記録には「最後の道具: till = refused …」と原因が出ていたが、モデルはそれを読まずに同じ技を呼び続けた。設計書 120 は、同じ理由で 5 回失敗した技を止めるだけで、原因を調べて直すことは求めていなかった（120 §3）。

直す道具 `write_skill` はあったが、(1) 失敗のあと呼ぶかはモデル任せで、(2) 書き直しは原因を書かなくても通り、(3) 前と同じコードを書いても通った。

## 2. 直したこと
1. **失敗の結果に次の手を付ける**（`play.py` `SKILL_FAILED_NEXT`）: 技が失敗（`fail` / `error`）したときの道具の結果に「先に原因を調べる（記録の、失敗した・断られた道具とその文）。コードのせいなら `write_skill`（what に原因と直し方）、場面のせいなら道具で整える。同じ技をそのまま呼ばない」を付ける。見張りが止めた（`stopped`）・同じ理由で動かさなかった（`refused`）ときは付けない
2. **直す書き込みは原因を書かせる**（`skills.py` `_check_fix`）: 同じ名前の技を書き直すとき、`diagnosis`（どの呼び出しが、どんな文で失敗・断られたか、なぜか。20 字以上）がなければ差し戻す。前の版と同じコードも差し戻す（「原因が技のコードにないなら、書き直さない」と伝える）。差し戻しは既存の書き直し（`max_attempts`）の中。新しい技には要らない。スキーマの `diagnosis` は先頭に置く（原因を書いてからコードを書かせる）
3. 書いた原因は、直した理由（`SkillRevisedEvent.reason`）になる（なければ前の失敗）
4. 文言: 技を書くシステム指示の「直すとき」と、道具の選択の技の節（長さの上限 190 字内）、`abilities.yaml` の `skills`

## 3. 変えなかったこと
- 失敗のたびに自動で書き直させない。原因が場面（クワがない、種がない）のこともあり、書き直しは 1 時間に 3 回まで（費用）のため。モデルに原因を調べさせ、コードのせいなら直させる
- 同じ理由で 5 回失敗した技を止める決まり（設計書 120）はそのまま

## 4. テスト
`test_skills.py` に 3 件（原因なし・同じコードの差し戻し、新しい技は原因不要、失敗の結果に次の手が付く条件）。`_check_fix` の呼び出しと付ける条件を外すと落ちる。Python 1639 件通過。
