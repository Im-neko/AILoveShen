# レシピを全部入れて調べられるようにし、Gemini の知識でクラフトする

作成: 2026-09-26。

## 1. 目的

ユーザー（2026-09-26）: 「レシピはなるべくたくさん入れておいて検索可能にしておくのがよい。あとは Gemini が元から持っている知識でクラフトできるようになっているとよい」

きっかけ: 「ベッドを青くしない？」に「まだできない」と答えた。原因はレシピの知識（minecraft-data は染色のレシピを 1 通りしか載せない）で、操作の仕方ではなかった。

## 2. 今どうなっているか

- **クラフトの実行はもう全部できる**: サーバーの RCON が接続時に `recipe give @a *` を送り、ボットのレシピ本にはすべてのレシピが入っている。クラフトはレシピ本の要求（`craft_recipe_request`）なので、サーバーが知っているレシピなら何でも作れる
- **足りないのは知識**: 計画（solver）、調べもの（`recipe_of` / `how_to_get`）、プロンプトは minecraft-data のレシピを使っている。タグの材料（どの羊毛でも、どの原木でも）が 1 通りしか載らず、作れないと判断する物がある。検索もない

## 3. 形

- **レシピのデータを同梱する**: 1.21.4 のバニラのレシピ全部（1,370: 作業台・手持ちのクラフト、かまど・溶鉱炉・燻製器・焚き火、石切台、鍛冶台）とアイテムのタグを、`minecraft-bridge/data-static/` に JSON で置く。取り方は `npm run recipes:fetch`（misode/mcmeta の 1.21.4 の要約。バージョンを上げるときに取り直す）
- **`recipes.mjs`（RecipeIndex）**: 読み込み、タグを展開（入れ子のタグも）、材料を「どれか 1 つ」の候補の集まりにする。検索（結果の名前、材料の名前、部分一致）
- **計画（solver）に使う**: `Knowledge` がレシピをここから取る。材料がタグならグループ（`#planks` など）として解く。染め物（別の色から染めるレシピ）は、白いものからに絞る（染めた物から別の色に染め直す遠回りと、ベッドからベッドの循環を避ける）。石切台・鍛冶台のレシピは、道具がまだないので計画には使わない（検索には出す）
- **調べもの**: `recipe_of(item)` は全部の作り方（作業台かどうか、かまど、石切台）を返す。新しい `find_recipes(query)`（例: "blue", "lantern", "wool"）で結果か材料の名前から探す。道具モードと技（`t.find_recipes`）で使える
- **Gemini の知識でクラフトする**: Gemini は知っている物を名前で目標や道具にしてよい（`have(lantern, 1)`、`craft(lantern)`）。実際のレシピはブリッジのデータで確かめてから作る（作り話のレシピで動かない）。レシピにない物（存在しない名前）は理由つきで断る。「できること」に「バニラのクラフトのレシピはすべて使える」と書く

## 4. やらないこと

- Gemini にレシピ（グリッドの並べ方）そのものを書かせて手で並べる: サーバーのレシピ本で作れるので要らない。並べ方の間違いで材料を失う危険もある
- 石切台・鍛冶台を使うこと（それらの道具は後で）

## 5. 検証

- 単体テスト: タグの展開（入れ子）、検索、solver が完全なデータで主な物（板材、棒、作業台、木のツルハシ、かまど、チェスト、ドア、ベッド、松明、青いベッド、ランタン）を「不可能」にしない、染め物を白からに絞る
- 実機: 視聴者の「〇〇作って」（盾、ランタン、色つきのベッド）が引き受けられ、作れるか
