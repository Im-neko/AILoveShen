# 81 チャットの返事が見る、会話の流れと時系列

2026-10-01、状態: 実装済み、実機では未確認（配信の再起動が要る）。

## 1. きっかけ

user: 「コメントに反応する時はそこまでのコメントとbotの応答の会話の流れをふまえて応答してほしいです。この時、時系列も大事なので時系列に注意して応答を生成するようにしたいです」

それまでの返事は、会話の履歴の最新 10 件（実況も数えた）を、時間も誰への返事かも付けずに見ていた。実況は頻繁なので、コメントとの往復が押し出されやすかった。コメントは返事を書き終えてから履歴に入る（実況が先に答えないため、2026-09-30）ので、返事を書く間に入った実況の後ろに並び、時系列が逆になった。返事をしなかったコメント（仕分けで飛ばした、追いつかず捨てた）は履歴に残らず、あとの返事から見えなかった。

## 2. 仕組み

- `Conversation`: 最新 40 件（20 から）。`_append` は時刻の順に並べる。視聴者のコメントは届いた時刻（`ConversationMessage.timestamp` = `ChatComment.received_at`）で入るので、返事を書く間に入った実況より前に並ぶ。`recent_chat_flow(chat_limit, commentary_limit)` は、視聴者のコメントと自分の返事の最新 10 件と、実況の最新 3 件を、時刻の順に返す（返事のプロンプトが使う）。返事の `ConversationMessage.addressed_to` に、誰のコメントへのものかを入れる
- プロンプト（`format_messages(messages, now)`）: 行頭に `[N秒前]` と、`nekoさん` / `あなた（nekoさんへの返事）` / `あなた（実況）` を付ける。`now` なしの書き方は目標の決定・実況のまま。返事の本文のコメントは、5 秒以上経っていれば `コメント（42秒前に届いた）:`、ほかに返事を待っているコメントがあれば「## このあとに届いた、まだ返事していないコメント」を付ける（`GenerationContext.now` / `comment_received_at` / `waiting_comments`）
- 返事の決まり（`REPLY_RULES`、`reply` と `reply_requests`）に「会話の流れと時系列」: 古い順、[ ] は経った時間、コメントは届いた時点の流れへの発言、「それ」は流れから決める、人を取り違えない、答えたことを繰り返さない、「今していること」は今の状況で古い会話の時点とは違うことがある
- 経路: `ChatResponder` が `received_at` と待っているコメント（`_as_message`）を `LLMService.generate_response` → `GenerateResponseRequest` → `GenerateResponseUseCase` に渡す。仕分けで飛ばしたコメントと、追いつかず捨てたコメントは `remember`（`factories/stream.py`: 履歴に視聴者のコメントとして足す）で残す

## 3. 弱いところ

- 返事の履歴は 10 件。話題が長く続くと古い往復は見えない
- 返事が会話の流れを使うかは LLM 次第（決まりと形で促すだけ）。実機の返事で見て、足りなければ決まりを足す
- 仕分けで飛ばしたコメントは、返事のないコメントとして履歴に並ぶ（実況・目標の決定のプロンプトにも出る）
