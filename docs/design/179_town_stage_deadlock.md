# 179. 書き損じた街の段階の条件で、段階が終わらず目標の決定が回り続ける

## 1. 起きたこと（`logs/stream.log`、`logs/generations`、`data/mission.json`）

- 2026-10-16 01:25 から約 6 時間、目標の決定が通らなかった。生成ログの 1113 回の目標呼び出しのうち、`through_night` が 466 回、`at_home` が 188 回。差し戻しの理由は「昼なのに through_night」480 回、「at_home はもう済んでいる」186 回、「大目標が残っていない」114 回。配信は家の中で `wait` と `sleep` を繰り返し、街づくりは止まっていた
- `data/mission.json` の街の段階 2（食料とあかりで夜を越せる拠点にする）の `unresolved` に、`placed(torch, home','count':8},{) は判定できない（conditions rejected: where must be home, ...）` があった。街を定めたときに LLM が書いた条件の `where` が壊れていて、ブリッジに 3 回差し戻されても直らず、設計書 15 のとおり未解決に移された
- 未解決が残る段階は終われない。書き直すのは語彙（`vocabulary_version`）が前に試したときから変わったときだけで、今の版は `tried_with` と同じ `611acf6719da`。この壊れた部分は永久に残る状態だった
- 段階の条件のうち `stored(food, 16)` は済み、残りの条件がないので、段階は大目標としてリストに入らない（`_next_stage`）。大目標のリストが空になり、LLM は大目標を自分で足すしかないが、「リストの編集は変える理由があるときだけ」という決まりと、前回の見直しの文の写しで、足さずに生存の小目標（`through_night`、`at_home`）を選び続けた。どちらも昼・達成済みで差し戻される。足した大目標も、壊れた未解決の文を見て `placed(torch, 8, home)` など済んだものだった（41 回）

## 2. 原因は 2 つ

1. **`TownPlanner._settle`**: 手に入らない条件（`impossible`、能力が足りない）と、判定できない条件（`GoalRejectedError`、書き損じ）を、同じく未解決に移していた。前者は能力が足されたら書き直せるが、後者は語彙が変わっても書けるようにならない。待たせると段階が二度と終わらない
2. **大目標が空のときの目標の決定**: 生存の小目標は夜・空腹・体力・死亡のときしか通らない。空のまま待っても決まらないのに、プロンプトには「なし」としか出ず、足すよう言っていなかった

## 3. したこと

1. `_settle`: 判定できない条件は、警告のログを出して**捨てる**（未解決に移さない）。手に入らない条件は今までどおり未解決。判定できる条件も未解決も残らない段階は、`TextGenerationError`（`no condition the bridge can judge`）にして、街の定義を保存せず次の切れ目でやり直す（`advance` の持ち越しと同じ）
2. `format_goals`: 目標の決定のプロンプト（`with_ids`）で大目標が空のとき、`なし（空のままにしない: plan_changes の add で、最終目標に向かう大目標を足す。身を守る小目標が選べるのは夜・空腹・体力・死亡のときだけ）` と出す。大目標を編集できない道具の選びには出さない
3. 保存済みのデータ `data/mission.json` の段階 2 の `unresolved` を空にした（コードでは壊れた文を見分けられない。元は `data/backups/mission-20261016-before-stage-fix.json`）。段階 2 は済んで、街が完成した（全 2 段階）
