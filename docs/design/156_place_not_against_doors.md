# 156. 置くときにドアなど使うブロックに寄りかからない

2026-10-10、user: 「ドアの前からその斜め上の奥にあるブロックに対してブロック置こうとしてるせいでブロック上手く置けずにドアをパカパカしてるみたいです」

## 1. 起きていたこと
`logs/place-refusals.jsonl`（12:00Z 以降）の「置けなかった」60 件のうち 55 件が、`caller: placeOne`、置き先 (158,81,-455)、寄りかかった面 `oak_door (158,80,-455)`。置き先は戸口の真上のマス（家の壁の最後の 1 枚）で、1 つ下はドアの上半分。サーバーは「the block is still air」と断り、同じ手が約 2 秒おきに続いた。

## 2. 原因
`placeOne`（`build.mjs`）が使う `GoalPlaceBlock`（mineflayer-pathfinder）は、置き先の 6 つの隣を下・上・北・南・西・東の順に見て、届く最初の面を基準にする。基準にできるかは当たり判定の形だけを見るので、ドア（`shapes` がある）を選ぶ。ドアに向けて「置く」操作をすると、置く代わりにドアを使う（開閉する）。サーバーが置けず、ドアだけが開け閉めされた。隣には壁の板（西と南）があり、そちらを基準にすればよかった。

## 3. 直したこと
`place-faces.mjs`（新）の `placeFaces(bot, pos)`: 6 面のうち、隣が使うブロック（`INTERACTIVE`: ドア・トラップドア・フェンスゲート・チェスト・樽・作業台・かまど・ベッド・ボタン・レバーなど。`placing.mjs` が持っていたものをここへ移し、`placing.mjs` から再公開）の面を外す。`GoalPlaceBlock` を作る 3 か所（`build.mjs` `placeOne`、`primitives.mjs` `place_at` と `level` の穴埋め）の `faces` に渡す。基準にできる面がすべて使うブロックなら、置く先が見つからない（`no reference face`）失敗になり、ドアを開閉しない。

## 4. 直していないこと
- `place_at` の `c.against`（呼び出し側が借りる面を指定する）がドアのときは、そのまま（候補を作る側が外している）
- pathfinder が自分の足場積みで基準にする面
- 実機（ブリッジの再起動後、`caller: placeOne` の件数で見る）

## 5. テスト
`place-faces.test.mjs`（使うブロックの面を外す、既定の `GoalPlaceBlock` がドアを選ぶことの再現、絞ると壁の板を選ぶ、すべて使うブロックなら置く先がない）
