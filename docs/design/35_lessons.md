# 35. 教訓帳: 指摘と失敗を、似た状況で思い出す

作成: 2026-09-26。18（自分のメモ）、27（失敗の分析）、34（Jev でできることは Jev に）、12・13（返事と頼み）に関係する。

## 1. きっかけ

ユーザー（2026-09-26）: 「過去の指摘などの記憶を、似たような状況になったときに思い出すのが難しそう。指摘とその条件をうまく覚える方法はないか」→ 提案（状況のスナップショットつきの教訓帳、コードで絞って Jev で確かめる、実績で残す・消す）に「一旦それでやってみます」。

今のメモ（18）は、書いた日から 3 日で消え、どの状況でも全部をプロンプトに出す。視聴者の助言（`learn_from_viewer`）も失敗の助言（27 の `advice`）も、

- 数日で消える（夜の助言を、次の夜には忘れている）
- 関係のない場面にも出る（昼の採掘中に夜の助言）、数が増えると全部は出せない
- 効いたかどうかがわからない

## 2. 教訓帳（メモ帳とは別）

教訓 1 件（`Lesson`）:

| 項目 | 中身 |
|---|---|
| `text` | 教訓（自分の言葉の日本語 1 文、80 字まで。座標や家の名前は書かない） |
| `condition` | どんなときの教訓か（Gemini の言葉、60 字まで。Jev が当てはまるかを見る） |
| `situation` | 状況のキー（下の決まった語彙）。`explicit` なら Gemini が選んだキー |
| `source` | `viewer:<名前>`（コメントで教わった）か `failure`（自分の失敗から） |
| `taught` / `used` / `helped` / `failed` | 教わった回数、思い出した回数、そのあと小目標が済んだ回数、行き詰まった回数 |

- ワールドが作り直されても消さない（メモと違う: 教訓は場所によらない）。`data/lessons.json`
- 日で消さない。消すのは実績（§6）と上限（200 件）

### 2.1 状況の語彙（コードが決める）

| キー | 値 |
|---|---|
| `goal` | 小目標の述語（have / stored / built / through_night / explored …） |
| `item` | 小目標の物（oak_log、iron_pickaxe、建物の名前） |
| `time` | day / dusk / night / dawn |
| `place` | home（家の中）/ underground / outside |
| `body` | hungry（満腹度 6 以下）/ hurt（体力 8 以下）/ ok |
| `pickaxe` | yes / no（つるはしを持っているか） |
| `ended` | 前の小目標の終わり方: stuck / stalled / died / met / other |

## 3. 教訓の入り口

1. **視聴者の助言**: 返事の `lesson`（今まで通り）に、`lesson_when`（任意: `text` と、`goal` / `item` / `time` / `place` / `body` のうち当てはまるもの）を足す。教訓帳があれば、メモ帳ではなく教訓帳に書く（同じ教訓はメモに 3 日残すより、似た状況で出る方がよい）。`lesson_when` のキーがなければ、今の状況のスナップショット
2. **自分の失敗**: 失敗の後の目標の決定（27）に、任意の `lesson` と `lesson_when` を足す（「次に似たことがあったら」の一般的な教訓。座標は書かない）。キーがなければ、行き詰まった小目標とそのときの観測のスナップショット（`ended` つき）

同じ教訓（空白と句読点を除いて同じか、ほぼ同じ文で同じ `goal`）は新しく書かずに `taught` を 1 増やす（視聴者に何度も言われた教訓は強くなる）。

## 4. 思い出す流れ

1. **コードで絞る**: 今の状況と教訓のキーの重なりを点にする（`item` 3、`goal` 2、`body` 2（ok 以外）、`ended` 2（失敗のとき）、`time` 1（day 以外）、`place` 1（outside 以外）、`pickaxe` 1（no））。`explicit` の教訓は、書いてあるキーが今と違えば外す（「夜は…」を昼に出さない）。2 点以上を、点、実績（helped − failed）の順に最大 6 件
2. **Jev で確かめる**: 1 回の `IFastJudge.ask` で、教訓ごとに YES_NO（「この教訓は今の状況に当てはまるか」、`condition` と今の状況を見せる）。確信度 `min_confidence`（0.6）以上の「はい」だけ残す
3. Jev が答えない・時間切れ（`timeout_seconds` 2 秒）・`judge: rules` のときは、コードの上位 3 件（前と同じくプレイは止めない）
4. 最大 `shown`（4）件を出す

思い出すのは 2 か所:

- **目標の決定の前**（Gemini が決めるとき）: 終わった小目標の状況と、一番上の中目標のまだの手順（これからやること）をキーにする。`Activity.lessons` として「思い出したこと」の欄に出る（目標の決定、実況、返事で同じ見え方: 12）
- **小目標の始まり**（Jev が選んだときも）: 新しい小目標の状況。`Goal.lessons` として Jev の状態（`remember`）と道具のプロンプトに出る。この教訓が §6 の実績の対象

「思い出したこと」はメモと同じく「確かめていない」と書く（事実はゲームの状況）。

## 5. 記録

`logs/lessons/*.jsonl`: いつ（decision / start）、状況、候補の教訓、Jev の答えと確信度、出したもの、前のやり方に回した理由。

## 6. 実績で残す・消す

- 小目標の始まりに思い出した教訓: `used` +1。その小目標が済めば `helped` +1、行き詰まった・進まない・死んだら `failed` +1（時間帯の変化などは数えない）
- 確かな教訓（`helped` 2 以上で `helped` > `failed`）は消さない
- 弱い教訓（`used` 4 以上で `helped` 0）は消す
- 200 件を超えたら、確かでないもののうち（helped − failed、最後に使った順）の一番低いものを消す

## 7. 設定

```yaml
minecraft:
  lessons:
    judge: jev          # jev | rules（コードの上位だけ）| off（教訓帳を使わない: 視聴者の教訓はメモへ）
    path: data/lessons.json
    record_dir: logs/lessons
    shown: 4
    candidates: 6
    min_confidence: 0.6
    timeout_seconds: 2.0
    max_lessons: 200
```

## 8. 決めなかったこと・あとで

- Gemini の `note_changes` の lesson（メモ）は今のまま（短い間のメモ）。教訓帳に寄せるかは使ってから
- 教訓の書き直し・まとめ（似た教訓を 1 つにする）を Gemini にさせる
- 点の重みと閾値は `logs/lessons` を見て直す
- 実機での確認はまだ
