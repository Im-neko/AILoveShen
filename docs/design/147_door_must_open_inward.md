# 147. ドアの奥が固いブロックでふさがる設計を、設計の段階で差し戻す

2026-10-10、user: 「今立てたstorehouse、床の高さが合って無くて入れないよ」「これにLLMが気付けるようになってほしいです」
（`logs/generations/gen-20261010T052546Z.jsonl` 06:59:53Z の `build_design`）

## 1. 起きていたこと
- 倉庫（storehouse、7x7x5、near_home）が 244/244 で建ち終わったが、ボットも入れない
- 設計の形（AI の出力）: `fill cobblestone y=0`（床）、`hollow_box planks y=1〜4`、4 隅の `fill log`、`clear (1,2,1)-(5,3,5)`（部屋の中）、`door (3,1,0)`
- 実測（`inspect`）: ドアは (167,80,-450)。外の地面は y=79 の草（立つ高さ 80）で、ドアの高さは合っている。奥の (167,80,-449) は板で、立てるのは y=81。ドアの真上 (167,82,-450) も板なので、1 段上る余地がない（出るのは問題ない）

## 2. 原因
- `hollow_box` の底の面も固い。床を y=0 に別に作ったうえで y=1 から箱を置いたので、y=1 の全面が板になった。部屋の中を空ける `clear` は y=2 から始まり、y=1 は残った（人が立つのは y=1 というプロンプトの決まりとずれた）
- 設計の検査（`BuildDesign`）は、名前、範囲、ブロック数だけを見ていて、ドアの奥に立てるかを見ていなかった。ブリッジの検査（`registerBuild`）は世界との衝突を見る場所で、形の誤りは見ない

## 3. 直したこと
- `BuildDesign._check_entrances`（`domain/value_objects.py`）: 展開したブロックで、ドアの内側の 2 マス（足と頭）が固いブロックなら `ValueError`。理由は `previous_error` として設計をやり直させる AI に返る（最大 3 回）。内側の向きはブリッジの `BuildPlan.doorOutward` と同じ決め方（左右が壁なら南北、そうでなければ東西）
- プロンプト（`build_design`）に、`hollow_box` の底の面も固いこと、ドアの内側の 2 マスは空けることを書いた

## 4. 直していないこと
- 建ってしまった storehouse の検査: 検査は新しい設計にしか効かない
- storehouse の設計図は直した（2026-10-10 18:29、user: 「やっていいです」）: ブリッジを止め、`state.json` の `builds.storehouse` の y=1 の内側 25 マスを `planks` から `air` に書き換えて再起動（元は `logs/state.json.bak-20261010-storehouse`）。ブリッジの `placed` は 244/244 のまま（遠くで読み込めず再計算していない）。ボットが倉庫に戻って板を掘るかは未確認
- 建て終わった建物にドアから入れるかを確かめて、AI に知らせること（今は設計の段階だけ）
