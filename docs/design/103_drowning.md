# 103. 溺れないようにする

2026-10-07、user: 「え、なんか溺死した？」「なんで」「溺れないようにしてほしい」
（`logs/bridge.log` 07:12〜07:13Z、`logs/generations`）

## 1. 起きていたこと

目標 `have(coal, 2)`（LLM の思い込みで、石炭は要らなかった。設計書 67 §5 の続き）のために、LLM が `goto(131, 64, 131)`（家から南東へ 330 m、海の上）を呼んだ。経路探索は水の中を歩いて渡り、海底（y=52〜56）で頭が水の中のまま、毎秒 −2.0 を 10 回受けて死んだ（20 → 0）。

息の反射（設計書 69）は一度も動かなかった。診断は `unknown (in water, oxygenLevel 308, head cell water: drowning with the air value not falling?)` だった。2026-10-04 の死亡（y54、毎秒 2.0 を 8 回）のログにも、同じ書き方の診断がある。同じ原因で、2 回目。

## 2. 原因

1. **反射の条件が、実機の値と合っていなかった。** 反射は `bot.oxygenLevel` が気泡の数（0〜20）だと想定し、`PLAN_AT`（16）以下で動く。実機では水の中で 294〜319 の値が出た（水の外では 20）。16 以下にならないまま、溺れ死ぬまで反射が出なかった。mineflayer 4.39（`entities.js` の `air_supply / 15`）の計算と、実機の値が合わない理由は、まだ分かっていない
2. **経路探索が、水の中をほぼ無料と数えていた。** `liquidCost` の既定は 1
3. **`goto` が、水の上の座標を断らなかった**
4. 溺れの診断が、`bot.oxygenLevel` だけを見ていた（原因が `unknown` になる）

## 3. 決めたこと

酸素の値は信用せず、**頭が水の中にいた時間から息を見積もる**（`breath.mjs` `trackHead` / `airLevel`）。1 気泡 = 15 ティック = 0.75 秒。値は MAX_AIR（20）から引く。水から出て 3 秒呼ばれなければ数え直す。`bot.oxygenLevel` が 0〜20 の範囲なら、小さいほうを使う。水中呼吸や息の強化は無視する（早めに浮くほうが安全）。

| 件 | 直し | 場所 |
|---|---|---|
| 息の反射 | 見積もりの息で動く（深い海なら、水面まで泳ぐのに足りなくなる前に出る） | `breath.mjs` |
| 経路探索 | `liquidCost` を 10 に。水の中 1 マスを、陸の 10 マスぶんの遠回りと数える（浅い川は渡る） | `primitives.mjs` `configureMovements` |
| `goto` | 水の上の座標は断る（ボートのときは通す）。座標の下 8 マスまでの最初の固い物の上が水なら断る | `tools.mjs` |
| 診断 | 見積もりの息が 2 以下なら `drowning` | `damage-log.mjs` |

## 4. テスト
- `breath.test.mjs`: 酸素の値が 300 前後でも、深い海で息が尽きる前に反射が出る。数え直し
- `movements.test.mjs`: `liquidCost`
- `tools.test.mjs`: 水の上の `goto` を断る、陸は通す
- `damage-log.test.mjs`: 約 14 秒で `drowning`
どれも、直しを外すと落ちる。

- `oxygenLevel` の 300 前後の理由（mineflayer の値の尺度）は、未解明。実機で `bot.oxygenLevel` と気泡の関係を測る
- 水の中の見積もりは 1 気泡 0.75 秒の固定値。実機で測って直す
