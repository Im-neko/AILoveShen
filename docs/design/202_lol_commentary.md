# LoL の試合を見ながら雑談する（マイクラ以外の配信）

作成: 2026-10-24。ユーザーの問い「マイクラ以外のコンテンツを考え始めたい。LoL 実況。他人の LoL のゲームプレイ画面を見ながら実況・雑談したい」。ユーザーの決定: 見る試合は **1（自分のプレイ）と 3（配信者の生配信）**、スタイルは **ゆるい雑談メイン（解説はしない）**。**検討の段階。実装は Phase 0 の実験スクリプトだけ（§6）。**

## 1. 方針

- マイクラは「ブリッジが世界を判定し、LLM が目標を決める」だった。LoL は **操作しない**ので、目標・ソルバー・ブリッジ・Jev の候補選びは要らない。入力は映像だけ、出力は喋りだけ
- 解説（戦術の指摘、チャンピオンの強弱）は求めない。読めなかったものには触れない前提にして、画面の読み違いが害になりにくい雑談を選ぶ。「今のうまい」「やられたね」「ミニマップ静かだね」程度
- 画面の読み取りは **完了の判定には使わない**（マイクラと違い、判定すべき目標がない）が、**事実として話してよいのは読めたものだけ**とする

## 2. 流用するもの / 作るもの

| 流用 | 作る |
|---|---|
| `IScreenCapture` / `ObsScreenCapture`（OBS のソース 1 つを JPEG で撮る） | 見る→喋るのループ（`WatchService`、`GameService` の代わり） |
| 画像つきの `generate_json`（常にリモートの LiteLLM） | 画面の読み取り用の語彙・プロンプト（LoL 用の `abilities` ではなく、読み取りのスキーマ） |
| `CommentaryGate`（Jev: 今喋る価値があるか）、`max_silence_seconds` | 変化の検出（§4: 間引き） |
| チャット返信、振り分け、TTS、アバター、`AvatarDirector` | 試合の記憶（今の試合で話したこと、読めたキルの流れ） |

## 3. 入力

- **共通**: 配信映像を OBS のソース（ブラウザ / ウィンドウキャプチャ）に映し、`obs.game_source` で撮る。元の音声はミュート。**映像だけ Render Delay で数秒遅らせる**（AI の判断・読み取りの時間を映像の遅れに隠す。これで「今の！」が遅れて聞こえる問題を和らげる。遅らせた映像を撮り、同じ映像を配信に出す）
- **1（自分のプレイ）**: Live Client Data API（`https://127.0.0.1:2999/liveclientdata/…`、自己署名証明書）があれば、イベント（キル、オブジェクト）と時間を正確に取れる。Phase 2 でアダプターにする。**映像の読み取りと併用**（API が使えないときは映像だけ）
- **3（配信者の生配信）**: API は使えない。映像だけ。権利は §7

## 4. 費用と遅延

- 画像はプロンプトキャッシュが効かない。4 秒に 1 回呼ぶと 1 時間に約 900 回
- 間引き: (a) 画面の変化が小さければ呼ばない（縮小画像の差分）、(b) 軽い判定（Jev / 小さいモデル）で「話す価値があるか」を先に決め、本呼び出しは価値があるときだけ、(c) `max_silence_seconds` で長い黙りを避ける
- 画像の大きさ: 全体 768px では HUD が読めない見込み。**HUD の領域の切り出し**（時間・キル数の上中央、キルフィードの右上、ミニマップ、下中央の自分のチャンピオン）を高解像度で渡す案を Phase 0 で比べる

## 5. 画面から読むもの（Phase 0 で読めるかを測る）

時間（mm:ss）、キル数、見分けられたチャンピオン名、キルフィードの行、今起きていること（1 文）。**読めない・自信がない項目は空にさせる**（推測で埋めさせない）。雑談の一言は、読めたものだけを材料にする。

## 6. 段階と、先へ進む基準

- **Phase 0（実験）**: `tools/lol_vision_probe.py`。動画かフレームのフォルダから、幅（768 / 1280）と HUD の切り出しごとに、読み取りの JSON と雑談の一言、遅延、トークンを記録する。ユーザーが目で見て判定する。目安（暫定）: (1) 時間とキル数が読める、(2) 雑談の一言のうち画面と矛盾するものが 1 割未満、(3) 読み取りの遅延の中央値が 4 秒未満。満たさなければ、切り出し・モデルの変更、または API 併用を先に
- **Phase 1**: `WatchService`。OBS の遅延、変化の検出、`CommentaryGate`、雑談。チャットとの掛け合い。`--no-speak` で試す
- **Phase 2**: Live Client Data API のアダプター（自分のプレイ）。API と映像の併用
- **Phase 3**: 試合の記憶（読めたキルの流れ、前に話したこと）、視聴者との雑談を試合の流れに結びつける

## 7. 未確認・ユーザーの確認が要ること

- **権利**: 配信者の生配信（3）を自分の配信で流して喋るには、配信者の許可と、Twitch の再配信のルール・音楽の扱いの確認が要る（私は法的な確認をしていない）。自分のプレイ（1）で始めるなら問題は小さい
- Live Client Data API が観戦モード・リプレイでどこまで動くか（未確認）
- モデルが LoL のチャンピオン・アイテムを（パッチの変化を含めて）どこまで知っているか
- 実際の読み取りの精度・遅延・費用（Phase 0 で測る）
