# 162. 丸石が足りない採掘場は、設計を切らずに待つ

2026-10-10 22:52、user: 「坑道と地上をなんどもなにもしないまま往復してる。原因わかる？」→ 「1 かな」（丸石が足りずに止まった採掘場を、掘り尽くしたと扱わない）

## 1. 原因
`dig_mine` は、坑道が洞窟に出て、塞ぐ丸石が手元に足りないとき、`giveUp`（`stopMine`）を呼んでいた。`stopMine` は設計（`layout.cells`）をそのセルで**切り捨てる**。危ないもの（溶岩・水・岩盤）を避けるための切り捨てを、足りない物（丸石）にも使っていた。

mine_2（底 y 32）は 10-10 07:41 に、丸石 0 個で 59 セルに切られた。以後、切られた設計は 59/59 で `done` になり、`minePlan` は「下りきった採掘場」と見て、底に鉱石が見えなければ掘り尽くしたとして、別の入口に新しい採掘場（mine_3）を設計した。22:51 の石炭の小目標は、mine_2 の底まで下りて（22.8 秒）何も取らずに上がり、別の入口へ歩いて mine_3 を作る、という往復になった。

## 2. 直したこと
- `dig_mine`: 丸石が足りないとき、設計は切らない。先に、掘ってきた坑道の横の石（`stone` / `deepslate`）を掘って丸石にする（`seal-stone.mjs`、直近 4 セルの両脇、足元と 1 つ上の高さ）。掘ってよいのは、設計のマス・階段の柱と床・これから塞ぐ面の外で、穴のまわりが固い岩か自分の坑道だけの所（洞窟・水・溶岩・砂利に面した所は掘らない）
- それでも足りなければ、`layout.paused = { x, y, z, need, reason }` を残して止まる（設計と `building` のまま）。掘った後なら成功として理由を返し（松明が尽きたときと同じ形）、1 セルも掘れていなければ失敗にする。次に丸石を持って戻れば、そのセルを塞いで続きを掘り、`paused` を消す
- `minePlan`: `paused` で丸石が足りない採掘場は後回しにして、ほかに掘れる採掘場があればそちらを選ぶ。ほかになければその採掘場の続き（石を掘って丸石にする）。丸石を持てば元に戻る
- 表示: 目標の行と施設の中身に `waiting at y N for cobblestone: ...` を出す
- 危ないもの（溶岩・水・岩盤）と「置こうとして塞げなかった」は、今までどおり切り捨てる

## 3. 直していないこと
- mine_2 はもう切られていて、`done` のまま戻らない（設計は元に戻せない）。mine_3 に移っているので、そのままにしている
- 降りる前にチェストから丸石を出す手は足していない（掘った石で足りるため）。松明（設計書 161）と同じ「下りる前の確認」にするかは、実機の様子を見てから
- 実機未確認（ブリッジの再起動が要る）

## 4. 同じ往復の、ほかの原因（user に報告済み、未対応）

- 長い移動の途中で、コメントの助言による考え直しが入って、歩いた分が無駄になる
