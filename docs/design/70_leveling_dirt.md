## 2. 決めたこと

**整地する土地の下は、土や石を取るために掘らない**（`leveling.mjs` `keptGround`）:

- 守る土地: `wanted`（Python が目標を立てるたびに `PUT /goal` の `level_areas` で送る。すべての大目標の条件、
  中目標、その計画の小目標、今の小目標の束にある `leveled`。まだ整地していない土地も守る）と、`done`
  （`level` を始めた土地をボット自身が覚える。8 か所まで、`state.json` の `leveling`。目標が終わった後も守る）
- 守る範囲: 中心から半径 + 1 の内で、床の高さ（立つ高さ − 1）以下の自然の地形（`TERRAIN`）。床より上の
  出っ張りは整地で掘るものなので、土の取り先としてよい
- 使う所: `digTargets`（候補とソルバー）、`find_blocks`、`observation.around`（数だけ、`in_leveled_area`）、
  ツール `dig`（断って、外から取るよう言う）。守る土地が近いと近い順の 64 個が全部その内になるので、あるときは
  512 個から探す（`findCount`）
- 土は整地の外から取る。外に土がなければ、いつもどおり探しに行く

**埋めるだけなら、穴の数だけ土を持ってから始める**（`fillNeeded` = 穴の数、最大 64）:

- 目標の枝 `leveled`: 出っ張りがあるか、持っている埋める物（`fillCount`: 土・粗い土・丸石）が穴の数以上のときだけ
  `level` の候補。足りなければ `dirt` を穴の数だけ集める枝（`addSolved`）と、その行
- ツール `level`: 出っ張りがなく、持っている数が足りなければ断る（土地の外から取るよう言う）

**穴埋めの直し**（`primitives.mjs` `level`）:

- 穴の中に立っていて、足元に積まずに縁へ出られた（浅い穴）ときは、飛ばさずに外から埋める。前は
  `climbed out but the hole is still open` でその列を飛ばした
- 出る途中で足元に積んで土を使い切ったら、次の周で終わる（前は `equip` に null を渡し、`Invalid item object`
  でその列を飛ばした）

**置けない原因の記録**（`place-report.mjs`）: サーバーに設置を断られたとき、置く先とその上下左右のブロック、
基準のブロック、ボットの位置と目の高さからの距離、そこから 3 マス以内の生き物を、ブリッジのログと
`logs/place-refusals.jsonl` に残す。置く動きは変えない。同じ列だけ断られる原因は、コードから決められなかった
（ボットの足元のセルではない。置く先の実物が空気なのに断られている）。記録を読んでから直す

## 3. 採らなかったこと

- 土の取り先を 1 か所に決めて設計する（「土の採掘場」）: 石の採掘場（設計書 68）と同じ形にできるが、土は家の
  そばで取れるので、まず「整地の下から取らない」だけにした。`quarry.spot` が同じ場所から掘り続ける（設計書 64）
- 整地を終えた土地を `done` から外す: 8 か所で古いものから捨てる。大目標が終わっても守るのが目的
- `demolish: true` で守る土地を掘れるようにする: しない（断る文が外から取るよう言う）
- 置けない列を数分は飛ばして覚える: 原因を見てからにする（残りの列に数えるので、飛ばすと達成の判定と食い違う）

## 5. 追記 2026-10-04: 「the block is still air」の原因の一部 — 縁に張り付いた位置からの設置

`logs/place-refusals.jsonl` の 634 件を調べた。**最初に出した「83% が自分のいるマスに置こうとしていた」は偏っていた**: 足元に積む塔の動作では成功も同じ状態になる（成功は記録されない）ので、断られた分だけを見ても原因とは言えない。実際は次のとおり。

- 塔の積み上げ（ボットがそのマスの中、`dy` 0〜0.75）: 断られても数 tick で再試行して通る。139 回の連続の中央値は 2 回、合計 144 秒 / 73.5 時間。直す価値は薄いので触っていない。連続 139 回のうち、そのあとの動作が失敗したのは 44 回。内訳は 8 件しか見ていない（2 件が下の補修、残りは反射・ダメージによる中断）ので、残りの 36 件は未確認
- **壁を壊して出たあとの補修（`exit_wall` → `repairWall` → `placeOne`）が、同じマス (61,77,-329) で 3 回（10/03 05:12、05:19、14:23）、決まって x=62.3 から断られ、失敗していた**。失敗すると壁に穴が残り、補修（`repair_wall`）も同じ位置から始まるので同じく失敗する。サーバーのプレイヤーの当たり判定は幅 0.6F（float）で半幅 0.30000001、Mineflayer の物理は 0.3 ちょうど。置くマスの縁にぴったり張り付いた位置（x=62.3 → 縁は 62.0）では、サーバーから見ると約 1.2e-8 だけボットがそのマスに入っていて、「プレイヤーと重なる場所には置けない」の規則で断られる、と考えると、毎回同じ位置・同じマスで断られることと合う。サーバー側の判定は直接見ていないので、これは**最も合う説明**であって確認ではない

直し（`build.mjs` `flushWith` / `backOffFrom`）: `placeOne` が置く前に、ボットの当たり判定が置くマスの縁から 2cm 以内に触れていれば（中に入っているのは別の話）、自分のマスの真ん中へ寄ってから置く。確かめ方: 次に壁の出入りがあったとき、`exit through the … wall` が成功し、`place-refusals.jsonl` に x=…3 の記録が増えなければ当たり。それでも断られるなら、記録の `bot` と `dest` から説明を考え直す。

残り 75 件（当たり判定の重なりなし）の原因は調べていない。
