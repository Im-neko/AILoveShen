# 102. 約束の層を先に決める・作業台は LLM が置く

2026-10-07、user: 「層決めてから目標設定するようにしてほしいです。手元の作業台もLLMの判断次第でおけるようにしてほしいです。浅い竪穴は地下としなくて良いです。判断が難しいので」
（経緯: 設計書 101。「本来中目標にはいるであろう「ツルハシを作る」が大目標にいます。目標の分類がやっぱり難しいみたいですがどこに困難がありそうでしょうか？」）

## 1. 約束の層（大目標か中目標か）

### 起きていたこと
視聴者「そこでツルハシ作って作業再開したら？」の返事（`purpose=reply`）は `request: none` で、約束を守る段階（`purpose=promise`）が `now` を選んだ。この経路のスキーマには `level` がなく、必ず大目標になった（`parse_proposal` は `level` を読むが、`promise_schema` が出させていなかった）。同時刻の `reply` の `request` 経路には `level: job` があり、層を選べた。入口 2 つのうち 1 つだけ層を選べなかった。

### 決めたこと
1. `promise_schema` に `level`（`objective` / `job`）を足し、題名・条件より前に置く。「先に層を決める」
2. `now` / `later` で `level` がなければ、差し戻す（`level is missing`）。ほかの経路と同じく、`level: job` は今の大目標の中目標として入る（`_accept_job`）
3. 層の基準（スキーマの説明と `PROMISE_RULES`）: 大目標 = 名前のある建物・施設、今の大目標と関係のない頼み。中目標 = 今の大目標が要る道具・材料、進めるのを妨げているものをなくす 1 つの一歩（穴から出てやり直すためのツルハシ、使う板材のための原木）。迷ったら中目標

### 残ったこと
- 層の判断はモデルの判断のまま。基準は「今の大目標のためか」で、機械的に判定できない（`have(道具)` は大目標にも中目標にも書ける）。実機で、分類を誤った約束の数を見る
- 小目標（生存の目標。through_night、at_home）にする層は、約束にはない（コードが大目標への混入を断るだけ）

## 2. 作業台

- `stationRefusal` の「地下には作業台を置かない」を外した（かまどは家の中だけのまま）。置くかどうかは `place` を呼ぶ LLM が決める。設計書 101 §3 の「閉じた地下でツルハシがないとき」の例外は、この一般の規則に置き換えた
- 置く場所を選ぶ側（候補の `stationSpots`）は、地下では出さないまま
- `craft` が、近くに作業台がなくて作業台を持っているとき、または遠くの作業台へ届かない（`No path`）ときに、「持っている作業台を `place` で隣に置いて、やり直す」と返す（遠い作業台へ歩こうとして `No path to the goal!` だけが返り、LLM が剣など別の物を作ろうとしていた）

## 3. 浅い縦穴

浅い縦穴（屋根 8 層未満）を「地下」と数えるかは、変えない（user: 判断が難しいので不要）。
