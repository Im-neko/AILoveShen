# 63. 再起動のあとに、今の小目標を続きから追う

2026-09-30。状態: 実装済み、実機では未確認。

## 1. 何が切れていたか

大目標・中目標・計画（`data/mission.json`）と、ブリッジの世界の状態（`state.json`）は保存されていたが、
今の小目標（理由、助言、診断、見直し、思い出した教訓、束）と、その歩みの数え（歩数、続けて失敗した回数、
進まない歩数）は `PlaySession` のメモリにしかなく、Python を再起動すると最初のステップで
「no goal yet」から決め直しになった。配信中にコードを直して再起動するたびに、Jev の選び直し（数秒）か
LLM の決定（10 秒以上）が要り、続けて失敗していた小目標を助言なしでもう一度選ぶことがあった。

## 2. 決めたこと

- 保存: `data/goal.json`（`minecraft.goal_path`、空なら保存しない）。`IGoalStore` / `JsonGoalStore`。小目標を決めたとき
  （`_start_goal`）と、1 手ごとに（`execute` の終わり）、`SavedGoal`（小目標、時間帯、歩数、続けて失敗、
  進まない歩数、残りの最小値、決めたときの死んだ回数）を書く。一時ファイルに書いてから名前を変える。
- 復元: `StartPlayUseCase._resume_goal`。ブリッジが今も同じ小目標を追っているときだけ引き継ぐ。
  比べるのは、ブリッジの `/observe` の `goal.spec`（`GoalStatus.spec_label`、`have(log, 16)` の形）と、
  保存した先頭の条件（`dig_depth` は除く）。ブリッジも作り直した（ワールドのリセットなど）なら
  ブリッジの小目標はなく、引き継がない。`PUT /goal` は送り直さない（`through_night` の `sawNight`
  や `explored` の出発点など、ブリッジが持つ状態を壊さない）。
- 引き継いだあとの終わり判定は今までどおり最初のステップの `needs_new_goal` が見る: 済んだ、大目標が
  終わった、死んだ（保存した死んだ回数と比べる）、時間帯が変わった、歩数が上限を超えた、など。
- ワールドのリセットでは `data/goal.json` も日付つきの名前にして取っておく（`scripts/reset_world.sh`）。

## 3. 引き継がないもの

`Stagnation` / `Repetition` / `StuckCheck` の数え、小目標の始まりに思い出した教訓の実績（`Lesson`
の使った回数）、直近の行動記録（`_goal_steps`）、`_recent_goals`。再起動の後の数歩で数え直す。
保存した小目標が古い状況の判断を持ち越さないよう、実行中だった 1 手も引き継がない。
