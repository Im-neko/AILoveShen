# 設計書 46: 発言と行動を食い違わせない

状態: 実装（2026-09-27）

## 1. きっかけ

ユーザー（2026-09-27）:「発言と行動の不一致が目立つ」。すべてローカルの LLM に切り替えた直後の 07:14〜07:18 の記録（`/api/debug/gemini`）で見えたこと:
- 目標の決定が約 2 分で 6 回。決まるたびに実況が「次はこれをやる」と言うので、言ったことをやる前に計画が変わる
- 夕方に、時間帯が「夕方（朝まで約 9 分）」と書かれていて、見直しに「夜が明けたので外に出られる」と書き、外の手順を決めた
- かまどを持っているのに小目標 `have(furnace, 1)` と手順「石 8 → かまど」を決め、決めた時点で小目標は済んでいた。実況の「かまどの準備は完了」は正しく、行動（石を掘りに行く）が無駄だった
- 一言（live）が直前の実況と食い違った:「パンをクラフトするよ」の 30 秒後に「パンは明日作れる」
- 読み上げのキューは古くなった実況を捨てない（待ち時間は測っていない）

## 2. 目標の決定をコードで照らす（`AdvancePlayUseCase._decide_goal`）

差し戻して（理由を添えて聞き直す）次の決定に直させる:
- **もう済んでいる小目標**: ブリッジの `set_goal` の答えが `met` なら `the small goal … is already met now`
- **手順の順番**: 手順は順番どおりに進むので、後の手順が済んでいるのに前が残っていれば、前はそこへ行くためのものでしかない（`_check_step_order`。`/check` で判定。判定できなければ確かめない）
- **時間帯の取り違え**: 見直しの文が今の時間帯と食い違う言い方をしていれば（`_check_time`: 夕方・夜に「夜が明けた」「朝になった」「朝なので」、夜に「昼なので」、昼に「夜になった」「夜なので」。「夜が明けたら」のような仮定は除く）

存在しない述語は、前から `parse_decision` と「出していない述語」で差し戻している（07:15:55 の崩れた答えもそれで聞き直した）。

時間帯の書き方（`format_time`）: 夕方は「夕方（暗くなってきた。夜になるまで約 N 分、そのあと朝まで約 M 分）」。英語（Jev）も同じ。

## 3. 一言は直前の実況と食い違わない（`LiveNarration._events`）

一言に今の小目標（述語と理由）を先頭に渡し、指示に「直前に話したことと食い違うことを言わない（やると言ったことをやめる・明日に延ばす、済んだと言ったことをまだと言う、など。今の小目標と行動の結果が変わったときだけ変わったと言ってよい）」を足した。

小目標の切れ目の実況（Narrator）は、自分の実況が会話の履歴に残るので次の実況で見えている。一言は会話の履歴に残さない（設計書 43）ので、Narrator からは見えない（残ること）。

## 4. 古くなった実況は読まない（`TTSService`）

`tts.queue.max_age_seconds`（出どころ → 秒。既定 `commentary: 20`）: キューで待った時間がこれを超えた発話は、取り出したときに読まずに捨てる（ログ `[tts] N 秒待って古くなったので読まない`）。実況と一言は `source="commentary"`。視聴者への返事（`chat`）は遅れても読む。

## 5. 残ること

- 道具の選択（ローカル、考えない）が実況と逆のことをする（07:15:37: 実況「肉がないから牛を探す」、道具 `smelt beef x4`）のは、ここでは直していない。ブリッジが断る（持っていない物は焼けない）ので害は 1 手の失敗
- 目標の決定の回数そのもの（崩れた答えのやり直し、時間帯の変わり目）は減らしていない
- 実機では試していない
