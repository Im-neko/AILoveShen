# 91. 目標の 3 層の見せ方（大目標・中目標・小目標）: 小目標はいま実際にしている動作

2026-10-07、user: 「小目標に家を建てるとか抽象的なものがきてます」→「小目標にはいま実際にしようとしてる動作を表記しておいてほしい。大目標はいま達成しようとしていること（家の建築・植林場の構築・畑の構築・採掘場の構築）、中目標（「注目表」は打ち間違い）にはそれに向けて必要なことのうちの 1 つ（材料集め・ブロックの設置・整地・耕す・柵の設置・水源の確保・場所の選定）、小目標にはいま現在しようとしている行動（原木を集める・アイテムのクラフト・水源の設置・目的地までの通路の確保・家に帰る・寝る）」。

## 1. 起きていたこと

稼働中の記録（2026-10-07 05:25 JST）で、中目標が `have(log,16): done` と `built(): not yet`、小目標が `built()`（画面は「家を建てる」）だった。大目標「自分の家を作る」・中目標「家を建てる」・小目標「家を建てる」が同じ言葉になり、小目標の欄が「いま何をしているか」を示さなかった。

理由は設計どおり（設計書 50 §161）: `have` の中目標だけが次の一歩に分解され、`placed` / `built` / `farmed` などは中目標と小目標が同じ述語になる。小目標の欄は述語の日本語（`goal_label`）を出していた。

## 2. 直したこと（表示だけ。内部の小目標は述語のまま）

user の選択: 小目標の欄は**実行する手から日本語に変換**、建築 `built()` は**表示だけ分解**（設計書 50 §161 は変えない）。

- 小目標の欄 = いま実行している手の動作（`action_label.py`）。道具の呼び出し（`dig` `craft` `place` `go_home` `sleep`…）と、ブリッジの候補の `verb`（49 種）から、決まった規則で作る。LLM の一文（`intent`）や、候補の英語の名前（Jev が選ぶとそのまま画面に出ていた: `dig oak_log at 60,68,-202`）には左右されない。
  - 例: 原木の `dig` → 「オークの原木を集める」、`place_plan` → 「家づくり: オークの原木を置く（1/115）」（`built()` はここで分解されて見える）、`go_home` → 「家に帰る」、`sleep` → 「ベッドで寝る」。
  - 動作は次の手に変わるか小目標が変わるまで残す（`PlaySession.action`。手の間に述語の表示へ戻ってちらつかない）。決められない手（知らない verb、候補にない id）は空で、述語の label のまま。
  - 述語の label は「めあて: 家を建てる」の行に回した（動作があるときだけ）。`/overlay` も `/overlay/vtuber` も。動作が変わるとバブルが弾む（NEW! は小目標が変わったときだけ）。
- 中目標の欄: 題（LLM が書く「水源の確保」など）があればそのまま、なければ「種類: 条件」（`job_label`。材料集め / 材料の保管 / ブロックの設置 / 整地 / 植林 / 畑づくり / 明かりの設置 / 場所の選定 / 施設づくり。例: 「ブロックの設置: 家を建てる」）。
- 大目標は変えない（大目標の題は LLM が書く）。
- 英語の名前を日本語にする辞書（`ITEM_NAMES`）を `application/use_cases/item_names.py` に移し、木の種類（oak_log → オークの原木）も引けるようにした。
