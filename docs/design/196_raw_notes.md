# 196. 判断なしのプレイの自分用メモ（write_note）

2026-10-19。設計書 191（判断なしのプレイ）、192（手引き）、194（技の失敗の知らせ）の続き。

## 1. 何が起きたか

ベンチ 8・9 回目（raw_free）は、12〜24 分で作業台か木のつるはしまで進んだあと、夜の野原で 14〜24 回死に、進まなかった。設計書 191 の追補で「いま」に `deaths`（回数と最後の死に方）を足したが、9 回目も変わらなかった（76 分で 14 回、周りを見る技 391 回、避難所を「探す」技 44 回・作るのは 0 回）。

LLM が見るのは「いま」・技の一覧・直近の道具 8 件だけで、技は動かす手順しか覚えない。「夜は野原にいると死ぬ」「木は 78m 先」のような学びは、書き残す場所がなく、8 件で流れて消える。通常のプレイの「教訓」「自分のメモ」（`NoteKeeper`）は、ブリッジの判断や Python の決定の層にあって、判断なしのプレイには入らない。

## 2. 変えたこと

- 道具 `write_note(text, replace?)` を判断なしのプレイに足した（`tool_catalog.NOTE_TOOLS`。`QUERY_TOOLS` には入れない: 通常のプレイの道具の一覧と、プロンプトのキャッシュを変えないため）。ブリッジを通らず、Python が受ける（`read_guide` と同じ。同じステップの中で選び直せる調べものの扱い）
- `NoteBook`（`raw_notes.py`）: 12 件まで、1 件 240 字まで。`replace` に番号で書き直す。同じ文は足さない。いっぱいになったら足せず、書き直しを選ばせる（初めは古いものから黙って消していた。設計書 197 §3）
- プロンプトに「自分のメモ」を、技の一覧と直近の道具の間に載せる（毎回。技の一覧の後ろに置くので、前の部分のキャッシュは外さない）。決まりに「直近の道具は数件で消える。死んだ・失敗したときの原因と次にどうするか、この世界の様子は write_note で書き残す」を足した
- 最後の選択の周（調べものを出さない周）では、メモも出さない

## 3. しないこと

- メモの中身をブリッジや Python が作る・直すことはしない（「夜は穴を掘れ」のような助言は入れない）。何を書くか、書いたものを使うかは LLM が決める。そこが、この実験で測りたいこと
- 保存はしない（実行の中だけ）。ベンチは毎回新しいワールドなので、前の実行のメモを持ち越すと測定が汚れる。ログ（`メモ: ...`）には残る
- 手引き（設計書 192）は変えない。メモは人が書いた知識ではなく、LLM の失敗からの学び。`raw_free` にも `raw_guided` にも入る（記憶の仕組みであって、知識ではないため）

## 4. 測り方

`raw_free` を同じシード・同じ条件で回し、8・9 回目（木のつるはしまで 12 分 / 未達、死亡 24 / 14）と比べる。見るのは、(a) 死んだあとにメモが書かれるか、(b) 書かれたメモに沿って行動が変わるか（避難所を作る、昼のうちに木を集める）、(c) マイルストーンに着く時間と死亡回数。メモが書かれても行動が変わらなければ、モデルの力の問題として、強いモデルとの比較（`LITELLM_MODEL`）に進む。

## 5. テスト

`tests/unit/application/test_raw_notes.py`（書く・書き直す・断る・いっぱいで足せず書き直しを求める）、`test_raw_play.py`（メモがブリッジに行かず、同じステップで書かれ、次のプロンプトに載る。最後の周で出さない）。

## 6. 実行 10 の結果（2026-10-19）
36 回書かれたが、書き直し（`replace`）は 0 回。中身は「死亡 N 回目の後、夜、体力 X、敵 Ym。夜明けを待つ」という、「いま」に出ている状態の実況で、計画（昼に木を集めて板→棒→ツルハシ）はそれに押し出されて消えた。書いても行動は変わらず、死亡 23 回（82 分）。木のツルハシは 4952 秒で作れた（実行 8 は 756 秒）。直し方は設計書 197。
