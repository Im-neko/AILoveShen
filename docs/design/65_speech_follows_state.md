# 設計書 65: 発言を今の状態と約束に従わせる

状態: 実装（2026-09-30）。§2 → §3 → §4 の順に入れた。実機では未確認

## 1. きっかけ

ユーザー（2026-09-30）:「発言・目標・行動の一貫性が無いと感じることが多い」「視聴者が混乱するので困っています。1（言ったことと違う行動）、2（今の状態と違うことを言う）が主な問題です」「順に進めてください」。

設計書 46（発言と行動を食い違わせない）は、見つかった事例ごとに直した:
- 目標の決定を差し戻す（済んでいる小目標、時間帯の取り違え）
- 一言に「直前に話したことと食い違わない」と指示を足す → 追記で、直前の誤りを状態より優先させて悪化した
- 古い実況を読まない

どれも「LLM に書かせた文を、書いたあとに確かめる」ことはしていない。目標の決定と返事には差し戻しがあるのに、実況・一言・Narrator の出す文だけは、書かれたまま読まれる。もう一つ、直したかどうかを数える手段がない（「感じる」で直している）。

決まっていたこと（ユーザーが認めた順）: 設計書 → 測る → 予告は動き出してから（D）と変更の説明 → 発話の照合（B）。

## 2. 測る（先にやる）

### 2.1 読み上げの記録 `logs/spoken/*.jsonl`

視聴者が聞いたことの記録が今はない。`SpokenLines` は読み上げの前に入れるだけで、`TTSService` は 20 秒待った実況を捨てる（`logs/commentary` は Jev の間合いの判断で、話さなかった行も含み、文そのものはない）。`stream.spoken_record_dir`（既定 `logs/spoken`）に 1 行 1 件で書く:

- 話す前（`say` / `say_notice` / `say_reply` / 管理画面）: `event: line`、`text`、`source`（commentary / notice / reply / admin）、`outcome`（said / repeat: 直前と同じで言わない）、そのときの状態（`speech_state`: 小目標、`goal_met`、`intent`、`acting`、`has_home`、`inside_home`、`home_distance_m`、時間帯、体力。束の小目標は、まだ済んでいない条件だけを小目標として書く）
- 照合（§4）: `event: check`、`text`、`verdict`（ok / rewrite: 食い違うので作り直す / dropped: 言わない / unchecked: 照らせなかった）、`attempt`、`problems`、Jev の答え（`answers`: 質問 → [はい/いいえ, 確信度]）、状態
- 読み上げの結果（`TTSService` の `on_outcome`）: `event: tts`、`text`、`source`、`outcome`（played / failed / dropped_old: 待って古くなった / dropped_full）、`waited`

話した文と、話した時点の状態が同じ行に残る。突き合わせる相手は `logs/steps`（行動）と `logs/goals`（目標）。

### 2.2 測定の道具 `tools/speech_consistency.py`

- `forecasts`: 既存の `logs/commentary`（新しい小目標を話した行）と `logs/steps` から、予告した小目標のその後を数える。LLM を使わず、記録があれば過去の分も数えられる（`logs/steps` は古い記録と新しい記録で形が違う: 結果の行が無い日は、成功の数を出さない）
- `lines`: `logs/spoken` の各行を、話した時点の状態と照らして 1（予告と違う）と 2（今の状態と違う）に分ける。判定は §4 の `SpeechCheck` と同じ質問を Jev に聞く（`TYPESAFE_API_KEY` が要る）。配信中の照合と測定で判定がずれないよう、質問は 1 か所に持つ
- 1 時間あたりの件数と割合で出す。「視聴者がこれを聞いたら矛盾と感じるか」を基準にするので、種類は 1 と 2 の 2 つに絞る

## 3. 予告は動き出してから言う、やめたら言う（D と変更の説明）

### 3.1 何が起きているか（既存ログから）

`tools/speech_consistency.py forecasts` の結果（2026-09-26〜09-30 の全ログ。終わりが分かる 286 件。末尾の追記に全体）:

- 58% が「未達成でやめた」で終わる。その半数は 60 秒以内
- 予告しても行動が 1 つもないまま終わったのは 9%（09-29 以降は 3%）。「言った直後に変える」は主因ではなかった
- 動き出したあとでやめる理由は、行動が失敗し続ける（stuck）と、時間帯の変わり目（夕方・夜・朝は決めた小目標の切れ目）が大半で、進まない（stalled）は少ない
- 話してから最初の行動の成功まで、中央値 8 秒、90 パーセンタイル 30 秒。行動はあったのに 1 つも成功しないまま終わったのは 15%

### 3.2 直すこと

1. **予告は最初の行動が成功してから**（`Narrator.on_goal_set` / `on_action`）。`GoalSetEvent` では話さず、その小目標の情報だけ持つ（`_awaiting`）。行動が 1 つ成功したら（`GameActionExecutedEvent` の `ok`）、予告の文（今いる場所はこの時点のもの）を取っておいた出来事に足し、切れ目として話す（gate は今までどおり）。動く前に小目標が終わったら（済んだ・やめた）、予告しなかったことにして、その小目標のことは何も言わない。取っておいた見どころ（大目標の完了、家、街）は、その小目標が動く前に終わったとき、予告なしで話す
2. **予告したことをやめるときは、やめたと言う**。実際に話した予告を覚え（`_told`）、その小目標が未達成で終わったら、次の実況に「さっき次にやると話した小目標 X を、やり遂げずにやめた（理由）。話したことと違うので、やめた理由を言う」を必ず入れる（`_must_speak`: Jev の間合いの判断で飛ばさない）。出来事には入れたが話さなかった予告（gate が見送った）は、その小目標が終われば出来事ごと消す。予告を今も追っている小目標のものとしてだけ覚える（話している間に終わった小目標は覚えない）

D を入れても「動き出したあとにやめる」60% は減らない。それは §6 の残ること（小目標の粘り）で、この設計書の範囲ではない。ここでは、やめたときに視聴者が置いていかれないようにする。

## 4. 発話の照合（B）

### 4.1 方式

実況・一言（Narrator と LiveNarration）が作った文を、読み上げの直前に今の状態と照らす（`SpeechCheck`、`application/use_cases/speech_check.py`）。

構造化して書かせて（`{text, place, done, next}`）コードで比べる案は採らない。`done` と `next` を述語に直す語彙がなく、文を書いた LLM の自己申告なので独立していない。代わりに、文を Jev に読ませて YES_NO で聞き、答えを状態の事実と比べる。`SAME_MEANING_QUESTION` と `CommentaryGate` と同じ形（`IFastJudge.ask`、確信度の下限）。

状態の `current_goal` は、束の小目標ではまだ済んでいない条件だけ（`Goal.unmet`。一部が済んだ直後の「かまどができた」は正しい）。ブリッジが小目標を達成と判定したがプレイのループがまだ終わらせていない間（`goal_met`）は、「済んだ」を聞かない。

聞くこと（1 回の呼び出しに全部入れる）:

| 質問 | 状態と食い違い |
|---|---|
| `claims_inside_home`: 今、家の中にいる・入った・戻ったと言っているか | `has_home` かつ `inside_home` が偽 |
| `claims_outside_home`: 今、家の外にいる・出たと言っているか | `inside_home` が真 |
| `claims_goal_done`: 今の小目標が済んだ・手に入ったと言っているか | 今の小目標は未達成（終わっていれば変わる） |
| `contradicts_plan`: 今の小目標・今の行動と別のことをしている・する予定だと言っているか | 小目標と行動の説明を状態に渡す |

これからのことや過去のことは数えない（「家に帰るね」は場所の主張ではない）。食い違うと判定する確信度の下限は 0.75（`StuckCheck` と同じ）。

### 4.2 照らす時点

作った時点ではなく、読み上げる直前の `activity()`。Narrator は出来事が起きた時点の activity で文を作るので、作っている間に場所や小目標が変わる。

### 4.3 食い違ったとき

1. 食い違いの理由を出来事として足して、1 回だけ作り直す（`前の案「…」は今の状態と食い違う: …。今の状態に合わせて言い直す`）
2. 作り直した文もまだ食い違うなら、その行は言わない（`logs/spoken` に `outcome: check`、理由つき）

会話の履歴（`Conversation`）には、照合を通った文だけを入れる（言わなかった文を「言った」ことにしない）。照合があるとき、Narrator は `record=False` で作り、通ったあとで `remember` する。

Jev が答えない・時間切れ（2 秒）のときは、照合できなかったとして話す（`CommentaryGate` と同じ。理由をログに残す）。Jev の鍵がなければ照合しない（起動時にログで言う）。

### 4.4 範囲

Narrator の実況と LiveNarration の一言・雑談・独り言。道具の `intent` をそのまま読む一言は行動そのものなので照らさない。定型の一言（考え始めた）も照らさない。視聴者への返事は照らさない（§6）。

### 4.5 設定

`stream.speech_check: jev | off`（既定 jev）と `stream.spoken_record_dir`。開発中なので互換のための選択肢は足さない。

## 5. 消すもの

`LiveNarration._events` の「予定を理由なく変えない（やると言ったことをやめる・明日に延ばす、など）」を消す。設計書 46 の追記が、この種の指示は直前の誤りを状態より優先させると示した。「正しいのは今の状態で、直前に話したことが違えば状態に合わせて言い直す」は残す。食い違いはコードが見る。

## 6. 残ること

- 予告した小目標の 58% が未達成で終わる。小目標の粘り（進まない歩数、時間帯の切れ目、行動が失敗し続けたときの決め直し）は別の設計が要る。説明を足しても、視聴者が聞く予告と実際の食い違いの数は減らない
- 視聴者への返事と管理画面の発言は照らさない。返事にも「家にいるよ」の類の誤りはありうる
- `contradicts_plan` は Jev の読み取りに頼る。言い換えや、大目標のための言及を「別のこと」と読む誤りがありうる（追記の手作りの 17 文の試験では、誤って止めたことはなく、見逃しがあった）
- 照らすのは道具を選ぶ側ではない。実況が「肉がないから牛を探す」と言い、道具が `smelt beef` を選ぶ、ような食い違い（設計書 46 §5）は、道具の選択の側の問題として残る
- `contradicts_plan` が止めすぎる危険（追記）。作り直しでも同じ食い違いになれば言わないので、実況が減る
- 話した予告が聞こえなかったとき（読み上げが古くなって捨てた、直前と同じで言わない、失敗）は、その予告を話していないことにする（`Narrator.unheard`。`TTSService.on_outcome` と `say` から知らせる）。ただし記録は `Narrator` の直近 8 文だけ
- 実況に渡す出来事は、最後の 3 つだけ（`GenerateCommentaryUseCase.max_recent_events`）。取っておいた見どころが多い切れ目では、前のほうが実況に届かない（元からの制限）
- 読み上げなしの配信（`--no-speak`）では、アバターは `CommentaryGeneratedEvent` の文で口を動かすので、言わなかった文・作り直す前の文にも反応する（読み上げがあるときは反応しない）
- 実機では試していない（配信を再起動して、`logs/spoken` が溜まってから `tools/speech_consistency.py lines --judge jev` で測る）

### 実 Jev（jev-1.13.0）での試験

手作りの 17 文（家の内外、済んだ、別のこと、雑談。正しい文と食い違う文を混ぜた）に 4 つの質問を聞いた。1 回 220〜250 ms。

- 食い違う文を食い違うと判定: 「やっと家の中に入れたよ」（0.93）、「いま外に出たところだよ」（0.91）、「松明を4本手に入れたよ」（0.85）、「鉄を掘りに行くよ」「これから畑に水をまくね」（今の小目標は松明）
- 期待どおり 12 / 17。私が「止めない」と書いた 2 文を `contradicts_plan` が止めた: 「これから家に帰るね」（0.91）、「外に出て木を切ってくるね」（0.77）。今の小目標（松明）と別の行動を言うので質問の意味としては正しい判定だが、家に帰る途中の実況を「松明を作る」に書き直させる（実況が硬くなる）危険がある。これが一番見直す所（下限か質問の言い方）
- 見逃し: 「家に着いたよ、ただいま」（はい 0.64）、「松明ができたよ！」（はい 0.56）は確信度が下限 0.75 に届かず通る。「家の中は安心だね」は場所の主張とは言えず、はいと答えなかった

つまり 0.75 は、止めすぎない側に置いている（見逃しは減らせるが、正しい文を止める危険が増える）。17 文は手作りで、実際の実況での見逃しと止めすぎは分かっていない。`logs/spoken` が溜まってから `lines --judge jev` と、`check` の `rewrite` / `dropped` の割合で数えて、下限と質問を決め直す。
