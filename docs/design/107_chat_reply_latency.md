# 107. コメントへの返事が 8 分遅れた原因: 家がないのに建物を設計していた

2026-10-07、user: 「全然コメントしてないタイミングでコメントに反応してるかも」「コメントは割り込みで反応してあげられるようにしたい。反応がなかなかもらえないと悲しいから」

## 1. 起きていたこと（`zmx history stream`、`logs/generations`、`logs/promises`）

コメントが届いてから返事までの時間は、ふだん 5〜60 秒。20:41 から 3 回、400〜630 秒（7〜10 分）になった。

| コメント（JST） | 返事 | 遅れ |
|---|---|---|
| 20:41:57 ねこかも「家建てれるとこま…」 | 20:50:22 | 505 秒 |
| 20:46:08 / 20:50:12 | 20:56:40 / 20:56:53 | 632 / 401 秒 |
| 20:56:32 / 20:56:45 / 20:57:43 / 20:58:22 | 21:06:20〜21:06:59 | 517〜590 秒 |

コメントした人から見れば、コメントのない時に返事が来る。遅れた返事が「家を作る」と約束すると、その約束で夜越し（`through_night`）が切られた（21:06）。

## 2. 原因

返事（`GenerateResponseUseCase`）が大目標を受けるとき、`ObjectiveKeeper.accept` → `_design_builds` → `BuildDesigner.design` が、その場で Gemini に建物（`build_design`、画像つき、1 回 40〜200 秒）を設計させる。返事は設計が終わるまで話されず、返事は 1 件ずつ順に作る（`ChatResponder`）ので、あとのコメントもすべて待つ。

`build_design` が 3 回とも、ブリッジの `build house rejected: there is no home yet: build the house first` で断られた（12:00〜12:06Z: 141 + 208 + 37 + 86 秒 ≒ 8 分。20:45、20:46 も同じ）。名前付きの建物は家の隣に登録されるので、家がないうちは、どんな設計でも断られる。プロンプトにも「家はまだない」と書かれていたが、設計はそのまま呼ばれていた。

## 3. 直したこと
`BuildDesigner.design`: 家がなければ、設計を呼ぶ前に `GoalRejectedError("there is no home yet: build the house first")` で断る。返事はその理由を受けて作り直す（頼みは受けられなかった、と言わせる）ので、数秒で終わる。

## 4. 返事のあとに裏で設計する（user: 「2 ですすめて」）
user の選択: 返事は先に話し、建物の設計は返事のあとに裏でする。

- `ObjectiveKeeper.accept(..., on_added=...)`: `on_added` を渡す呼び出し（チャットの返事）は、断る理由になる確認だけ先にする（頼みの形、上限 `check_room`、同じ完了条件の大目標、まだない建物があるときの家の有無 `BuildDesigner.require_home`）。まだない建物（`built(name)`）があれば、設計と登録（`_design_and_add`）を裏の仕事にして、`None` を返す。設計が要らなければ今までどおり、足して返す
- 裏の仕事は、設計 → 施設・判定・条件の確認 → 大目標を足す（`_add_objective`）。足せたら `on_added(大目標)`。断られたら（設計できない、その間に上限に届いた、など）`on_design_failed(視聴者, 題名, 理由)` を呼び、配信（`factories/stream.py`）が固定の一言（「…の設計がうまくいかなかったから、あきらめるね。また頼んでね！」）を話す。一言は固定文で、LLM に作らせていない（v1）
- 足すのを設計のあとにしたのは、設計の前に足すと、ブリッジがまだ知らない `built(name)` を持つ大目標ができるため（`goals.mjs` が `NotYetError`: 目標にできず `PUT /goal` が 400）。設計中は大目標がプランにない
- 「今やる」（`when: now`）の考え直し（`request_rethink`）は、足せてから（`on_added`）。足す前に考え直すと、小目標の決定がまだない建物を選ぶ
- 同じ完了条件の設計が裏で進んでいる間の同じ頼みは、足さない（設計を 2 回しない）。配信を止めるときは、裏の設計をやめる（`cancel_designing`、`closers`）。やめたのは断られたのではないので話さない
- 施設の設計（`facility_design` 平均 1.4 秒）と判定を書く（`check_write` 14 秒）は、裏にしない（遅くない）。遅いのは `build_design`（平均 100 秒、最大 208 秒）だけ

### 限界（正直に）
- 返事を作る列は、まだ 1 件ずつ。返事そのものの LLM（`reply` 5〜10 秒、最大 3 回の試し）、約束の判定（`promise` 平均 6.6 秒）、事実の確認は、今までどおり順に待つ。ふだんの 5〜60 秒は変わらない。「割り込み」（コメントが届いたらすぐ、別に反応する）は、まだ。次の選択肢: 相づちを先に話す（案 1）
- 裏で設計している間、その大目標はまだない。返事は「やるよ」と言ったので、断られたときは上の一言で言い直す。その間にほかの頼みが上限を埋めると、足せずに断られる
- 家がないときに LLM が `built(house)` を提案するのは、定石の「家」（`built()`、名前なし）がすでにあるのに別の名前付きの建物と取り違えているため。今は断るだけで、既存の大目標へ誘導してはいない（別の判断）
